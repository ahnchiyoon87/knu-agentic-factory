## 1 · 내 공장을 받습니다

서른아홉 개의 공장이 돌고 있고, 그중 하나가 오늘 내 것이 됩니다.

**① VS Code 에서 터미널을 엽니다**

위 메뉴 **터미널 → 새 터미널**.
메뉴에 터미널이 안 보이면 창이 좁아서 접힌 것입니다 — 맨 위 `…` 안에 있습니다.

![창이 좁으면 위 메뉴가 `…` 로 접힙니다 — 그 안에 터미널이 있습니다](그림/실습/실습_2_터미널열기.png)

**② 실습 폴더로 들어갑니다**

```
cd 2일차/실습
```

**③ 공장을 받습니다**

```
uv run 내번호.py
```

처음이면 1~2분 걸립니다. 글자가 주르륵 지나가는 건 필요한 프로그램을 내려받는 중입니다.

![번호를 받은 뒤 — ★ 사이가 내 공장 번호입니다](그림/실습/실습_2_내번호.png)

★ 사이의 번호가 내 것입니다. 사람마다 다릅니다.

## 2 · 내 공장을 눈으로 봅니다

**① 크롬을 열고, 방금 화면에 뜬 주소를 붙여넣습니다**

```주소
http://34.64.94.16:8000/view?tenant=내번호
```

화면에 찍힌 주소를 그대로 복사하세요. 옆 사람 번호를 넣으면 남의 공장이 열립니다.

![내 공장 — 가운데 초록 네모가 CNC 6대, 오른쪽 위에 내 번호가 찍혀 있습니다](그림/실습/실습_2_공장뷰.png)

**② 네 가지가 보이면 됩니다**

- 네모(CNC 기계) 6개 — `EQ-01` ~ `EQ-06`
- 동그란 점(로봇) 2개 — `AMR-01` `AMR-02`
- 네모 안 숫자가 1~2초마다 바뀜
- 오른쪽 위에 내 번호

**③ 여섯 대의 온도를 훑어봅니다**

제일 낮은 기계와 제일 높은 기계가 **20도 가까이 차이 나는데, 여섯 대 다 초록색 — 전부 정상**입니다.
회전이 빠른 기계일수록 뜨겁습니다. 분당 1600번 도는 기계는 56도,
2200번 도는 기계는 74도가 제자리입니다.
온도는 기계 겉면이 아니라 **회전축을 받치는 베어링 안쪽**에서 잽니다. 그래서 숫자가 이렇게 높습니다.

> **「정상」의 기준이 기계마다 다릅니다.**
> 그래서 여섯 대에 같은 선 하나를 그을 수 없습니다.

이 탭은 닫지 않습니다. 오늘 계속 씁니다.

## 3 · 계속 지켜볼 수 있습니까

방금 여섯 대 중 **한 대**에 이상이 들어갔습니다.
멈추거나 빨갛게 되는 것이 아닙니다. 온도만 아주 조금씩 오릅니다.

**① 30초쯤 화면을 봅니다**

어느 기계인지 짚어 봅니다.

**② 못 찾는 것이 보통입니다**

짚으셨다면 여섯 대 중 하나를 찍은 것입니다. 못 짚었어도 마찬가지입니다 —
**30초로는 근거를 댈 방법이 없습니다.** 그게 이 30초가 묻는 것입니다.

**③ 게다가 이건 계속 봐야 잡힙니다**

> **여섯 대 전부를, 밤새, 매일 지켜보실 수 있습니까?**

사람은 못 합니다. 눈이 나빠서가 아니라, **쉬어야 하기 때문**입니다.

## 4 · 그래서, 쉬지 않는 감시자를 만듭니다

사람 대신 화면을 지켜볼 감시자를 지금부터 만듭니다.
감시자가 하는 일은 하나입니다 —

> **지금 값이, 그 기계의 「평소」에서 얼마나 벗어났는가.**

여기서 「평소」란 **지금 값 바로 앞 한 시간 — 값 60개** 를 말합니다.

```수식
z = ( x − μ ) / σ

x : 지금 값        μ : 평소의 평균        σ : 평소의 흔들림
```

방금 봤듯 기계마다 평소 온도가 다르니, 80℃ 같은 고정선 하나로는 안 됩니다.
그래서 감시자는 **그 기계의 최근 값들**로 평소를 매번 새로 잽니다.

**① 왼쪽 탐색기에서 `2일차` → `실습` → `detect.py` 를 엽니다**

감시자의 뼈대가 이미 들어 있고, **비어 있는 곳이 다섯 군데** 있습니다.
오늘 고치는 파일은 이 하나뿐입니다.

**② `Ctrl`+`F` 로 `빈칸` 을 칩니다**

`빈칸 1` 부터 `빈칸 5` 까지 차례로 걸립니다. **채우는 방법은 각 빈칸 바로 위 주석에** 적혀 있습니다.

| 빈칸 | 고칠 줄 | 감시자가 얻는 것 |
|---|---|---|
| 1 | `mean = ...` | 평소의 평균 |
| 2 | `var = ...` | 평소의 흔들림 |
| 3 | `return ...` | 평소가 한 번도 안 흔들린 자리의 판단 |
| 4 | `return ...` | 판정 — 평소 흔들림의 몇 배부터 이상인가 |
| 5 | `방침 = ...` | 값이 빈 자리를 어떻게 할지 |

![detect.py 를 연 화면 — 「빈칸 1」 아래 `mean = ...` 이 오늘 고칠 첫 줄입니다](그림/실습/실습_2_detect열기.png)

일하는 방법은 끝까지 같습니다 — **고치고, `Ctrl`+`S` 로 저장하고, 확인 명령을 칩니다.**
(탭 이름 옆에 ● 이 남아 있으면 아직 저장이 안 된 것입니다)

직접 채워도 되고, 막히면 **정답을 넣고 넘어가도 됩니다** — 그 명령은 각 단계에 있습니다.
정답을 넣어도 **여러분이 쓰던 것은 `detect_내가짠것.py` 로 남습니다.**
어느 쪽이든 끝(7일치 돌리기)까지 갑니다.

## 8 · 값이 빈 자리를 정합니다 — 빈칸 5

센서가 죽으면 값이 안 들어옵니다. 이 데이터에는 `EQ-01` 에 **2시간짜리 빈 구간**이 있습니다.

그 구간을 감시자가 어떻게 다룰지, `빈칸 5` 에 **숫자 하나로** 정합니다.

**`1` 을 적으면** — 빈 자리를 그냥 둡니다.
없는 값을 지어내지 않는 대신, 그 2시간은 못 봅니다.

**`2` 를 적으면** — 바로 앞 값으로 메웁니다.
판정할 구간이 늘어나는 대신, 2시간 내내 같은 값이 들어가고 —
값이 돌아오는 순간 **없던 이상이 하나 생깁니다.**

**여기도 정답이 두 개입니다. 둘 중 하나를 고르세요** — 왜 골랐는지만 말할 수 있으면 됩니다.
두 경우의 코드는 이미 파일에 들어 있습니다. 숫자 하나만 적으면 됩니다.

```
uv run 확인.py
```

**나오는 화면**

![세 함수가 모두 통과 — 감시자가 완성됐습니다](그림/실습/실습_2_확인통과.png)

`고른 방침` 줄은 무엇을 골랐느냐에 따라 다르게 나옵니다.

**막히면 정답을 넣고 갑니다**

```
uv run 확인.py --정답 3
```

정답 넣기는 `1` 로 채웁니다. **`2` 를 골랐어도 그건 정답입니다.**

**감시자가 완성됐습니다.** 이제 진짜 데이터에 풀어놓습니다.

## 9 · 7일치에 풀어놓습니다

지금까지 `확인.py` 가 쓴 것은 값 몇 개짜리 연습 데이터였습니다.
이제 **진짜 7일치 60,480줄**입니다. 감시자가 무엇을 잡고 무엇을 놓치는지 여기서 드러납니다.

다 채웠으면 강사 신호에 맞춰 **다 같이** 돌립니다 — 결과 화면을 같이 읽기 위해서입니다.

```
uv run 돌려보기.py
```

**나오는 화면**

![7일치를 도는 데 몇 초 걸립니다 — 여기까지가 머리줄입니다](그림/실습/실습_2_돌려보기머리.png)

`돌려보기.py` 는 여러분이 만든 감시자를 **온도와 진동, 두 데이터에** 돌립니다.
그래서 결과에는 진동 이상도 같이 나옵니다.

이어서 심어 둔 이상 3종이 각각 어떻게 나왔는지 세 줄로 나오고,
마지막에 **아닌데 잘못 울린 것**이 몇 줄인지 나옵니다.

| 표시 | 뜻 |
|---|---|
| `[O ]` | 잡았다 |
| `[  ]` | 못 잡았다 |
| `[~ ]` | 울리긴 했는데, 정상 구간에서 울리는 빈도와 다를 게 없다 |

`[~ ]` 는 잡은 것이 아닙니다. 아무 데서나 그만큼 울리고 있으니까요.

**결측 줄은 사람마다 다릅니다.** `빈칸 5` 에서 무엇을 골랐느냐가 여기 찍힙니다.
`1`(그냥 둔다)을 고른 사람은 그 2시간을 판정하지 않기로 한 것입니다 —
**틀린 것이 아니라 고른 대로 된 것입니다.**

맨 아래 **「아닌데 울린 것」**이 다음 단계의 기준선입니다.
이 화면은 **닫지 말고 그대로 둡니다.** 숫자를 바꿔 가며 여기 값과 계속 견줍니다.

## 10 · 숫자를 흔들어 봅니다

지금은 `k=3.0` · `window=60` 입니다. 이 값이 최선인지 직접 바꿔 봅니다 — 한 번에 하나씩만.

**① 더 민감하게**

```
uv run 돌려보기.py --k 2.0
```

**② 더 둔하게**

```
uv run 돌려보기.py --k 4.0
```

**③ 보는 구간을 짧게**

```
uv run 돌려보기.py --window 30
```

**④ 돌릴 때마다 두 숫자를 같이 봅니다**

- **잡은 것** — 심어진 이상 3종이 각각 어떻게 나왔나
- **아닌데 울린 것** — 하루 약 몇 번

한쪽만 보면 속습니다. `k` 를 낮추면 더 잡히지만, 그 대신 무엇을 치렀는지를 같이 봐야 합니다.

**더 잡으려 하면 헛울림이 는다 — 오늘의 한 문장입니다.**

마지막으로, 여러분이 한참을 들여 만든 이것을 AI 는 얼마 만에 짜는지 봅니다.

---

## 11 · 같은 것을 AI 가 짜는 걸 봅니다

여기는 **강사가 보여 주는 자리**입니다. 여러분은 화면만 보면 됩니다.

여러분이 고민하며 채운 그 함수를, 강사가 **AI 코딩 에이전트**에게 말로 시킵니다.
**몇 초면 다 짭니다.**

코드가 나오면 두 곳을 눈여겨보세요 — 방금 여러분이 직접 고민한 자리들입니다.

- **흔들림을 무엇으로 나눴나** — 개수인가, 개수−1 인가
- **값이 빈 자리를 어떻게 했나** — 그냥 뒀나, 메웠나

그리고 그 코드를 **같은 7일치**에 돌립니다.
잘 짰는지 아닌지, 여러분은 이제 **숫자로** 판정할 수 있습니다 — 직접 만들어 봤기 때문입니다.

**내일은 이 AI 에게, 여러분이 짠 감시자를 쥐여 주고 일을 시킵니다.**

## 오늘 여기까지 왔습니다

| | |
|---|---|
| **봤다** | 여섯 대가 저마다 다른 온도에서 도는 것 — 그리고 이상이 눈에 안 보이는 것 |
| **만들었다** | 쉬지 않는 감시자. 손으로 채운 다섯 줄이 **6만 줄을 몇 초에 훑었다** |
| **쟀다** | `k` 를 흔들며, 더 잡으면 무엇을 치르는지 숫자로 봤다 |
| **지켜봤다** | 같은 것을 AI 가 몇 초 만에 짜는 것 — 판정은 내가 숫자로 했다 |

순간 튀는 것은 심어 둔 자리마다 정확히 울렸습니다.
30초를 봐도 못 짚던 것을, 여러분이 채운 다섯 줄이 몇 초 만에 집어냈습니다.
라이브러리를 부른 적은 한 번도 없습니다.

그리고 `빈칸 3` 과 `빈칸 5` 에서 어느 쪽을 골랐느냐가 옆 사람과 다른 결과를 만들었습니다.
**그게 오늘 여러분이 한 판단입니다.**

### 그런데 두 가지가 남았습니다

**하나 — 못 잡은 것이 있습니다.**

서서히 오르는 그 이상, 감시자가 `[~ ]` 로 흘려보낸 것입니다.
`k` 를 아무리 낮춰도 안 잡혔고, 낮추면 헛울림만 늘었습니다.
감시자의 「평소」가 최근 값들이라, 온도가 천천히 오르면 **평소도 같이 따라 오르기 때문**입니다.

**둘 — 잡아도 「왜」를 모릅니다.**

감시자는 「EQ-03 이 이상하다」까지만 말합니다.
정비 담당이 남긴 *"부품 입고 지연으로 점검 보류"* 같은 메모는 읽지 못합니다.

**내일 이 둘을 해결합니다 — 오늘 짠 `detect.py` 와 오늘 받은 번호를 그대로 들고.**
