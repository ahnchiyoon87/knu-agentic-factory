## 1 · 내 공장 받기

서른아홉 개의 공장이 돌고 있고, 그중 하나가 내 것이 됩니다. 번호를 받아야 시작됩니다.

**① VS Code 에서 터미널을 엽니다**
위 메뉴 터미널 → 새 터미널

메뉴에 터미널이 안 보이면 창이 좁아서 접힌 것입니다. 맨 위 `…` 을 누르면 그 안에 있습니다.

```

```


처음이면 1~2분 걸립니다. 글자가 주르륵 지나가는 건 필요한 것을 갖추는 중입니다.

## 2 · 내 공장 눈으로 보기

앞으로 잡을 이상이 어떻게 생겼는지 먼저 봅니다. 숫자만 보면 감이 안 옵니다.

**① 크롬을 엽니다**

**② 방금 화면에 뜬 주소를 주소창에 붙여넣습니다**

```주소
http://34.64.94.16:8000/view?tenant=내번호
```

`내번호` 자리에 내 번호가 들어갑니다. 화면에 찍힌 주소를 그대로 복사합니다 — 옆 사람 번호를 넣으면 남의 공장이 열립니다.

**나오는 화면**

![내 공장 — 가운데 초록 네모가 CNC 6대, 오른쪽 위와 오른쪽 패널에 내 번호가 찍혀 있습니다](그림/실습/실습_2_공장뷰.png)

**③ 네 가지를 확인합니다**

- 네모(CNC 기계) 6개 — `EQ-01` ~ `EQ-06`
- 동그란 점(로봇) 2개 — `AMR-01` `AMR-02`
- 네모 안 숫자가 1~2초마다 바뀜
- 오른쪽 위에 내 번호

**④ 여섯 대의 온도를 눈으로 훑어봅니다**

제일 낮은 기계와 제일 높은 기계가 **20도 가까이 차이 납니다.**
그런데 여섯 대 다 초록색, **전부 정상**입니다. 원래 그 온도에서 도는 기계들입니다.

**회전이 빠른 기계일수록 뜨겁습니다.** 분당 1600번 도는 기계는 56도가 제자리이고,
2200번 도는 기계는 74도가 제자리입니다. 재는 자리는 기계 겉면이 아니라
**회전축을 받치는 베어링 안쪽**이라 숫자가 이만큼 높게 나옵니다.

**한 기계에게 정상인 온도가, 다른 기계에게는 이상일 수 있습니다.**

**⑤ 이 탭은 닫지 않습니다**

## 3 · 눈으로 계속 지킬 수 있는지 확인하기

**② 못 찾아도 괜찮습니다**

찾으셨더라도 — **근거를 숫자로 댈 수 있습니까?**

**③ 게다가 이건 계속 봐야 잡힙니다**

> **여섯 대 전부를, 밤새, 매일 지켜보실 수 있습니까?**

**④ 그래서 대신 지켜볼 것을 만듭니다**

**눈이 좋아서가 아니라, 쉬지 않기 때문입니다.**

## 4 · 고칠 파일 열기

오늘 손대는 파일은 하나뿐입니다. 어디를 채우는지 먼저 봅니다.

**① 왼쪽 탐색기에서 `2일차` → `실습` → `detect.py` 를 누릅니다**

**② `Ctrl`+`F` 를 누르고 `TODO` 를 칩니다**

**뼈대는 이미 다 들어 있습니다.** 고칠 것은 `...` 이라고 적힌 **다섯 줄**뿐입니다.
새로 만들 줄도, 지울 주석도 없습니다.

| 자리 | 고칠 줄 | 하는 일 |
|---|---|---|
| `TODO 1-A` | `mean = ...` | 앞 W개의 평균 |
| `TODO 1-B` | `var = ...` | 앞 W개의 표본분산 |
| `TODO 2-A` | `return ...` | 표준편차가 0 인 자리를 어떻게 볼까 |
| `TODO 2-B` | `return ...` | z 가 k 를 넘는지 판정 |
| `TODO 3` | `방침 = ...` | 값이 없는 자리를 어떻게 다룰까 |

<!-- 사진 실습_2_detect열기.png
     VS Code 전체 화면. 왼쪽 탐색기에 2일차 > 실습 이 펼쳐져 있고
     오른쪽에 detect.py 가 열려 TODO 1-A · mean = ... 줄이 보이는 상태.
     파일 탭(detect.py)까지 나오게. -->

만드는 것은 이동 윈도 z-score 입니다.

```수식
z = ( x − μ ) / σ

x : 지금 값        μ : 최근 W개의 평균        σ : 최근 W개의 표준편차
```

함수 이름은 바꾸지 않습니다. 다른 파일들이 이 이름으로 불러 씁니다.

**무엇을 쓰는지는 그 자리 주석에 적혀 있습니다.** 주석은 지우지 않아도 됩니다.

## 6 · 평균과 표준편차 구하기

지금 값이 평소와 얼마나 벗어났는지 재려면, 먼저 「평소」가 뭔지 정해야 합니다.
**지금 값 바로 앞의 `window` 개**를 평소로 삼습니다.

**① `detect.py` 에서 `TODO 1-A` 를 찾습니다**

`Ctrl`+`F` 로 `TODO 1-A` 를 치면 그 자리로 갑니다.
**뼈대는 이미 다 있습니다.** 새로 만들 줄도, 지울 주석도 없습니다.

**② 바로 아래 `mean = ...` 의 `...` 만 고칩니다**

무엇을 쓰는지는 그 자리 주석에 적혀 있습니다 — `seg` 를 다 더해서 개수로 나눕니다.

**③ 이어서 `TODO 1-B` 의 `var = ...` 도 같은 식으로 고칩니다**

`seg` 를 자를 때 뒤끝이 `i` 라서 **지금 값은 안 들어갑니다.**
넣으면 튀는 값이 자기 평균을 끌어올려 자기를 숨깁니다. 그래서 뺐습니다.

**④ 저장하고 확인합니다**

`Ctrl`+`S` — 탭 이름 옆의 ● 이 사라져야 저장된 것입니다.

```
uv run 점검.py
```

**⑤ 막히면 이 명령으로 채우고 갑니다**

```
uv run 점검.py --열기 1
```

**10분을 넘기지 마세요.** 오늘의 핵심은 이 함수를 혼자 떠올리는 게 아니라,
**내 코드로 7일치를 돌려 숫자가 어떻게 움직이는지 보는 것**입니다.

**이제 「평소」가 생겼습니다.** 다음은 얼마나 벗어나야 이상이라고 부를 것인가입니다.

## 7 · 이상인지 판정하기

기준이 생겼으니 선을 긋습니다. **평소에서 몇 걸음 벗어나야** 이상이라고 부를 것인가.
그 걸음 수가 `k` 입니다.

**① 같은 파일에서 `TODO 2-A` 를 찾습니다**

**② `return ...` 의 `...` 만 고칩니다**

여기는 **표준편차가 0 인 자리**입니다. 최근 값이 한동안 완전히 똑같았다는 뜻이고,
실제 데이터에 있습니다. 0 으로 나누면 파이썬은 조용히 넘어가지 않고 **멈춥니다.**

**이상으로 볼지 말지는 여러분이 정합니다.** 정답이 하나가 아닙니다.
고르고, 왜 그랬는지 말할 수 있으면 됩니다.

**③ 이어서 `TODO 2-B` 의 `return ...` 도 고칩니다**

여기가 본 판정입니다. `z` 의 절댓값이 `k` 를 넘으면 이상입니다.
**위로 벗어난 것도 아래로 벗어난 것도 이상**이라 절댓값을 씁니다.

**④ 저장하고 확인합니다**

```
uv run 점검.py
```

**⑤ 막히면 이 명령으로 채우고 갑니다**

```
uv run 점검.py --열기 2
```

**선을 그었습니다.** 그런데 값이 아예 안 들어온 자리는 어느 쪽으로 칠까요.

## 8 · 값이 없는 자리 정하기

센서가 죽으면 값이 안 들어옵니다. 이 데이터에는 `EQ-01` 에 **2시간(120개)** 짜리 빈 구간이 있습니다.

**여기는 정답이 하나가 아닙니다.** 고르고, 왜 골랐는지 말할 수 있으면 됩니다.

**① 같은 파일에서 `TODO 3` 을 찾습니다**

**② `방침 = ...` 자리에 `1` 이나 `2` 를 씁니다**

| 쓰는 값 | 하는 일 | 대가 |
|---|---|---|
| `1` | 그냥 둡니다 — 그 구간은 판정하지 않습니다 | 없는 값을 지어내지 않습니다. 대신 그 구간은 못 봅니다 |
| `2` | 직전 값으로 메웁니다 | 판정할 구간이 늘어납니다. 대신 2시간 내내 같은 값이 들어가 표준편차가 0 이 되고, 값이 돌아오는 순간 **없던 이상이 하나 생깁니다** |

**두 방침의 코드는 이미 아래에 다 들어 있습니다.** 숫자만 고르면 그쪽으로 갑니다.
앞뒤 평균으로 메우는 등 다른 방침을 쓰고 싶으면 그 아래를 통째로 바꿔도 됩니다.

**③ 저장하고 확인합니다**

```
uv run 점검.py
```

![세 자리를 다 채운 뒤 — 3개 중 3개 통과](그림/실습/실습_2_점검통과.png)

`고른 방침` 안내는 무엇을 골랐느냐에 따라 다르게 나옵니다.

**④ 막히면 이 명령으로 채우고 갑니다**

```
uv run 점검.py --열기 3
```

**세 자리가 다 찼습니다.** 이제 이 코드를 진짜 7일치에 태웁니다.

> 왜 그렇게 되는지 궁금하면 **맨 뒤 「참고 답안」** 에 세 함수의 완성본과 설명이 있습니다.

## 9 · 7일치에 돌려 보기

지금까지 `점검.py` 는 **값 몇 개짜리 시험 데이터**로 함수가 맞게 도는지만 봤습니다.

> **다 채웠어도 여기서 멈춥니다.** 강사가 "다 같이 엔터" 라고 하면 그때 칩니다.

```

```

맨 아래 **「아닌데 울린 것」** 이 몇 번인지가 오늘의 숫자입니다.

## 10 · 숫자를 흔들어 보기

기본값이 정답인지 확인합니다. 한 번에 하나씩만 바꿉니다.

**① 더 민감하게**

```
uv run run.py --k 2.0
```

**② 더 둔하게**

```
uv run run.py --k 4.0
```

**③ 보는 구간을 짧게**

```
uv run run.py --window 30
```

**④ 돌릴 때마다 두 숫자를 같이 봅니다**

한쪽만 보면 속습니다. `k` 를 낮추면 더 잡히지만, **그 대신 무엇을 치렀는지**를 같이 봐야 합니다.

**더 잡으려 하면 헛울림이 는다 — 오늘의 한 문장입니다.**

이제 마지막으로, 같은 함수를 AI 에게 시키면 어떻게 다른지 봅니다.

## 11 · AI 가 짠 것과 나란히 놓기

같은 일을 AI 에게 시키면 어떤 코드가 나오는지, **그리고 그게 내 것보다 나은지** 봅니다.
이 자리는 강사가 앞에서 합니다. 여러분은 화면을 보면 됩니다.

**① 강사가 AI 에게 시킵니다**

여러분이 아침부터 채운 그 함수를, 말 몇 줄로 만들게 합니다.

**② 나온 코드를 같이 읽습니다**

특히 두 곳을 봅니다.

- **표준편차를 무엇으로 나눴나** — 개수인가, 개수−1 인가
- **값이 없는 자리를 어떻게 했나** — 그냥 뒀나, 메웠나

**③ 그 코드를 같은 데이터에 돌립니다**

여기가 핵심입니다. 코드만 보면 어느 쪽이 나은지 알 수 없습니다.
**여러분이 아까 본 그 화면**이 AI 코드로 다시 나옵니다.

| | 내가 짠 것 | AI 가 짠 것 |
|---|---|---|
| **잡은 것** — 심어진 이상 3종 중 몇 개 | ? | ? |
| **놓친 것** — 나머지 몇 개 | ? | ? |
| **아닌데 울린 것** — 하루 몇 번 | ? | ? |

세 줄을 **같이** 봐야 합니다. 한 줄만 보면 어느 쪽이든 이겨 보입니다.

**④ 그래서 어느 쪽입니까**

숫자가 갈리면 이유를 찾을 수 있습니다. 표준편차를 개수로 나누면 값이 작아지고,
작은 표준편차로 나눈 z 는 커집니다. **더 자주 울린다는 뜻입니다.**

**AI 가 짠 코드가 맞는지 틀린지를 숫자로 말할 수 있는 것 — 그게 오늘 얻은 것입니다.**
짜 본 적이 없으면 이 판정을 할 수 없습니다.

## 오늘 여기까지 왔습니다

| | 오늘 한 것 |
|---|---|
| **봤다** | 여섯 대가 저마다 다른 온도에서 도는 것, 그리고 이상이 눈에 안 걸리는 것 |
| **짰다** | 최근 값과 견줘 판정하는 함수 셋을 채워 7일치에 돌렸다 |
| **쟀다** | `k` 를 바꿔 가며 무엇이 늘고 무엇이 주는지 숫자로 봤다 |
| **판정했다** | AI 가 짠 코드와 내 것을 같은 데이터에 태워 견줬다 |

### 그런데 두 가지가 남았습니다
