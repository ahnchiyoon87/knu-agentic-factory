# 운영 — 공장은 학생 PC 에서 돈다. 운영할 서버가 없다

경남대 8월 특강의 K-정밀 공장 시뮬레이터. **docker compose 한 벌**(FastAPI 공장 +
Postgres DB)이 학생 각자의 PC 에서 자기 것 하나만 돌린다. 클라우드 서버·VM·리모컨·
자리 배정은 전부 없앴다 — 그 시절 접속값은 `.env.은퇴백업_클라우드` 에만 남아 있다.

## 켜고 끄기

```bash
docker compose up -d       # 켠다 — 첫 실행은 빌드 + 스키마 자동 적용까지 몇 분
docker compose down        # 끈다 (데이터는 남는다)
docker compose down -v     # 끄고 데이터까지 지운다 — 공장 초기화
```

스키마는 컨테이너가 켜질 때마다 `tools/migrate.py up` 으로 스스로 맞춘다(멱등).
사람이 마이그레이션을 기억할 필요가 없다.

## 수업 흐름과 스위치

| 언제 | 무엇 | 어떻게 |
|---|---|---|
| 2일차 고장 주입 | 학생 화면의 **[이상 시작]** 버튼 | 배속 ×120 자동 · 소진(2분 30초) 후 ×60 자동 복귀 |
| 3일차 아침 | (없음) | AI 열쇠는 배포본 `.env` 에 캡슐로 이미 실려 있다 |
| 3일차 31장 | 제어 개방 | `uv run 제어열기.py` — 재기동 없이 DB 플래그가 바뀐다 |

## 다 같이 쓰는 것은 OpenAI 키 하나다

- 키는 **전용 프로젝트(예산 상한)** 의 것을 배포 전에 강사 .env 에 넣으면,
  배포본만들기.py 가 **캡슐(KNU1: 난독화)로 바꿔 학생 .env 에 심는다** —
  sk- 원문은 어디에도 안 보이고, 수업 뒤 키를 지우면 캡슐도 그 순간 죽는다
- 39명 동시 혼잡은 각자의 공장이 넘긴다 — `diagnose.py`·`agent.py` 의
  지수 백오프(1·2·4·8·16·30초 + 흔들기, Retry-After 존중, 최대 6번)
- 크레딧 소진(insufficient_quota)은 재시도하지 않고 「잔액이 없습니다 —
  강사에게 알리세요」로 정직하게 알린다
- 진단이 끝내 실패해도 학생 쪽 `diagnoser.py` 가 규칙 기반으로 내려가
  폐루프 일곱 걸음은 끝까지 돈다

## 막히면

| 증상 | 처방 |
|---|---|
| 화면이 안 뜬다 | Docker Desktop 이 켜져 있나 → `docker compose up -d` |
| 무엇인가 엉켰다 | `docker compose down -v` 뒤 다시 `up -d` — 그 학생 것만 초기화된다 |
| 「제어 통로가 잠겨」 | `uv run 제어열기.py` 를 아직 안 친 것 |
| AI 가 「잠시 막혔습니다」 | 39명 동시 혼잡 — 1분 뒤 다시. 코드 문제가 아니다 |
| AI 가 「잔액이 없습니다」 | OpenAI 크레딧 충전 — 강사 몫 |

상세 규칙·구조·검증 상태는 저장소 루트 `핸드오프.md` 가 원본이다.
