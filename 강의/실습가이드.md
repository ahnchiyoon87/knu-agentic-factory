## §1. 내 공장 열어보기 (20분)

#### 왜 하는가

오늘 잡을 이상이 어떻게 생겼는지 **눈으로 먼저 봅니다.**
사람 눈으로 알아챌 수 있는지 없는지를 확인하는 것이 §2 를 하는 이유가 됩니다.

#### 1-0. 내 공장 받기 (2분) — 이 한 줄이 시작입니다

```bash
cd 2일차/실습
uv run 내번호.py
```

> **처음 한 번은 1~2분 걸립니다.** 이 실습에 필요한 것들을 `uv` 가 알아서 갖춥니다.
> 두 번째부터는 바로 뜹니다.

서버 주소를 물어봅니다. **그냥 Enter** 를 누르면 수업 서버로 갑니다.
(다른 주소를 쓰라고 안내받았을 때만 그 주소를 넣습니다.)

![내번호.py 를 돌리면 내 공장 번호와 공장 보기 주소가 뜹니다](그림/실습/실습_2_내번호.png)

**★ 표시된 번호를 적어 두세요.** 오늘 기억할 것은 이것 하나뿐입니다.
그 아래 붉게 표시된 **공장 보기 주소**는 다음 단계에서 바로 씁니다.

> **자리를 옮기거나 컴퓨터를 바꿨다면** — `uv run 내번호.py S07` 처럼 그 번호를 뒤에
> 붙여 다시 실행하면 **같은 공장을 그대로 가져옵니다.**
>
> **지금 번호가 뭐였는지 잊었으면** — `uv run 내번호.py` 를 그냥 다시 치세요.
> 몇 번을 쳐도 같은 번호가 나옵니다. 번호가 바뀌거나 소모되지 않습니다.
>
> 내일 쓸 설정(`config.json`)은 **이때 자동으로 채워집니다.** 손으로 적을 것이 없습니다.

#### 1-1. 접속 (3분)

방금 화면에 뜬 **공장 보기 주소**를 브라우저 주소창에 그대로 붙여 넣습니다.

```
http://<강사가 알려 준 서버 주소>/view?tenant=<내 번호>
```

- **주소 전체가 위 화면에 이미 찍혀 있습니다.** 직접 조합하지 마세요.
- 각자 번호가 다릅니다. 옆 사람 번호로 들어가면 남의 공장이 보입니다.

**성공 판정** — 이 화면이 뜨면 됩니다.

#### 1-2. 평소 값을 눈에 익힙니다 (5분)

**설비마다 평소 온도가 다릅니다.** 이건 고장이 아닙니다.

- `EQ-04` 는 56도 근처, `EQ-05` 는 74도 근처에서 놉니다.
- 그래서 **모든 설비에 같은 경고선 하나를 그을 수가 없습니다.** 이게 오늘 강의의 출발점입니다.

지금 **여섯 대의 온도를 한 번 적어 두세요.** 잠시 뒤에 다시 봅니다.

```

EQ-04 ______   EQ-05 ______   EQ-06 ______
```

#### 1-3. 강사가 고장을 하나 넣습니다 (10분)

강사 콘솔에서 여러분 공장에 **이상 세 가지 중 하나**를 주입합니다.

| 이름 | 어떻게 생겼나 |
|---|---|
| 드리프트 | 온도가 **서서히** 오릅니다 |
| 스파이크 | 진동이 **한순간** 튑니다 |
| 결측 | 센서 값이 **안 들어옵니다** (화면이 멈춘 것처럼 보임) |

주입 뒤 **2분 동안 화면만 보세요.** 그리고 아래 두 칸을 채웁니다.

```
무엇이 달라졌나?  ____________________________________
어느 설비인가?    ____________________________________
```

> **못 맞혀도 됩니다.** 맞히는 시간이 아니라, **사람 눈으로 되는지 확인하는 시간**입니다.
> 이 칸에 "모르겠다"라고 적혀 있는 것이 오늘 §2 를 하는 이유입니다.

#### 1-4. 정리 (2분)

브라우저 탭은 **닫지 말고 그대로 두세요.** 오늘 끝까지 씁니다.

## §2. 이상감지 알고리즘 직접 구현 (50분)

#### 왜 하는가 (교안 원문)

> **이 랩만큼은 AI에게 통째로 맡기지 않는다.**
> 전공에서 배운 알고리즘 감각이 AI 시대에 왜 여전히 무기인지 확인하는 시간이다.

이틀 내내 AI에게 시키는데 왜 이것만 직접 짤까요 — 마지막 단계에서 **AI가 짠 것과 나란히
놓고 판정하는 쪽에 서 보기 위해서**입니다. 판정할 수 있는 사람만이 AI를 도구로 부립니다.

#### 2-0. 폴더 열기 (2분)

VS Code에서 이 폴더를 열고, **터미널에서 그 폴더로 들어갑니다.**

```bash
cd 2일차/실습
```

안에 이런 파일들이 있습니다.

| 파일 | 무엇 | 건드리나 |
|---|---|---|
| `detect.py` | **여기만 고칩니다** | ✅ |
| `run.py` | 내 구현을 데이터에 돌리고 채점 | ❌ |
| `점검.py` | **막혔을 때 여는 것** — 내 코드를 돌려보고 어디가 틀렸는지 짚어 줍니다 | ❌ |
| `내번호.py` | 내 공장 받기 — 처음에 한 번 | ❌ |
| `README.md` | 이 랩 설명 | 읽기만 |
| `정답/` | **시간이 다 됐을 때** `점검.py --열기` 가 읽는 완성본 | 직접 열지 마세요 |

데이터는 **K-정밀 7일치 CSV, 60,480행**(CNC 6대 × 7일 × 1분)입니다. 이미 들어 있습니다.
그 안에 **이상 세 가지가 심어져 있습니다.**

#### 2-1. Step 1 — TODO 세 군데 채우기 (25분)

`detect.py` 를 열면 `# TODO 1` `# TODO 2` `# TODO 3` 이라고 적힌 자리가 세 군데 있습니다.

만드는 것은 **이동 윈도 z-score 이상감지**입니다.
— "최근 W개 값의 평균에서, 지금 값이 표준편차의 몇 배나 벗어났나"로 판정합니다.

```
z = ( x − μ ) / σ        x: 지금 값   μ: 최근 W개 평균   σ: 최근 W개 표준편차
```

| TODO | 함수 | 채울 내용 |
|---|---|---|
| 1 | `window_stats()` | 직전 W개 값으로 **평균과 표준편차** 계산 |
| 2 | `is_anomaly()` | z-score 가 임계값 **k 를 넘는지** 판정 |
| 3 | `handle_missing()` | 값이 **안 들어온 자리**를 어떻게 다룰지 |

**세 번째는 정답이 하나가 아닙니다.** 버릴지, 앞 값으로 채울지, 따로 표시할지 —
여러분이 고르는 것이고, 그 선택을 나중에 설명할 수 있으면 됩니다.

**힌트**

- C만 하다 온 사람을 위한 **인덱싱·슬라이싱 힌트 박스**가 `detect.py` 안에 붙어 있습니다.
  (예: 직전 W개는 `values[i-w:i]`)
- 표준편차가 **0이 되는 경우**를 한 번 생각해 보세요. 나누기에서 터집니다.
- **15분이 지나면 강사가 힌트 카드 1을 전체 공개**합니다.
  막혀 있는 게 정상 범위라는 뜻이니 부담 갖지 마세요.

**막히면 — `점검.py` 를 여세요. 혼자 헤매지 않게 만들어 둔 것입니다.**

`run.py` 는 다 채워야 돌아가지만, `점검.py` 는 **채우는 도중에도** 돌아갑니다.
세 함수를 하나씩 돌려 보고 **어디가 왜 틀렸는지만** 짚어 줍니다. 답은 주지 않습니다.

아직 아무것도 안 채웠으면 이렇게 나옵니다 — **이게 정상입니다.**

채울수록 `[ ]` 가 `[O]` 로 바뀝니다. 아래쪽 붉은 줄이 **다음에 뭘 할지**를 알려 줍니다.

**시간이 다 됐는데도 막혀 있으면** — 마지막 수단이 있습니다.
막힌 함수 **하나만** 완성본으로 채웁니다. 나머지는 그대로 두고 계속 갑니다.

```bash

```

> 다음 장면까지 같이 도착하는 것입니다. 채운 함수는 나중에 한 번 읽어 보세요.

| 증상 | 조치 |
|---|---|
| `ZeroDivisionError` | σ 가 0인 구간입니다. 0일 때 어떻게 할지 정해 주세요 |
| `IndexError` | 앞쪽 W개가 아직 안 쌓인 구간입니다. i < W 일 때를 먼저 처리하세요 |
| 뭘 채워야 할지 모르겠다 | `uv run 점검.py --힌트 1` → 그래도 모르면 `--힌트 2` |
| 시간이 없다 | `uv run 점검.py --열기 <번호>` 로 그 함수만 채우고 다음으로 |

- 천천히 오르는 변화는 **최근 평균도 같이 올라갑니다.** 기준선 자체가 따라 움직이니
  지금 값과 평균의 차이가 벌어지지 않습니다. **z-score의 구조적 한계**입니다.
- 값이 아예 안 들어온 구간은 **계산이 통째로 건너뜁니다.** 없는 값은 평균에도, 판정에도
  들어가지 않으니 "이상하다"고 말할 기회 자체가 없습니다. 이걸 잡으려면 TODO 3에
  **별도 규칙**을 넣어야 합니다 — 그게 TODO 3의 정답이 여러 개인 이유입니다.
- 임계값을 낮추면 **아닌데 울리는 것이 훨씬 빠르게 늘어납니다.** 참고 구현 실측으로는
  기본값에서 하루 약 81번이던 것이 k=2.0에서 **하루 약 911번, 11배**가 됩니다.

**이 한계를 적어 두세요. 내일 실습이 정확히 이 문제에서 시작합니다.**

</details>

#### 2-3. Step 3 — AI가 짠 것과 나란히 놓기 (10분)

**이 자리는 강사가 화면에서 직접 합니다.** 여러분은 화면을 보면서
**내가 짠 코드와 비교**하면 됩니다. 따로 설치할 것은 없습니다.

강사가 AI에게 시키는 것은 여러분이 방금 짠 것과 **같은 함수**입니다.

```

윈도 통계, 임계 판정, 결측 처리를 포함해서.
```

화면에 뜬 코드를 내 `detect.py` 와 나란히 놓고 봅니다. **특히 결측 처리(TODO 3)를 보세요.**

```
AI는 결측을 어떻게 처리했나?   ____________________________
내 방식과 다른 점은?           ____________________________
어느 쪽이 낫나, 왜?            ____________________________
```

세 번째 칸에 답할 수 있다는 것 — **그게 오늘 이 랩이 준 무기입니다.**

## §1. 내 코드를 MCP 도구로 내놓기 (55분)

#### 왜 하는가 (교안 원문)

> 알고리즘이 혼자 돌면 스크립트, 에이전트가 도구로 쓰면 지능이 된다.

2일차에 짠 `detect()` 는 아직 스크립트입니다. 이걸 **MCP 도구**로 내놓으면, AI가
"지난주 이상 점검해 줘"라는 말을 듣고 **알아서 여러분의 코드를 호출**합니다.
MCP는 AI에게 외부 프로그램을 손으로 달아 주는 표준입니다 —
**오늘 오전은 「읽는 손」, 오후는 「움직이는 손」**입니다.

#### 1-0. 준비 (8분)

```bash
cd 3일차/실습/도구만들기
```

**`config.json` 은 어제 `내번호.py` 가 이미 채워 뒀습니다.** 열어서 확인만 하세요.

```jsonc
{
  "transport": "stdio",
  "data_source": "fallback",                 // fallback 이어야 합니다
  "fallback": {
    "csv_path": "auto",                      // 2일차 CSV 를 스스로 찾습니다
    "shared_api": "http://34.64.94.16:8000",// 강사 서버 — 자동으로 채워집니다
    "tenant": "S07"                          // 내 번호 — 자동으로 채워집니다
  }
}
```

| # | 항목 | 이렇게 돼 있어야 합니다 |
|---|---|---|
| ① | `data_source` | `"fallback"` |
| ② | `fallback` → `shared_api` | 강사 서버 주소. **`127.0.0.1` 이면 안 됩니다** |
| ③ | `fallback` → `tenant` | **내 번호** (예: `S07`) |

> **②③ 이 비어 있으면** — 어제 `내번호.py` 를 안 돌린 것입니다.
> **`127.0.0.1` 로 돼 있으면** — 돌리긴 했는데 강사 주소 대신 그걸 넣은 것입니다.
> 둘 다 고치는 법은 같습니다. `2일차/실습` 에서 이렇게 한 번 치세요 —
>
> ```bash
> uv run 내번호.py --서버 http://<강사가 알려 준 주소>:8000
> ```
>
> 번호는 그대로 유지되고 여기 설정만 새 주소로 다시 채워집니다.
> **손으로 적지 마세요** — 오타 하나로 오후가 통째로 막힙니다.

> **왜 `fallback` 인가** — 원래는 각자 만든 데이터베이스를 보게 되어 있는데,
> 이번 특강에서는 그 단계를 하지 않았습니다. `fallback` 은 **센서값은 나눠받은 CSV에서,
> 정비 이력은 강사 서버에서** 가져오는 경로입니다. 도구 이름과 응답 형태는 똑같아서
> 이후 단계는 전부 동일합니다. **전원 이걸로 진행합니다.**

> ⚠️ `shared_api` 가 `127.0.0.1` 이면 **"내 컴퓨터"** 를 가리킵니다.
> 그러면 정비 이력을 못 가져오고, 잠시 뒤 진단 리포트에 **원인 추정이 안 나옵니다.**
> 리포트가 밋밋하게 나오는 이유는 대부분 이것입니다. **지금 바꿔 두세요.**
> (나눠 준 상태에서는 `shared_api` 와 `tenant` 가 **빈 칸**입니다. `내번호.py` 가 채웁니다.)

**중간 확인** — 아직 아무것도 안 채웠으므로 오류가 나는 게 정상입니다.

```bash
uv run mcp_server.py --check
```

`NotImplementedError` 가 나오면 준비 완료입니다. 다음으로 갑니다.

| 증상 | 원인 | 조치 |
|---|---|---|
| `detect.py 를 불러오지 못했습니다` | 2일차 TODO 세 곳이 비어 있음 | `2일차/실습` 에서 `uv run 점검.py` 로 먼저 끝냅니다. 시간이 없으면 `--열기` |
| `NotImplementedError` | ★ 두 자리 중 하나가 비어 있음 | `uv run 점검.py` 가 어느 자리인지 알려 줍니다 |
| 정비 이력이 빈 배열로 온다 | `shared_api` 가 `127.0.0.1` | 1-0 의 서버 주소로 바꿉니다 (`점검.py` 0-1 이 잡아 줍니다) |
| 401 이 뜬다 | 번호·키 불일치 | `2일차/실습` 에서 `uv run 내번호.py` 를 다시 치세요 |
| 시간이 없다 | — | `uv run 점검.py --열기 <번호>` 로 그 도구만 채우고 다음으로 |

#### 1-2. Step 2 — AI 에게 말로 시키기 (22분)

**다 채운 사람은 여기서 멈춥니다.** 강사가 "다 같이" 라고 하면 그때 칩니다.

```bash
uv run agent.py
```

이 한 줄이 AI 에게 **문장 하나**를 줍니다.

```
지난 주 설비 이상을 점검하고, 이상이 있으면 해당 설비의 정비 이력을 조회해
원인 추정과 권고 조치를 담은 진단 리포트를 작성하라.
```

> **도구를 언제 어떤 순서로 부를지는 말하지 않습니다.** AI 가 정합니다.
> 이게 오늘 오전에 배운 ReAct 입니다.

화면에 이렇게 찍힙니다 — **AI 가 내가 만든 도구를 스스로 부르는 장면**입니다.

```
  도구 호출  detect_anomaly(equipment_id=EQ-03, hours=168)
      → {"anomaly_count": 97, …}
  도구 호출  query_equipment(equipment_id=EQ-03)
      → {"maintenance": [{"work_order_no": "WO-2026-0801", …
```

> **도구는 내 컴퓨터에서 실행됩니다.** 강사 서버는 「어느 도구를 부를지」만 중계합니다.
> 그래서 내 PC 에 AI 키를 두지 않아도 됩니다.
>
> 설비를 하나만 보게 하려면 — `uv run agent.py --설비 EQ-03`
> 지시 문장을 내 것으로 바꾸려면 — `uv run agent.py --지시 "..."`

**성공 판정** — 리포트에 세 가지가 다 있으면 완성입니다.

```
☐ 어느 설비가 이상한지
☐ 원인 추정 — 정비 이력을 근거로 (WO 번호가 인용되어야 함)
☐ 권고 조치
```

**막히면**

| 증상 | 원인 | 조치 |
|---|---|---|
| 도구를 하나도 안 부른다 | 서버가 안 붙음 | 아래 「서버가 안 붙을 때」 참조 |
| 이상은 찾는데 원인이 없다 | 정비 이력을 안 부름 | 지시문에 "정비 이력을 조회해" 가 들어 있는지 확인 |
| 리포트가 뭉뚱그려 나온다 | 지시가 짧아서 | 그대로 두세요. **오후에 이 문제를 다룹니다** |

**서버가 안 붙을 때**

`uv run mcp_server.py --check` 로 **서버 없이 도구만** 먼저 확인하세요.
거기서 JSON 이 나오면 도구는 멀쩡한 것이고, 붙는 문제는 손 들면 강사가 봐 줍니다.

> `--check` 는 MCP 서버를 안 띄우고 함수만 직접 부릅니다. 방화벽과 무관합니다.
> **도구가 도는지 확인하는 데는 이걸로 충분합니다.**

#### 1-3. 여기까지의 한계 (5분, 읽기만)

리포트가 "속도를 낮추라"고 권고해도 **공장은 그대로 돕니다.**
읽는 손까지 달았고, 움직이는 손이 없습니다.

그리고 문제가 하나 더 있습니다. 방금 준 지시 한 문장을 다시 보세요.

> 지난 주 설비 이상을 <u>점검하고</u>, 정비 이력을 <u>조회해</u>
> 원인을 <u>추정</u>하고 리포트를 <u>작성하라</u>.

**한 문장에 네 가지 일**이 들어 있습니다. 오후에 이걸 쪼갭니다.

## §2. 폐루프 닫기 (70분)

#### 왜 하는가 (교안 원문)

> 마지막은 배운 것의 확인이 아니라, 스스로 폐루프를 확장할 수 있다는 증명이다.

지금까지 에이전트는 **제안만** 했습니다. 이제 판단이 **실제 설비를 바꿉니다.**

#### 2-0. 준비 (7분)

```bash
cd 3일차/실습/폐루프
```

`config.json` 맨 위 **세 줄**은 어제 `내번호.py` 가 이미 채워 뒀습니다. 확인만 하세요.

```json
"tenant":     "S07",
"access_key": "영문·숫자로 된 긴 문자열",
"base_url":   "http://34.64.94.16:8000"
```

**먼저 이것부터 돌립니다.**

```bash
uv run loop.py --check
```

`연결  http://… · S07 · 설비 6대 · 로봇 2대` 가 나오면 준비 끝입니다.

![loop.py --check — 첫 줄에 연결 정보, 둘째 줄에 제어 통로 상태](그림/실습/실습_3_loop_check.png)

위 화면처럼 **둘째 줄에 「제어 통로가 아직 잠겨 있습니다」** 가 나오면 강사가 아직 열지
않은 것입니다. 첫 줄(연결)만 맞으면 여러분 쪽 준비는 끝난 것이니 그대로 기다리세요.

> **「config.json 을 아직 안 채웠습니다」가 뜨면** — `2일차/실습` 에서
> `uv run 내번호.py` 를 한 번 치세요 (그 폴더에서 칩니다). 세 줄이 자동으로 채워집니다.
> 자리를 옮겼으면 `uv run 내번호.py S07` 처럼 내 번호를 붙이세요.

> **제어 권한은 강사가 방금 열었습니다.** 어제까지는 잠겨 있었습니다.
> 열기 전에 실행하면 `403` 이 납니다 — 그때는 손 드세요.

**진단은 실제 LLM이 합니다. 그런데 여러분은 API 키를 넣지 않습니다.**
호출은 **강사 서버가 대신** 합니다 — `config.json` 의 `diagnose.backend` 가 `"server"` 인 것이
그 뜻입니다. **그대로 두세요.** 어제 `내번호.py` 가 채워 준 접속 키로 서버가 여러분을 알아봅니다.

**여러분이 쓴 지시문이 그대로 올라갑니다.** 서버는 중계만 하고 문장을 만들지 않습니다.
그래서 `build_prompt()` 를 어떻게 쓰느냐가 결과를 바꿉니다 — 그게 오후의 핵심입니다.

> 터미널에 `원인(rules)` 이라고 찍히면 **AI 진단을 못 받은 것**입니다.
> 일곱 걸음은 그래도 끝까지 가지만, 오늘 봐야 할 장면(AI 가 정비 이력을 읽고
> 원인을 대는 것)이 안 나옵니다. **조용히 넘어가지 말고 손 드세요.**
> 정상이면 `원인(server)` 이라고 찍힙니다.

#### 2-1. 구조 파악 (6분, 읽기만 · 아무것도 고치지 마세요)

```
loop.py            오케스트레이터 — 전체 루프. 완성돼 있음. 건드리지 않음
agents/
  detector.py      ① 감지 에이전트   ★ 채울 곳
  diagnoser.py     ② 진단 에이전트   ★ 채울 곳
  actuator.py      ③ 조치 에이전트   ★ 채울 곳
hitl.py            승인 관문 — 완성돼 있음. 여러분이 못 건드리는 계층
control_client.py  제어 도구 연결 — 완성돼 있음
```

여러분이 채우는 건 **★ 세 곳뿐**입니다.

**오늘 열린 제어 도구 4개**

| 도구 | 무엇 | 승인 |
|---|---|---|
| `set_equipment_speed` | 설비 회전수 변경 (감속) | **자동** — 되돌릴 수 있으니까 |
| `ack_alarm` | 알람 확인 처리 | **자동** |
| `stop_equipment` | 설비 정지 | **사람 승인 필수** |
| `dispatch_robot` | 정비 로봇(AMR) 파견 | **사람 승인 필수** |

아래 둘만 승인이 필요한 이유는 **한 번 하면 되돌릴 수 없기 때문**입니다.
이 구분은 `hitl.py` 가 강제합니다. **여러분 코드가 실수로 정지를 자동 실행하는 일은
구조적으로 불가능합니다.**

#### 2-2. ★ 세 곳 채우기 (35분)

각 파일 ★ 자리의 주석에 무엇이 필요한지 적혀 있습니다.
설계 핵심만 여기 요약합니다. 막히면 `uv run loop.py --열기 1` (1 감지 · 2 진단 · 3 조치).

| ★ | 채울 것 | 설계 힌트 |
|---|---|---|
| `detector.py` | 온도 이력에서 **서서히 오르는 변화** 감지 | **어제 z-score가 왜 그 변화를 못 잡았는지 기억하세요.** 최근 구간을 **앞 절반 / 뒤 절반으로 나눠 평균을 비교**하면, 천천히 올라도 뒤 절반이 앞 절반보다 높습니다 |
| `diagnoser.py` | 이상 정보 + 정비 이력을 LLM에 주고 원인 추정 | 프롬프트에 **세 문장을 꼭 넣으세요** (아래 참조) |
| `actuator.py` | 진단 결과 → 어떤 도구를 부를지 결정 | 감속(자동)부터. 심각하면 파견을 **요청**합니다 (승인은 사람이) |

**`diagnoser.py` 프롬프트에 반드시 넣을 세 문장** — 안 넣으면 실측으로 확인된 함정에 빠집니다.
**아래 따옴표 안을 그대로 복사해 넣으세요.** 문장을 바꾸면 결과가 달라집니다.

```
① "이 변화는 지금 작아도 계속 오른다."
   → 안 쓰면 LLM이 "조금 올랐네요, 지켜보죠"라며 아무 조치도 안 냅니다.

② "원인이 정비 보류·지연이면 감속과 함께 로봇 파견 요청까지 낼 것.
   파견은 사람이 승인하므로 요청을 망설이지 말 것."
   → 안 쓰면 감속만 하고 끝나서, 승인 장면이 아예 안 나옵니다.

③ "근거(evidence)에는 작업지시 번호를 그대로 인용할 것."
   → 안 쓰면 원인은 맞게 짚어도 번호를 안 적습니다.
     바로 아래 '볼 것 세 가지' 의 첫 칸을 못 채우게 됩니다.
```

#### 2-3. 돌리기 — 고리가 닫히는 순간 (18분)

```bash
uv run loop.py
```

루프가 돌기 시작하면 **가만히 둡니다.** 강사가 서른아홉 개 공장에 동시에 주입합니다.

| 걸음 | 무슨 일이 | 누가 |
|---|---|---|
| 01 | 온도가 슬금슬금 오르기 시작 (공장 화면에서도 보임) | 강사 |
| 02 | **1~3분 안에** detector 가 포착 | 에이전트 |
| 03 | diagnoser 가 정비 이력을 뒤져 원인 추정 리포트 출력 | 에이전트 |
| 04 | actuator 가 감속을 **자동 실행** → 공장 화면에서 회전수가 떨어짐 | 에이전트 |
| 05 | 터미널에 **승인 요청**이 뜨고 **루프가 멈춰 섭니다** | 에이전트 |
| 06 | `y` 입력 | **사람** |
| 07 | 공장 화면에서 **AMR이 실제로 움직입니다** → 잠시 뒤 값이 바뀝니다 | 에이전트 |

터미널에 이렇게 뜹니다.

```
승인 요청 — 되돌릴 수 없는 행동입니다.
  dispatch_robot(AMR-01 → EQ-03)

  승인하시겠습니까? [y/N]
```

> **02 에서 아무 일도 안 일어나는 1~3분이 정상입니다.** 값이 충분히 쌓여야 판정이 섭니다.
> 고장 난 게 아닙니다. 기다리세요.

**성공 판정** — 주입부터 AMR 이동까지 위 일곱 걸음이 **승인 1회를 빼고 사람 개입 없이**
이어지면 완료입니다.

**볼 것 세 가지** — 숫자는 각자 다릅니다. 자기 화면을 보세요.

```
진단이 인용한 작업지시 번호   ______________________
승인 요청이 뜬 시각           ______________________
승인 뒤 온도가 어떻게 되었나  ______________________
```

**막히면**

| 증상 | 원인 | 조치 |
|---|---|---|
| 감지가 영영 안 된다 | 주입 전이거나 창에 데이터가 덜 참 | 2~3분 대기 → 그래도면 손 들기 |
| 진단이 "조치 불필요"만 낸다 | 프롬프트에 ① 문장이 없음 | 2-2 의 **세 문장**을 넣으세요 |
| 감속은 되는데 승인 요청이 안 뜬다 | 프롬프트에 ② 문장이 없음 | 2-2 의 **세 문장**을 넣으세요 |
| 원인은 맞는데 작업지시 번호가 없다 | 프롬프트에 ③ 문장이 없음 | 2-2 의 **세 문장**을 넣으세요 |
| `NotImplementedError` | ★ 자리가 비어 있음 | 어느 파일 몇 번째 줄인지 메시지가 알려 줍니다 |
| `403` | 제어가 아직 잠겨 있음 | 손 들기 — 강사가 엽니다 |
| 승인 후에도 로봇이 안 움직인다 | 번호·키 불일치 | `2일차/실습` 에서 `uv run 내번호.py` 를 다시 치세요 |
| 시간이 다 돼 간다 | — | 아래 **`--열기`** 를 쓰세요. 그래도 안 되면 **부록 E(최소 경로)** 로 내려가고, 막히면 손 드세요 |

**시간이 다 됐는데도 막혀 있으면 — 막힌 자리 하나만 열고 갑니다.**

```bash
uv run loop.py --열기 1     감지(judge) 만 완성본으로
uv run loop.py --열기 2     진단(build_prompt) 만
uv run loop.py --열기 3     조치(to_commands) 만
```

> **나머지 자리는 여러분이 쓴 것 그대로 돕니다. 파일은 안 고칩니다** —
> 옵션을 빼면 다시 내 코드로 돌아옵니다.
> 오늘 목표는 세 자리를 혼자 채우는 게 아니라 **AMR 이 실제로 움직이는 것을 보는 것**입니다.
> 여기까지 왔다고 진 게 아닙니다. 채운 함수는 끝나고 한 번 읽어 보세요.

### 그래도 안 될 때 — 최소 동작 조합

시간이 없으면 이 조합까지만으로 넘어가십시오 — 이것만으로도 폐루프는 성립합니다.

| 최소로 필요한 것 | |
|---|---|
| `judge()` | **필수** — 없으면 아무것도 시작되지 않습니다 |
| `build_prompt()` | 문자열 두 개만 돌려주면 됩니다. 규칙 진단이 받쳐 줍니다 |
| `to_commands()` | **감속 하나만** 만들어도 폐루프는 성립합니다 |

**가장 짧은 `to_commands()`** — 감속 하나. 이것만으로 감지 → 진단 → 조치가 닫힙니다.

```python
def to_commands(diagnosis, finding, cfg):
    rpm = finding.get("current_rpm")
    if not rpm:
        return []
    target = max(float(cfg["min_rpm"]), round(float(rpm) * float(cfg["slow_down_ratio"])))
    return [{"command": "set_equipment_speed", "target": finding["equipment_id"],
             "args": {"rpm": target}, "detail": f"{rpm:.0f} → {target:.0f} rpm",
             "why": "온도 상승을 감속으로 먼저 꺾습니다."}]
```

정지와 로봇 파견은 여기에 없습니다 — **승인 관문을 시연하려면 파견을 하나 더 넣으십시오.**
