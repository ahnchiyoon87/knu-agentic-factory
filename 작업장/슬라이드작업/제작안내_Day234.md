## 2. 생성 절차 (덱마다 따로)

6. **가능하면 두 판씩 뽑아 주세요** — Day 1에서 장별로 나은 쪽을 골라 쓰는 방식이

## 3. 각 덱이 지켜야 하는 것 — 생성물 검사 항목

### 공통 (Day 1과 동일)

- 배경은 **순백 하나**, 표지형(1번)만 짙은 남색. 세 번째 바탕이 나오면 실패
- 제목이 화면을 잡아먹지 않는가. **큰 낱말이 두 줄로 넘어가면 이미 너무 큰 것**
- 낱말 나열형에서 **그림 대신 굵은 가로줄만** 나오지 않았는가
- 나란히 비교형에서 **배경을 반으로 갈라 칠하지** 않았는가
- 같은 문장이 화면에 두 번 찍히지 않았는가
- 마지막 줄이 화면 밖으로 잘리지 않았는가
- 그림 안에 **격자·청사진 무늬·뜻 없는 숫자 더미**가 깔리지 않았는가

### Day 2 전용

- **빈칸의 정답이나 어떤 항목이 틀렸는지 화면에 나오면 안 됩니다.** 16페이지의 예시 문장
  ("온도가 심각 임계값을 넘으면 미해소 알람을 해제한다")이 맞는지 틀린지 **말하면 실패**입니다
- 13~15페이지의 GWT 세 예제는 **실습 문서에 실제로 있는 문장**입니다. 수치·설비·등급을 바꾸면 안 됩니다

### Day 3 전용 ★ 가장 중요

- **심어진 이상 셋이 각각 잡히는지 안 잡히는지가 화면에 나오면 그날 실습이 통째로 망가집니다.**
  스파이크가 잡힌다거나 드리프트가 안 잡힌다는 말이 한 글자도 나오면 안 됩니다
- 18페이지의 오탐 수치(**하루 81건 → 911건, 11배**)는 이론으로 다루는 것이라 나와야 합니다
- 11페이지 GraphRAG는 **오늘 실습에 없다**는 것이 분명해야 합니다

### Day 4 전용

- 제어 도구 **네 이름을 영문 그대로** 씁니다 — `set_equipment_speed` · `ack_alarm` ·
  `stop_equipment` · `dispatch_robot`. 한국어로 바꾸면 실습과 어긋납니다
- 승인 구분을 바꾸면 안 됩니다 — **감속·알람확인은 자동, 정지·파견은 사람 승인**
- 11~13페이지는 **라이브 시연 자리**입니다. 실제 화면은 강사가 띄우므로
  **대시보드 목업이나 시연 결과 그림을 그리면 안 됩니다**
- 실측값 고정 — 감지까지 **1~3분** · **WO-2026-0801「부품 입고 지연으로 보류」** · **63℃ → 53℃**

## 4. 생성 뒤 — PPTX 조립

Day 1과 같은 파이프라인입니다.

1. 후보 PDF들에서 **장별로 나은 쪽 선정**
2. 선정본에서 **삽화만 잘라내기** (`00_작업파일/crop_art*.py` 참고)
3. **글자는 설명란 원문으로 다시 찍기** (`00_작업파일/build_pptx.py` 를 덱별로 복제해 사용)
4. `00_작업파일/check.py` · `gap.py` 로 레이아웃 검사
5. 완성본을 `산출물/N일차_*/슬라이드_DayN_N장.pptx` 로 저장

> **왜 글자를 다시 찍는가** — Day 1에서 생성물을 검사했더니 글자 크기가 규격을 안 지키고,
> 무대 설정에 없는 숫자(72.5℃)를 지어내고, 같은 문장을 두 번 찍는 일이 실제로 있었습니다.
> 삽화만 살리고 글자는 확정 원고로 찍으면 이 사고가 구조적으로 막힙니다.
