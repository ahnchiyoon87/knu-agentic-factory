- **기본 미션 (전 팀 공통, 60분 목표)** — 강사가 시연한 것과 똑같은
  감지 → 진단 → 조치 폐루프를 **자기 팀 공장에서** 돌아가게 만들기. 템플릿이 제공됩니다.
- **확장 미션 (남는 시간, 다섯 중 택1)** — 폐루프에 **새 에이전트 1개**를 추가. §3 참조.
- **운영** — 90분 개발 + 30분 데모 준비. 팀마다 **'막힘 티켓' 2장** — 스태프를
  집중적으로 붙잡아 쓸 수 있는 권한입니다. 아껴 쓰세요.
- **평가 (100점)** — 폐루프가 실제로 도는가 40 / 스펙 문서화 30 / 창의성 30. 학생 즉석 투표 반영.
- **최우선 원칙** — 전원이 폐루프 데모에 성공하는 것. 확장 미션은 가점입니다.
  60분에 기본 미션이 안 끝나면 **'동작 보장 최소 경로' 카드**를 받으세요(부끄러운 게 아니라 설계된 안전망입니다).

# §2. 기본 미션 — 폐루프 완성 (목표 60분)

### 왜 하는가 (교안 원문)

> 4일의 마지막은 배운 것의 확인이 아니라, **스스로 폐루프를 확장할 수 있다는 증명**이다.

### 2-0. 준비 (5분)

실습 저장소의 `W6_폐루프템플릿/` 폴더에서:

```bash
cd W6_폐루프템플릿
pip install -r requirements.txt
```

`config.json` 에 **팀 쪽지의 정보**(팀 번호·서버 주소·팀 접속 키)를 넣습니다.

### 2-1. 구조 파악 (5분, 읽기만)

템플릿은 **오케스트레이터-워커 구조**(Day 1 패턴의 회수)로 짜여 있습니다:

```
loop.py            오케스트레이터 — 전체 루프. 완성돼 있음. 건드리지 않음
agents/
  detector.py      ① 감지 에이전트  ★ 채울 곳
  diagnoser.py     ② 진단 에이전트  ★ 채울 곳
  actuator.py      ③ 조치 에이전트  ★ 채울 곳
hitl.py            승인 관문 — 완성돼 있음. 팀이 못 건드리는 계층
control_client.py  제어 MCP 도구 연결 — 완성돼 있음
```

여러분 팀이 채우는 건 **★ 세 곳뿐**입니다. 연결·안전장치·실행은 전부 완성돼 있습니다.

**오늘 열린 제어 도구 4개** (여러분 코드가 MCP 도구로 호출하게 됩니다):

| 도구 | 무엇 | 승인 |
|---|---|---|
| `set_equipment_speed` | 설비 회전수 변경 (감속) | **자동** — 되돌릴 수 있으니까 |
| `ack_alarm` | 알람 확인 처리 | **자동** |
| `stop_equipment` | 설비 정지 | **사람 승인 필수** |
| `dispatch_robot` | 정비 로봇(AMR) 파견 | **사람 승인 필수** |

왜 둘만 승인이 필요할까요 — 물리 세계에는 **한 번 하면 되돌릴 수 없는 행동**이 있기
때문입니다. 이 구분(HITL)은 `hitl.py` 가 강제하므로, 여러분 코드가 실수로 정지를
자동 실행하는 일은 **구조적으로 불가능**합니다.

### 2-2. ★ 세 곳 채우기 (30~40분)

Claude와 함께 해도 됩니다. 각 파일의 ★ 자리에 무엇이 필요한지는 파일 안 주석에
적혀 있습니다. 설계 핵심만 여기 요약합니다:

| ★ | 채울 것 | 설계 힌트 |
|---|---|---|
| `detector.py` | 온도 이력에서 **드리프트** 감지 | 어제 z-score가 왜 못 잡았는지 기억하세요 — 최근 구간을 **앞 절반/뒤 절반으로 나눠 평균을 비교**하면, 천천히 올라도 뒤 절반이 앞 절반보다 높아집니다 |
| `diagnoser.py` | 이상 정보 + 정비 이력을 LLM에게 주고 원인 추정 | 어제 진단 리포트와 같은 구조. **"드리프트는 지금 작아도 계속 오른다"** 를 프롬프트에 명시하세요 — 안 그러면 LLM이 "조금 올랐네요, 지켜보죠"라며 아무 조치를 안 합니다 |
| `actuator.py` | 진단 결과 → 어떤 도구를 부를지 결정 | 감속(자동)부터. 심각하면 정지·파견을 **요청**(승인은 사람이) |

### 2-3. 돌리기 — 폐루프가 닫히는 순간 (10~15분)

```bash
python loop.py
```

루프가 돌기 시작하면 손을 들어 **강사에게 주입을 요청**하세요. 강사가 콘솔에서
여러분 팀 공장에 온도 드리프트를 주입합니다. 그다음은 지켜보면 됩니다:

1. 팀 공장의 온도가 슬금슬금 오르기 시작 (2D 화면에서도 보임)
2. **1~3분 안에** detector가 포착 (실측 79~190초 — 초조해하지 마세요)
3. diagnoser가 정비 이력을 뒤져 원인 추정 리포트 출력
4. actuator가 감속을 **자동 실행** → 2D 화면에서 회전수가 떨어짐
5. 터미널에 **`승인 요청 — 되돌릴 수 없는 행동입니다 … 승인하시겠습니까? [y/N]`** 가 뜸
6. 팀원이 `y` 입력 → **2D 공장 화면에서 AMR이 실제로 움직입니다**
7. 잠시 뒤 온도가 실제로 내려갑니다 (실측: 63℃ → 53℃대)

`[■ 캡처 — 승인 프롬프트 터미널 + AMR 이동 중인 2D 화면]`

**성공 판정** — 주입부터 AMR 이동까지 위 7단계가 사람 개입 없이(승인 1회 제외)
이어지면, 기본 미션 완료입니다. **여러분 팀의 AI가 방금 공장을 지켜냈습니다.**

**검증 도구** — 시간이 남으면 `python verify_lab.py` 로 전 구간 자동 점검을 돌려볼 수 있습니다.

### 막혔을 때 (기본 미션)

| 증상 | 원인 | 조치 |
|---|---|---|
| 감지가 영영 안 됨 | 주입 전이거나, 창에 데이터가 덜 참 | 강사에게 주입 여부 확인 → 2~3분 대기 |
| 진단이 "조치 불필요"만 냄 | diagnoser 프롬프트에 드리프트 특성 미명시 | 2-2의 힌트 문장을 프롬프트에 추가 |
| `NotImplementedError` | ★ 자리가 비어 있음 | 에러 메시지가 어느 파일 몇 번째인지 알려줍니다 |
| 승인 후에도 로봇이 안 움직임 | 팀 키·팀 번호 불일치 | config.json 을 팀 쪽지와 대조 |
| 60분이 다 돼 감 | — | **손 들고 '동작 보장 최소 경로' 카드 요청** — 몇 줄 설정으로 데모 가능 상태까지 보장됩니다 |

# §4. 데모 발표 (팀당 5분)

**구성: 시연 3분 + 설계 설명 2분.**

- **시연 준비** — 발표 직전, 진행 안내에 따라 강사가 여러분 팀 공장에 **미리 주입**해
  둡니다(감지까지 1~3분 걸리므로, 앞 팀 발표 중에 여러분 루프가 이미 돌고 있게 하는
  운영입니다). 안내에 따르기만 하면 됩니다.
- **시연 3분에 보여줄 것** — 감지 로그 → 진단 리포트 → 승인 장면(**y 누르는 순간을
  화면에**) → AMR 이동. 확장 미션이 있으면 이어서.
- **설계 설명 2분에 말할 것** — ① 세 ★를 어떻게 채웠나 ② 왜 그렇게 (특히 detector:
  z-score 대신 무엇을, 왜) ③ 스펙 문서 (평가 30점입니다 — Day 2에 배운 대로)

**평가 다시** — 도는가 40 / 스펙 30 / 창의 30 + 즉석 투표. **화려함보다 "실제로 도는가"가
최대 배점**입니다.
