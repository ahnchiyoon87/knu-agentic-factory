## 1. System Intent — 왜 만드는가

K-정밀은 CNC 6대와 운반로봇(AMR) 2대로 정밀 부품을 가공한다. 설비 이상을 사람이
눈으로 확인해 대응하다 보니, 야간·교대 시간대에 이상 발견이 늦어 불량과 설비 손상이
발생한다. **설비 상태를 자동으로 감시하고, 이상 시 정해진 규칙대로 알리고 조치를
기록하는 시스템**이 필요하다.

## 2. PRD — 무엇을 만드는가

| # | 기능 덩어리 (capability) | 한 줄 설명 |
|---|---|---|
| C1 | 설비·로봇 마스터 | 설비/로봇의 기본 정보와 정상 운전 범위를 등록·관리 |
| C2 | 알람 규칙 | 임계값 초과를 판정하고 등급을 매기고 단계적으로 확대(에스컬레이션) |
| C3 | 정비 작업지시 | 발행 → 수행 → 완료로 이어지는 작업지시 상태 관리 |

# C1. 설비·로봇 마스터

## 데이터

| 항목 | 설명 |
|---|---|
| equipment_id | 설비 식별자 (EQ-01 ~ EQ-06) |
| display_name | 표시 이름 |
| temp_warn_c / temp_crit_c | 온도 주의 / 심각 임계값 (℃) |
| vib_warn / vib_crit | 진동 주의 / 심각 임계값 |

> 로봇(AMR-01, AMR-02)도 같은 방식으로 robot_id·display_name·battery_min 을 관리한다.

# C2. 알람 규칙

## 규칙 정의

| 등급 | 발생 조건 |
|---|---|
| WARN (주의) | 측정값이 주의 임계값 이상, 심각 임계값 미만 |
| CRITICAL (심각) | 측정값이 심각 임계값 이상 |

- 알람은 **설비 1대 · 지표 1개 · 미해소 상태** 기준으로 **1건만** 유지한다(중복 생성 금지).
- 알람에는 발생 시각, 설비, 지표, 측정값, 등급, 확인 여부(ack)를 남긴다.

## 인수조건 (GWT)

**GWT-2.1** 온도 주의 알람
- Given: EQ-03 의 온도 주의 임계값이 65℃ 이고 미해소 알람이 없는 상태에서
- When: 온도 측정값 66℃ 가 들어오면
- Then: EQ-03 · temperature · WARN 알람이 1건 생성된다.

**GWT-2.2** 온도 심각 알람
- Given: EQ-03 의 온도 심각 임계값이 80℃ 이고
- When: 온도 측정값 82℃ 가 들어오면
- Then: **해당 설비의 미해소 알람을 해제한다.** ← **판정 대상 ⓑ**

**GWT-2.3** 중복 알람 방지
- Given: EQ-03 에 미해소 temperature WARN 알람이 이미 있고
- When: 다시 66℃ 가 들어오면
- Then: `_______________________________________________`  ← **빈칸 ③**

**GWT-2.4** 알람 해소
- Given: EQ-03 에 미해소 temperature 알람이 있고
- When: 온도가 주의 임계값 아래로 내려온 상태가 지속되면
- Then: `_______________________________________________`  ← **빈칸 ④**

**GWT-2.5** 에스컬레이션
- Given: CRITICAL 알람이 생성됐고
- When: **30분** 동안 아무도 확인(ack)하지 않으면
- Then: 상위 담당자에게 다시 통지한다.

**GWT-2.6** 센서 결측
- Given: EQ-01 의 센서 값이 들어오지 않는 상태가 10분 이상 지속되고
- When: 관제 시스템이 이를 확인하면
- Then: **정상으로 간주하고 알람을 만들지 않는다.** ← **판정 대상 ⓒ**

# C3. 정비 작업지시

## 상태 흐름

```
ISSUED(발행) → IN_PROGRESS(수행 중) → DONE(완료)
                     └──────────→ CANCELLED(취소)
```

- 작업지시에는 work_order_no, 대상 설비, 발행 시각, 조치 내용(action), 비고(note),
  상태(status)를 남긴다.

## 인수조건 (GWT)

**GWT-3.1** 작업지시 발행
- Given: EQ-03 에 CRITICAL 알람이 있고
- When: 담당자가 정비 작업지시를 발행하면
- Then: 상태 ISSUED 인 작업지시가 생성되고 해당 알람과 연결된다.

**GWT-3.2** 상태 전이 제한
- Given: 작업지시가 DONE 상태이고
- When: 상태를 IN_PROGRESS 로 되돌리려 하면
- Then: `_______________________________________________`  ← **빈칸 ⑤**

**GWT-3.3** 완료 처리
- Given: 작업지시가 IN_PROGRESS 이고
- When: 담당자가 조치 내용을 적어 완료 처리하면
- Then: `_______________________________________________`  ← **빈칸 ⑥**

**GWT-3.4** 보류 표기
- Given: 부품 입고 지연으로 작업이 멈춰 있고
- When: 담당자가 비고에 사유를 기록하면
- Then: 상태는 IN_PROGRESS 로 유지되고 비고가 함께 조회된다.
