# 경남대 RISE 피지컬AI 사관학교 — Agentic AI 특강 사전 제작물 기술 조사 보고서

## TL;DR
- **시뮬레이터는 "직접 제작"이 정답이다.** 완성형 오픈소스(FUXA·openTCS 등)는 존재하지만 "설비 색 변화 + AMR 2대 좌표 이동 + Supabase/Python 연동 + 39명 네임스페이스 격리"를 한 번에 만족하는 것은 없다. **HTML5 Canvas(Day1 바이브코딩 데모) + Konva.js(본 시뮬레이터 백본)로 자체 제작**하고, FUXA는 색변화 데모/영감용으로만 참조하라.
- **Supabase 무료 티어는 이 규모에서 위험하다.** 실시간 동시연결 200개·활성 프로젝트 2개·1주 미사용 시 자동 일시정지·공유 CPU 500MB RAM, 그리고 결정적으로 Postgres Changes가 단일 스레드로 처리되어(RLS 활성 기본 벤치마크 기준 초당 64건 변경) 병목이 확실하다. **강사용 Pro 프로젝트($25/월) 1개 + 테넌트 컬럼 격리 + 클라이언트 폴링(1~2초)**을 권장한다.
- **스펙 주도 개발(SDD)은 "순수 Markdown + EARS/GWT 템플릿"이 정답이다.** OpenSpec·GitHub Spec Kit·AWS Kiro 모두 실재하는 도구지만, 4시간 실습에 설치·학습 오버헤드를 얹으면 이탈 위험이 커진다. 도구는 강사가 시연만 하고, 학생 실습은 강사가 만든 4단계 Markdown 스펙 저장소 빈칸 채우기로 진행하라. (Kiro는 별도 IDE라 "VS Code + Claude 플러그인" 확정 환경과 충돌.)

## Key Findings

### 주제 1 — 웹 2D 공장 시뮬레이터: 자체 제작 권장 (Konva.js 또는 Canvas)
- 완성형 오픈소스 디지털 트윈/SCADA는 다수 존재하나(FUXA, Scada-LTS, PyScada, openTCS, OpenTwins, iTwin.js, Babylon.js 등) 대부분 3D·인프라·산업 프로토콜 지향이라 이번 요구(2D 평면도 + 색변화 + 좌표이동 로봇 + Supabase 연동 + 멀티테넌트)와 정합성이 낮다.
- **FUXA**(MIT 라이선스, Node.js + Angular + SVG, Docker 한 줄 `docker run -d -p 1881:1881 frangoteam/fuxa:latest`)는 설비 색상을 태그값에 따라 native로 바꾼다(공식 문서: shape의 Property 속성이 "displays different colors according to the change of the Tag value"). 그러나 **AMR의 연속 X/Y 좌표 추종 이동은 문서상 확인되지 않았고**, 내장 "move"는 값-구간 트리거 액션이라 연속 좌표 이동은 커스텀 SVG 위젯+JS가 필요하다. 또 **Postgres/Supabase 네이티브 드라이버가 없어**(커넥터: Modbus, S7, OPC-UA, MQTT, ODBC, Redis 등; DB 히스토리언은 SQLite/InfluxDB) ODBC 또는 Supabase REST(WebAPI 커넥터) 경유가 필요하다. → 데모/영감용으로는 훌륭하나 실습 백본으로는 부적합.
- 브라우저에서 AGV/AMR이 2D 경로를 따라 움직이는 "바로 쓸 만한" 오픈소스는 사실상 없다: openTCS(플랜트 오버뷰가 자바 Swing 데스크톱), rware(파이썬 Gym 렌더), agv-sim-js·WareRover(소규모 학생 프로젝트, 라이선스 불명확). 재사용 리스크가 크다.
- 2D 라이브러리 비교: **Konva.js**(씬그래프·이벤트·드래그·레이어 캐싱, React/Vue/Svelte 공식 바인딩, "best for interactive 2D canvas applications ... dashboards"), **PixiJS**(WebGL, 수천 스프라이트 이동 시 최고 성능이나 이 규모엔 과함·상호작용 API 약함), **Phaser**(완전한 2D 게임 엔진, 물리·타일맵 등 불필요 기능 과다), 순수 **Canvas/SVG**(의존성 0, 6~8개 설비 + 2대 로봇 수준엔 충분, 단 애니메이션·히트테스트 직접 구현).

### 주제 2 — Supabase 실시간 파이프라인: 무료 티어 한계 명확, Pro+폴링 권장
- 무료 티어(2026년 7월 기준, 서드파티 요약 + 공식 문서 교차확인): DB 500MB, 파일 1GB, egress 5GB, MAU 50,000, Edge Function 50만 호출, **Realtime 동시연결 200개**, Realtime 메시지 200만/월(256KB 최대), **활성 프로젝트 2개**, **공유 CPU·RAM 500MB**, **1주 미사용 시 자동 일시정지**, 자동 백업 없음, DB 직접연결 60개·pooler 200개. Pro는 $25/월, **Realtime 500 연결**(초과 시 1,000연결당 $10), 자동 백업 포함.
- 쓰기 부하(설비 8대×1초×39명 ≈ 312 rows/s): Postgres INSERT 자체는 감당 가능하나, **Realtime Postgres Changes는 변경 순서 유지를 위해 단일 스레드로 처리**된다(공식 벤치마크 verbatim: "Database changes are processed on a single thread to maintain the change order. That means compute upgrades don't have a large effect on the performance of Postgres change subscriptions"). RLS 활성·구독 기본 예시에서 **초당 64건 변경, 최대 초당 32,000 메시지, p95 238ms** 수준이라, 여기가 명확한 병목이다. 공식 문서도 대규모에서는 RLS/필터 없는 public 테이블 또는 Realtime Broadcast 재전송을 권한다.
- 실시간 vs 폴링: 교육환경에서는 **클라이언트 폴링(1~2초 setInterval + 최신 행 SELECT)**이 훨씬 예측가능·디버깅 용이하며 200연결·단일스레드 병목·탭 전환 시 presence stale 이슈를 피한다. Realtime 구독은 Day1 "실시간 느낌" 데모에만 시연용으로.
- 멀티테넌트 격리: (a) **테넌트 컬럼 방식**(student_id/team_id 컬럼) — 가장 단순, 교육환경 권장, (b) RLS — DB단 강제 격리로 안전하나 정책 작성·디버깅 부담(교육 시간 소모), (c) 스키마 분리 — 39개 스키마는 관리 과함.
- 가입 abuse: Supabase Auth는 IP 기반 토큰버킷(버킷 용량 30 요청), **내장 이메일 프로바이더는 프로젝트 전체 합산 시간당 2건**으로 강하게 제한된다(공식 문서). 동일 IP 대량 가입/이메일 전송은 확실히 429로 걸린다. 대응: 강사가 계정을 사전 일괄 생성(이메일 확인 비활성화 또는 커스텀 SMTP 필수), 또는 익명 로그인 + 테넌트 컬럼.
- 대안: 이 규모(39명·4일)에서는 **강사용 Pro 프로젝트 1개**가 자체호스팅보다 합리적. 자체호스팅 Supabase·PostgreSQL 직접운영은 특강 준비·운영 부담이 커서 비권장.

### 주제 3 — 이상감지 실습: 이동 윈도 z-score 난이도 적정, 3종 이상 가설 타당
- **이동 윈도 z-score는 컴퓨터공학 학부생 50분 실습에 적정.** rolling mean/std → |z|>임계 판정 → 결측 처리의 3-TODO 구조는 pandas `.rolling()`로 뼈대가 서고, C/C++ 경험자에게 시시하지 않으면서 완주 가능하다.
- **3종 이상 가설은 타당하다.** (a) 점진 드리프트 → 이동평균 baseline이 적응해 z-score가 커지지 않아 미탐(문헌상 collective/contextual anomaly, "A gradual 0.5°C temperature rise ... looks like measurement noise reading by reading" → 시퀀스·윈도 분석 필요), (b) 순간 스파이크 → point anomaly로 z-score에 쉽게 잡히나 임계값을 낮추면 오탐 급증, (c) 결측 → std 계산에서 NaN 전파로 통계 자체가 깨짐. 서로 다른 실패 모드를 잘 드러낸다.
- 합성 데이터 노이즈: 너무 깨끗하면 단순 임계값으로 다 잡혀 시시해지므로 정상 구간에 가우시안 노이즈를 넣어야 트레이드오프가 체감된다. 문헌상 spike 크기 5σ는 어떤 방법으로도 잡히고, 3σ 국소·드리프트는 어렵다.
- 공개 벤치마크: NAB(58개 실/합성 시계열, 1,000~22,000 관측), SKAB(수순환 펌프 8센서·34개 시계열·약 37,401 포인트·온도/진동 포함·결측 없음·이상 <5%), SMD/MSL/SMAP, MIMII(음향), CWRU(베어링). SKAB가 이번 시나리오(온도·진동 산업설비)와 가장 근접하나 라벨·컬럼이 고정이라 "드리프트/스파이크/결측을 원하는 위치에 심는" 교육 목적엔 합성 데이터가 우월하다. 벤치마크는 확장·검증용 보너스로.
- 확장 과제: 이동 IQR(비정규분포 강건), EWMA(드리프트에 더 민감), Isolation Forest(sklearn 한 줄, 스케일 안정성 높아 짧은 실습에 적합). Day3 MCP 도구화 + 진단 에이전트와 연결.

### 주제 4 — 스펙 주도 개발(SDD): 순수 Markdown + EARS/GWT 템플릿 권장
- **OpenSpec**: 실재 오픈소스 CLI(Fission-AI, npm `@fission-ai/openspec`, Node.js 20.19+). 5개 명령(`/opsx:explore·propose·apply·archive·update`), 산출물은 `openspec/changes/`의 순수 Markdown(WHEN/THEN BDD 구문). Spec Kit보다 경량(설치 약 5분, 첫 산출물 약 250줄 vs Spec Kit 약 800줄), 20+ AI 어시스턴트 지원, DB/SaaS 락인 없음.
- **GitHub Spec Kit**: 실재 오픈소스 툴킷. Specify CLI(uv/pipx)로 부트스트랩, 슬래시 명령 `/speckit.specify→plan→tasks→implement`(+ constitution·clarify·analyze). 각 단계가 Markdown 산출물 생성, 30+ 에이전트 지원. "heavyweight, rigid phase gates, Python setup"이라 4시간 실습엔 과함.
- **AWS Kiro**: 실재 에이전트형 IDE(VS Code OSS 기반, Amazon Bedrock, Claude/Nova 라우팅). 프리뷰 2025년 7월, **GA 2025-11-17**, Amazon Q Developer 후속(신규 가입 2026-05-15 중단, **Q 지원종료 2027-04-30**). 스펙 단계를 건너뛸 수 없고 **EARS 표기**로 요구사항 문서화. 무료 티어(월 50 크레딧/인터랙션)는 평가용, Pro $20/월·Pro+ $40·Power $200. **별도 IDE 설치·모델 락인이라 확정된 실습환경(VS Code + Claude 플러그인)과 충돌** → 소개만.
- **권장**: 39명이 4시간 안에 스펙 읽기·빈칸 채우기·코드 생성을 하려면 **순수 Markdown 스펙 + EARS/GWT 템플릿**이 가장 안전. 도구(OpenSpec)는 강사가 5분 시연, 학생 실습은 GitHub의 Markdown 스펙 저장소 빈칸 채우기 → Day2에서 Claude로 Supabase 백엔드 생성.
- **EARS**(Easy Approach to Requirements Syntax): Alistair Mavin 외(Rolls-Royce plc, 제트엔진 제어 SW 감항규정 분석 중 창안, IEEE RE'09에서 2009년 최초 발표)가 만든 5패턴 — Ubiquitous(The <system> shall <response>), Event-driven(When <trigger>, the <system> shall…), State-driven(While…), Unwanted(If…then…), Optional(Where…). Kiro가 채택.
- **GWT/Gherkin**: Given(전제)-When(행동)-Then(결과). BDD에서 유래, Cucumber가 지원하는 DSL이 Gherkin. 인수조건 작성 표준. OpenSpec의 WHEN/THEN도 같은 계열.
- **Intent→PRD→Spec→인수조건 체계**: OpenSpec의 proposal→specs/→design→tasks, Spec Kit의 constitution→spec→plan→tasks 구조가 실제 템플릿으로 존재. 이를 참고해 강사가 4단계 Markdown 템플릿 제작.

### 주제 5 — 합성 시계열 생성: numpy/pandas 직접 제작 권장 (GutenTAG는 참조)
- **GutenTAG**(TimeEval, pip `timeeval-gutenTAG`, Python 3.9~3.13): YAML 설정으로 base oscillation(sine, ECG, random walk, CBF 등 6종) + 10종 이상 이상(amplitude, extremum, frequency, mean, pattern, platform, trend, variance 등)을 위치 지정 삽입, `--seed`로 재현 가능, 마지막 컬럼에 0/1 라벨 자동 생성. 학술 벤치마크용으로 강력하나 **컬럼 구조가 고정(channels + label)이라** 요구 스키마(equipment_id, timestamp, temperature, vibration, rpm, run_state)와 직접 안 맞는다.
- **tirthajyoti/Synthetic-data-gen**(KDnuggets/TDS): 산업 시계열에 drift(`pct_drift_mean`, `time_drift`), 스파이크(`anomaly_scale`, `one_sided`) 삽입 함수 제공. 참조 코드로 유용.
- **권장**: 약 6만 행(설비 6대×7일×1,440분) 규모·특정 컬럼·특정 위치 이상은 **numpy/pandas 직접 작성**이 가장 합리적. `np.random.default_rng(seed)`로 재현성 확보, 설비별 정상 baseline + 가우시안 노이즈에 드리프트/스파이크/결측을 인덱스 지정 삽입하면 100줄 이내로 완성되고 컬럼·이상위치를 완전 통제할 수 있다. GutenTAG는 확장·검증 비교용.

## Details

### 주제 1 상세 — 라이브러리별 제작 소요·연동
- **Konva.js (권장)**: 씬그래프 노드 모델, 내장 드래그·이벤트, 레이어 분리 캐싱(정적 배경 1회 렌더 + 동적 로봇/설비 레이어만 재렌더)이 대시보드에 최적. 6~8 설비 색변화 + 2 로봇 tween 이동이면 **강사 제작 1~2일**(툴팁·상태색·경로 애니메이션 포함) 예상. Python 백엔드 연동은 Supabase JS 클라이언트 또는 폴링 fetch로 좌표/상태 갱신 → Konva 노드 속성 업데이트로 간단.
- **PixiJS**: WebGL 하드웨어 가속·스프라이트 배칭 자동. 수천 이동 객체엔 최고지만 이번 규모엔 오버킬, 상호작용/이벤트 API가 Konva보다 약함.
- **Phaser**: 완전한 2D 게임 엔진(물리·입력·사운드·타일맵). 시각적 임팩트는 크나 불필요 기능이 많고 데이터 바인딩엔 부자연스러움.
- **순수 Canvas/SVG**: 의존성 0, 학습 부담 최소, 바이브코딩(Day1)로 실시간 생성 시연에 최적. 단 애니메이션·이벤트·히트테스트 직접 구현. → **Day1 바이브코딩 데모는 Canvas, 본격 시뮬레이터 백본은 Konva**로 이원화 권장.
- 시각적 임팩트(KPI=등록 유지율): 설비 색상 상태전이(녹→황→적) + AMR 경로 tween + 이상 발생 시 펄스/알람 효과가 "보기"의 핵심. Konva 레이어 캐싱으로 60fps 무리 없음.

### 주제 2 상세 — 부하 시나리오와 권장 아키텍처
- Supabase Realtime 공식 벤치마크(AWS·k6): Broadcast(WebSocket) **동시 3.2만 사용자·초당 224,000 메시지·중앙값 지연 6ms·p95 28ms·p99 213ms**; DB 기반 Broadcast(realtime.broadcast_changes, DB 초당 1만 insert) **동시 8만 사용자·초당 1만 메시지·중앙값 46ms**. 단 이는 **대규모 유료 클러스터(2~6노드)** 수치이며 무료 티어(공유 CPU·200 연결)와는 무관하다.
- 39명 각자 1탭 = 39 WebSocket 연결로 200 한도 내지만, 팀별 다중 구독·재접속·복수 탭이면 여유가 줄고 단일스레드 Postgres Changes 지연(기본 초당 64건 변경)이 누적된다.
- **권장 아키텍처**: (1) 강사용 **Pro 프로젝트 1개**, (2) 학생 데이터는 `student_id`/`team_id` **테넌트 컬럼**으로 단일 테이블 통합, (3) 클라이언트는 **1~2초 폴링**으로 최신 상태 SELECT, (4) 데이터 생성기(Python)는 **배치 INSERT**로 쓰기 집중 완화, (5) 실시간 "느낌"이 필요한 Day1 데모만 Realtime 구독 시연. 폴링은 부하가 예측가능하고 디버깅이 쉬워 39명 동시 교육에 유리.
- 계정 abuse 대응: 강사가 39개 계정 사전 생성(스크립트, 단 내장 이메일 시간당 2건 제한 회피 위해 이메일 확인 비활성화 또는 커스텀 SMTP), 또는 익명 로그인 + 테넌트 컬럼.

## Recommendations
1. **시뮬레이터(최우선, 제작시간 최대)**: **Konva.js로 자체 제작** 확정. FUXA를 하루 안에 Docker로 띄워 "설비 색변화" 데모만 확인해 레퍼런스로 쓰되, AMR 좌표 이동·Supabase 연동·멀티테넌트 때문에 백본은 자체 제작. Day1 바이브코딩 시연은 의존성 0의 Canvas. **판단 기준**: FUXA 커스텀 SVG 위젯으로 AMR 이동을 반나절 내 구현하지 못하면 즉시 Konva 자체제작으로 전환.
2. **Supabase(최우선)**: **강사용 Pro 프로젝트 1개 + 테넌트 컬럼 + 1~2초 폴링** 확정. 계정은 강사가 사전 일괄 생성(이메일 확인 비활성화). **판단 기준**: 리허설에서 39개 동시 폴링 시 지연·에러가 없으면 유지, 병목 시 폴링 주기 3~5초 또는 데이터 생성 주기 5초로 완화.
3. **SDD(형식 미정, 우선순위 높음)**: **순수 Markdown 4단계 템플릿(intent→PRD→spec(EARS/GWT)→acceptance)** 확정. OpenSpec을 강사 데모용으로 5분 시연. Kiro는 실습환경과 충돌하므로 소개만.
4. **이상감지**: **이동 윈도 z-score 3-TODO + 노이즈 있는 합성 데이터** 확정. 확장 과제로 EWMA/Isolation Forest. SKAB를 "실제 산업 데이터" 검증용 보너스로.
5. **합성 데이터**: **numpy/pandas 직접 제작**(시드 고정, 100줄 이내) 확정. GutenTAG는 이상 패턴 아이디어 참조용.

## Caveats
- Supabase 무료 티어 수치(200 연결·2 프로젝트·1주 일시정지 등)는 서드파티 요약(2026년)과 공식 문서를 교차 확인했으나, **특강 직전 supabase.com/pricing에서 재확인 필수**(정책 변동 잦음).
- FUXA의 "AMR 연속 X/Y 좌표 이동" 네이티브 지원 여부는 **확인되지 않았다**. 문서상 move는 값-구간 트리거 액션이며, 연속 좌표 추종은 커스텀 SVG 위젯+JS가 필요할 가능성이 높다.
- Supabase Realtime 벤치마크의 대규모 수치(3.2만·8만 사용자)는 **유료 클러스터 기준이라 무료 티어에 그대로 적용되지 않는다**. 무료/기본 구독 시 실질 병목은 단일스레드 Postgres Changes(초당 약 64건 변경)다.
- 브라우저 네이티브로 "AGV가 2D 경로 이동"하는 잘 관리된·명확 라이선스 오픈소스 플래그십은 **현재 존재하지 않는다**(openTCS는 자바 데스크톱, 소규모 JS 프로젝트는 라이선스 불명확).
- 이상감지 3종 실패모드 가설은 문헌과 정합하나, 실제 체감 정도는 **노이즈·윈도크기·임계값 조합에 크게 좌우**되므로 리허설에서 파라미터 튜닝 필요.
- AWS Kiro의 출시일(GA 2025-11-17)·가격·모델 라우팅은 서드파티 리뷰 + AWS 공식 블로그 기반이며 세부는 변동 가능. Amazon Q Developer 지원종료(2027-04-30)는 여러 소스에서 일치.
