호서대 RISE 교안 전수 조사
— 경남대 8월 특강 재사용 판정

호서대 5일 과정 자료 전체를 슬라이드 단위로 확인하고, 경남대 8월 특강 교안이 "기반 자산"으로 명시한 항목과 하나씩 대조한 결과입니다. 슬라이드 번호는 실제 파일 기준입니다.

조사 방법
  • 호서대 Day 1~4 강의교재 PPT를 PDF로 변환 후 전 슬라이드를 이미지로 렌더링하여 육안 확인 — Day 1(70장), Day 2(69장), Day 3(59장), Day 4(42장), 총 240장
  • Day 5 PBL 자료(수행계획 PPT, 산출물 템플릿 docx, 평가 루브릭 docx) 텍스트 전문 확인
  • Day 2~4 핸즈온 가이드 docx 원시 XML에서 텍스트·이미지 수 직접 추출
  • 전 파일 대상으로 SDD·OpenSpec·GWT·PRD·스펙·인수조건·Supabase·RAG·벡터·임베딩·Text2SQL·GraphRAG·Neo4j·z-score·이상감지·시계열·센서 키워드 전수 검색

1. 교안의 "기반 자산" 주장 검증

경남대 교안 1페이지는 호서대 자산 네 가지를 재활용한다고 적었습니다. 대조 결과는 다음과 같습니다.

교안이 명시한 자산판정실제 확인 내용
에이전틱 디자인 패턴 영상 부분 일치 Day 1에 패턴 자료는 있으나 15개 패턴 체계(Antonio Gulli 저서 기반)이고, 경남대가 쓰려는 5종 중 2종은 이름조차 없음. 아래 3절 참조
SDD / OpenSpec 블록 부분 일치 SDD는 Day 2 슬라이드 58~61에 실제 존재. 다만 OpenSpec은 없음 — 슬라이드 61에 GitHub Spec Kit·AWS Kiro가 이름으로만 언급됨
Supabase 바이브코딩 부분 일치 Vibe Coding 블록(Day 2 슬라이드 57~64)은 있으나 대상이 Supabase가 아니라 Odoo. 실습도 "Odoo 데이터로 물류 대시보드 만들기"
MCP·멀티에이전트 재설계 구조 일치 MCP는 Day 2 슬라이드 21~36, 멀티에이전트·HITL은 Day 4 슬라이드 18~30에 충실하게 존재. 재사용률이 가장 높음

본문에 적힌 "호서대 영상 재활용" 두 건

위치교안 표기판정실제
Day 1 강의 11–17장 에이전틱 디자인 패턴 5종 (호서대 영상 재활용, 각 1분 30초) 부분 5종 중 2종만 상세 슬라이드 존재
Day 3 강의 8–12장 단순 RAG / Text2SQL / GraphRAG 3방식 대조 (호서대 영상 재활용) 없음 해당 자료 전무. 240장 육안 확인 + 키워드 전수 검색에서 미발견
"영상"에 대하여

업로드된 파일에 동영상 파일은 없습니다. Day 1 PPT 70장이 전부 이미지로 렌더링된 슬라이드인데, 이것을 "영상"이라 표현한 것인지 별도 녹화본이 있는지는 자료만으로 판단이 불가합니다. 다만 슬라이드 자체는 완성도가 높아 그대로 활용 가능합니다.

3. 핵심 발견 — 디자인 패턴 5종 문제

경남대 교안이 쓰려는 5종과 호서대 자료의 체계가 서로 다릅니다.

호서대 Day 1 슬라이드 32는 구글 Antonio Gulli의 Agentic Design Patterns 저서를 요약한 15개 패턴 체계입니다. 반면 경남대가 쓰려는 5종 중 Orchestrator-Worker와 Evaluator-Optimizer는 Anthropic 계열 용어라 호서대 자료에 그 이름이 등장하지 않습니다.

경남대 5종 패턴별 소스 확인
패턴판정호서대 소스
Prompt Chaining 상세 있음 Day 1 s36(작업의 조립 라인) · s37(시장조사 워크플로우 사례) · s38(LangChain LCEL 구현)
Routing 상세 있음 Day 1 s39(시스템의 교통경찰) · s40(4가지 라우팅 방식 비교표) · s41(파이프라인 완성)
Parallelization 이름만 Day 1 s32 목록 · s35 빌딩블록 아이콘. 전용 설명 슬라이드 없음
Orchestrator-Worker 해당 명칭 없음 15패턴 목록에 미포함
Evaluator-Optimizer 해당 명칭 없음 15패턴 목록에 미포함
다만 우회로가 있습니다

Day 4 슬라이드 26 "멀티 에이전트 협업 패턴 한눈에 보기"에 네 가지 협업 패턴이 한 장에 정리돼 있습니다 — 순차 협업(Sequential) / 병렬 협업(Parallel) / 총괄-분배(Supervisor) / 검증과 되짚기(Review). 이것이 각각 Prompt Chaining · Parallelization · Orchestrator-Worker · Evaluator-Optimizer에 대응합니다.

따라서 5종을 채우려면 Day 1(Chaining·Routing 상세) + Day 4 s26(나머지 3종 개요)을 조합해야 합니다. 단, Day 4 s26은 한 장에 4개를 압축한 슬라이드라 각 1분 30초 분량으로 쓰려면 3장 정도는 새로 만들어야 합니다.
