## 1. 이 특강이 뭔가

경남대에서 열리는 **4일 × 4시간 특강**입니다. 학생 39명이 배우는 것은 한 문장으로
**"AI로 공장을 관리하는 법"** 입니다.

| 날 | 주제 | 학생이 하는 일 |
|---|---|---|
| 1일차 | **보기** | 코드 한 줄 안 치고, AI에게 말로 시켜 공장 관제 대시보드를 만든다 |
| 2일차 | **설계** | 말로만 시키면 왜 무너지는지 겪고, 스펙 문서로 다시 만든다 |
| 3일차 | **알기** | 센서 데이터에서 이상을 찾는 코드를 **직접** 짜고, 그걸 AI의 도구로 내놓는다 |
| 4일차 | **움직이기** | 팀별로 감지→진단→조치 AI를 완성해 **공장을 실제로 제어**한다 |

**마지막 날의 하이라이트가 이 특강의 존재 이유입니다** — 각 팀이 만든 AI가 자기 공장의
고장을 스스로 알아채고 → 원인을 찾고 → 기계를 늦추고 → 사람 승인을 받아 로봇을 출동시킵니다.
"내가 만든 AI가 내 공장을 지켜냈다"는 경험을 만드는 것이 목표입니다.

## 8. 협업 규칙

1. **`.env` 는 커밋 금지** — 새 자격증명 파일도 같은 원칙
2. 산출물 코드를 고치면 **그 폴더의 verify 를 돌려 통과 확인** 후 커밋. 구조를 바꿨으면 리허설까지
3. 교안 사양(수치·순서·이름)은 임의 변경 금지 — 바꾸려면 회의에서 합의
4. 큰 파일(pptx·zip·영상)은 커밋 금지 (`.gitignore` 가 확장자로 막음)
5. 학생 재료를 고치면 **k-precision-lab 에도 반영** (원본=여기, 배포본=학생 저장소)
