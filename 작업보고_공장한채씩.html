공장 한 채씩

클라우드 서버 한 대를 서른아홉 명이 나눠 쓰던 구조를 걷어내고, 학생 노트북마다 가상 공장이 한 채씩 도는 구조로 옮겼습니다. 그 대가로 늘어난 설치 과정은 추측 없이 전부 실제로 깔아 보며 다시 썼습니다.

대상 2·3일차 · 39명 · 비전공 성인 기록일 2026-08-20 저장소 knu-agentic-factory
01

서버를 지운 자리에 무엇이 남았나

공유 자원이 하나 사라질 때마다 그것을 관리하던 코드·문서·수업 절차가 같이 사라집니다. 이번에 사라진 것이 그만큼 많았습니다.

전 — 공유 서버후 — 각자 노트북
클라우드 VM 한 대에 공장 전체 docker compose 한 벌이 학생 PC 안에서 돈다 (FastAPI + Postgres)
학생마다 번호 배정 (S01~S39) 전원이 S01. 번호 관리라는 개념이 없다 — DB가 각자 것이라 부딪힐 상대가 없다
자리배정표 · 키배포표 · 강사 리모컨 없음. 고장 주입은 학생 화면의 [이상 시작] 버튼
접속 키 · 세션 풀러 한도 · 부하 가드레일 없음. 각자 컴퓨터라 몰릴 곳이 없다
망가지면 강사가 서버에서 복구 docker compose down -v 한 줄이면 초기화. 망가뜨려도 자기 것만

같이 삭제한 코드와 문서

구조가 바뀌었는데 옛 코드가 남아 있으면, 다음에 고치는 사람이 그것을 살아 있는 규칙으로 읽습니다. 쓰이지 않게 된 것을 남기지 않았습니다 — 강사 콘솔·번호 발급·격리 검증 도구·부하 시험 문서· 옛 마이그레이션 넷, 그리고 화면에서 테넌트를 고르던 선택칸까지.

클라우드 정리

GCP의 VM·고정 IP·방화벽 규칙을 전부 삭제했고, Supabase 프로젝트도 은퇴시켰습니다. 남은 과금 자원은 없습니다.

딱 하나 남은 공유 자산 — OpenAI 키

3일차 AI 진단만은 외부 서비스를 씁니다. 이것 하나가 39명이 함께 쓰는 유일한 자원입니다. 키를 학생에게 그대로 주지 않기 위해, 배포본을 만들 때 캡슐(KNU1:)로 바꿔 zip 안 .env에 심습니다. 학생이 열쇠와 관련해 할 일은 0이고, 화면과 파일 어디에도 sk-로 시작하는 원문이 나오지 않습니다.

캡슐은 암호화가 아니라 가림막입니다. 진짜 방어선은 두 가지입니다 — 전용 프로젝트에 걸어 둔 예산 상한, 그리고 수업이 끝나면 키를 삭제하는 것. 키를 지우는 순간 배포된 zip 안의 캡슐도 같이 죽습니다.

39명이 동시에 부를 때를 대비해 각자의 공장 안에 지수 백오프 재시도를 넣었습니다. 잔액이 없을 때는 재시도하지 않고 그대로 알려 줍니다 — 화면의 안내가 거짓말이 되면 안 되기 때문입니다.

02

대가는 설치 과정이었다

서버가 없어지면 그 서버가 하던 일을 학생 노트북이 합니다. 준비 안내가 네 단계에서 일곱 단계로 늘었습니다.

단계학생이 하는 일
① 노션배운 것을 남길 계정. 마지막에 그 링크를 내는 것이 수료 조건
② VS Code코드를 고치고 명령을 치는 창. 이틀 내내 이 화면을 본다
③ 실습 파일빈칸이 뚫린 코드와 7일치 센서 기록
④ uv파이썬을 대신 갖춰 주는 도구. uv run만 치면 된다
⑤ WSL새로 생김 — Docker가 올라탈 바닥
⑥ Docker새로 생김 — 공장을 포장째 받아 돌린다
⑦ 공장 켜기새로 생김 — docker compose up -d 후 브라우저로 확인

⑤·⑥·⑦은 하나로 묶여 있었는데 셋으로 갈랐습니다. 중간에 컴퓨터 재시작이 끼는 구간이라, 한 덩어리로 두면 학생이 자기가 어디까지 왔는지 알 수 없습니다.

그리고 일곱 개 모두 첫 줄에 「이게 무엇인지」를 적었습니다. 이름도 모르는 것을 일곱 개나 설치하면 「내가 뭘 하고 있는 거지」가 됩니다.

03

지우고, 다시 깔면서 적었다

설치 안내는 추측으로 쓰면 반드시 어긋납니다. 그래서 이 컴퓨터의 Docker와 WSL을 전부 지우고, 학생과 같은 맨바닥에서 처음부터 다시 깔며 화면을 잡았습니다.

지운 것

컨테이너·이미지·볼륨·빌드 캐시 전부(805MB 회수), Docker Desktop 본체와 설정 폴더 셋, 시작 메뉴 바로가기, WSL 배포판 Ubuntu, WSL 앱 패키지. 배포판을 지우기 전에 안을 열어 사용자 파일이 없는지 확인했습니다.

그렇게 해서 확정된 것

  • wsl --install은 재부팅 없이 그 자리에서 WSL 2.7.12와 Ubuntu를 설치한다
  • 이어서 세 가지를 묻는다 — 사용자 이름, 암호 두 번, Ubuntu 통계 수집 동의
  • Docker Desktop을 먼저 실행하면 「WSL not installed」 창이 뜬다. 그 창의 안내가 wsl --install과 컴퓨터 재시작이다
  • WSL을 깔고도 재시작하지 않으면 「Starting the Docker Engine…」에서 붙잡힌다

틀렸던 서술 — 실측으로 바로잡음

「Use WSL 2 체크박스에 체크」 — 설치기에 그런 체크박스가 없습니다. 실제 화면은 Per-user 라디오이고, 그 설명문에 Uses the WSL 2 backend라고 적혀 있습니다.

「재시작한 뒤 Ubuntu 검은 창이 열려 이름을 묻는다」 — 창이 따로 열리지 않습니다. 방금 wsl --install을 친 그 PowerShell 창에서 바로 이어집니다.

문서에는 사진에 찍힌 것만 적었습니다. 공식 문서에서 가져온 것은 절차의 근거 (관리자 PowerShell에서 실행, 설치 후 재시작, 이미 설치돼 있으면 도움말이 뜬다)이고, 그 밖의 「이럴 것이다」는 넣지 않았습니다.

확인 방법 — Microsoft Learn 「Install WSL」과 Docker 공식 문서를 원문으로 대조. 화면은 이 PC에서 실제로 설치하며 촬영한 캡처 23장.
04

학생 자료에서 걷어낸 것

맨바닥에서 다시 밟아 보니 그동안 안 보이던 것들이 드러났습니다.

실습 zip에 6,176개가 섞여 있었다

배포본 폴더에서 코드를 한 번 돌리면 .venv가 생기는데, 압축이 그것까지 통째로 담고 있었습니다. 항목이 6,269개(그중 .venv 6,176개)였습니다. 학생 PC에서는 경로가 달라 쓰지도 못하는 짐입니다. 찌꺼기를 거르도록 고치고, 다시 새면 빌드가 멈추도록 검사를 넣었습니다. 지금은 64개입니다.

화면에 남아 있던 개인 정보

  • wsl --install 캡처에 계정명과 컴퓨터 이름이 찍혀 있었다 → 같은 출력을 학생 이름으로 다시 그림
  • VS Code 첫 화면의 「최근 항목」에 개인 프로젝트 경로가 노출 → 그 위까지만 남기고 잘라냄
  • 탐색기 캡처에 정답 폴더가 보였다 → 그 그림이 가리키는 메뉴 줄만 남김

사진이 실제와 달랐다

탐색기 사진에 2일차·3일차·데이터 셋만 있었습니다. 공장 폴더가 생긴 지금 배포본과 어긋납니다 — 학생이 자기 화면과 대조하다 멈추는 자리입니다. 넷이 다 보이는 실측으로 교체했습니다.

05

같은 실수가 되풀이되지 않게

한 곳을 고치면 같은 종류가 다른 곳에서 또 나옵니다. 유형으로 잡고, 도구가 막게 했습니다.

무엇이 문제였나어떻게 막았나
치라고 준 명령에 「화면에 이렇게 나옵니다」가 붙었다 — 학생은 그 상자가 입력인지 결과인지 알 수 없다 명령으로 인정하는 첫 낱말에 docker·wsl·powershell이 빠져 있었다. 세 문서의 코드 블록을 전수로 대조해 다섯 곳을 바로잡고, 목록에 주석을 남겼다
사진과 그 설명이 쪽 경계에서 갈라졌다 둘을 한 덩어리로 묶어 구조로 고정. 밀림으로 생기던 큰 공백도 사라져 준비안내가 17쪽에서 13쪽이 됐다
사진이 끼면 번호 목록이 전부 「1.」로 리셋 원문의 숫자를 살리도록 수정
강사가 pptx를 열어 두면 빌드 전체가 멈췄다 잠긴 파일은 건너뛰고 나머지를 갱신한 뒤, 무엇이 안 바뀌었는지 끝에 알린다 — 슬라이드 작업과 동시에 자료를 다시 뽑을 수 있다
강조 상자가 옆 메뉴를 물거나 글자를 덮었다 좌표를 눈대중 대신 이미지에서 픽셀로 재서 넣는다

덧붙임

슬라이드를 고치는 사람이 빌드 구조를 몰라도 시작할 수 있도록, 맥락과 문체 규칙만 담은 문서를 따로 두었습니다 — 강의가 어떤 자리인지, 무대는 무엇인지, 이틀 줄거리, 절대 규칙, 그리고 실제로 세 번 빠졌던 문장 함정 다섯 가지.

06

지금 상태와 남은 일

학생 조건으로 완주했습니다

자동 검증이 통과했다는 것과, 학생이 겪는 순서를 실제로 밟아 보는 것은 다릅니다. 배포본 zip을 새로 풀어 처음부터, 정답을 보지 않고 빈칸을 직접 채우며 갔습니다.

  • 2일차 — 빈칸 다섯(평균·표본분산·σ=0 방침·z 판정·결측 방침) 직접 채워 3/3 통과. 7일치 6만 행에서 기준선 0.94% · 오탐 하루 81건, 스파이크 3/3 · 드리프트 240 중 4 · 결측 0/120 — 기록된 실측치와 일치
  • 손잡이도 실제로 먹혔습니다 — --k 3.5로 오탐 하루 22건(목표 30건 아래)에 잡은 종류는 오히려 2종으로 늘었습니다
  • 3일차 — 도구 빈칸 넷 채워 2/2 통과. AI가 도구를 스스로 부르고 WO-2026-0801을 근거로 인용
  • 폐루프 — 빈칸 다섯을 채우고 제어를 연 뒤 고장을 걸어 한 바퀴: 감지(+0.9℃) → 진단(WO-2026-0801) → 자동 감속 1792 → 1433 rpm → 승인 관문(로봇 파견)까지 전부 돌았습니다

완주가 잡아낸 것

학생 파일 안에 은퇴한 구조가 살아 있었습니다 — 「강사 공용 서버로 우회」·「개인 DB」 안내, 그리고 Supabase를 부르는 코드 갈래 둘. 닿지 않는 죽은 코드였지만, 다음에 고치는 사람이 살아 있는 규칙으로 읽습니다. 전부 삭제하고 다시 확인했습니다 — 도구 2/2 그대로입니다.

그 밖에 확인된 것

  • 배포본 자동 검증 전 항목 통과 — 죽은 코드를 걷어낸 뒤 다시 돌린 결과입니다
  • 실습 zip 64개 파일, 준비안내 15쪽·그림 23장
  • uv 설치 한 줄을 PowerShell에서 그대로 실행 — 정상 설치 확인

사람이 해야 하는 것

  • OpenAI 예산 상한 설정
  • 업로드 직전 수업용 새 키로 배포본 재생성 후 드라이브 업로드 (지금 zip에는 시험용 키가 들어 있습니다)
  • 강의 리허설 — 시간 실측

남은 확인

완주는 코드와 명령을 따라간 것이고, 강의실에서 사람이 겪는 시간은 아직 재지 않았습니다. 리허설로 각 구간이 배정된 시간 안에 끝나는지 보는 것이 남아 있습니다.
