## 1. 과정 개요

1일차에서 「무엇이 완료인가」를 숫자와 시나리오로 못 박는 법을 배웁니다.
그런데 **그 숫자를 정할 줄 알려면 한 번은 직접 재 봐야 합니다.**
"오경보 월 2건 이하"라고 쓸 때, 그 2가 왜 20이 아니고 0.2가 아닌지 아는 사람과
모르는 사람은 같은 문장을 써도 결과가 다릅니다.

이 이틀은 그 감각을 만듭니다. 2일차에 이상감지 알고리즘을 **라이브러리 없이 직접 짜고**,
임계값을 흔들어 가며 정탐과 오탐이 어떻게 맞바뀌는지를 자기 데이터로 봅니다.
3일차에는 그 코드를 AI의 도구로 내놓고, AI가 원인을 진단해 설비를 실제로 움직이는 것까지
**폐루프를 닫습니다.** 마지막에 승인을 누르면 화면의 AMR이 목적지로 이동합니다.

### 과정 콘셉트

> **"AI가 내놓은 결과를 판정할 수 있는 사람만이 AI를 도구로 부립니다.
> 판정하려면 한 번은 직접 만들어 봐야 합니다."**

### 이 과정만의 차별점

- **1인 1개의 가상 공장** — CNC 설비 6대와 AMR 2대의 상태가 1초마다 변합니다.
  각자 자기 공장에서 감시하고 조종합니다.
- **직접 짜는 구간과 AI에게 맡기는 구간을 나눕니다** — 2일차는 알고리즘을 손으로,
  3일차는 연결과 판단을 Claude와 함께. 나누는 이유가 이 과정의 논지입니다.
- **동작하는 것까지 갑니다** — 명세로 끝나지 않습니다. 감속 명령에 온도가 실제로
  내려가고, 승인을 누르면 로봇이 이동합니다.
- **AI가 짠 것과 내 것을 나란히 놓습니다** — 같은 함수를 Claude에게도 짜게 하고
  "어느 쪽이 낫나, 왜"에 답해 봅니다.

### 왜 「직접 짜기」와 「AI에게 시키기」를 나누는가

| | 2일차 | 3일차 |
|---|---|---|
| 손코딩 | **25분** (함수 3개) | 거의 없음 |
| AI 사용 | 마지막에 비교용으로만 | 처음부터 끝까지 |
| 하는 일 | 알고리즘을 만든다 | **AI가 만든 것을 판정한다** |
| 얻는 것 | "왜 이건 안 잡히지?" | "AI에게 무엇까지 맡길 것인가" |

2일차에 AI를 쓰지 않는 것은 불편을 주려는 것이 아니라,
**3일차에 AI가 내놓은 진단을 보고 "이건 맞다 / 이건 아니다"를 말할 수 있게 하기 위해서**입니다.

## 3. 모듈별 상세

# 2일차 — 잡기

### 도입 (30분) — 새벽 3시에 무슨 일이 있었나

창원의 정밀기계 제조사 K-정밀. 새벽 3시부터 아침 7시 사이에 CNC 설비 한 대의 온도가
서서히 올랐고 아무도 몰랐습니다. 사람이 못 본 이유 세 가지를 짚으면
자연스럽게 *"80도 넘으면 알람 걸면 되잖아"* 에 도달합니다.

그런데 그 설비는 **80도를 넘은 적이 한 번도 없습니다.** 62도에서 64도로 올랐을 뿐입니다.

게다가 설비마다 정상 온도가 다릅니다(EQ-04 56℃ ~ EQ-05 75℃).
선을 66도로 낮추면 다른 설비들이 하루 종일 울립니다.
**모든 설비에 같은 경고선 하나를 그을 수 없다** — 여기서 출발합니다.

### §1 (20분) — 내 공장 열어보기

명령 한 줄로 자기 공장을 배정받습니다. 브라우저에 2D 공장 화면이 뜨고
설비 6대와 로봇 2대의 값이 1~2초마다 변합니다.

여섯 대의 평소 온도를 적어 둔 뒤, 공장에 이상이 하나 주입됩니다.
**2분 동안 화면만 보고** "무엇이 달라졌나"를 적습니다.
맞히는 시간이 아니라 **사람 눈으로 되는지 확인하는 시간**입니다.

**산출물**: 브라우저에 도는 내 공장 · 관찰 기록

### 이론 (20분) — 이상을 재는 자 셋

고정 임계값 / 이동 평균 / 이동 윈도 z-score.
임계값 k와 윈도 W가 무엇을 바꾸는지. 정탐과 오탐이 왜 동시에 좋아질 수 없는지.

### §2 (50분) — 이상감지 알고리즘 직접 구현

**이 구간은 AI에게 맡기지 않습니다.**

`detect.py` 의 함수 세 곳을 직접 채웁니다. 각 3~8줄입니다.

| # | 함수 | 채울 내용 | 걸리는 곳 |
|---|---|---|---|
| 1 | `window_stats()` | 직전 W개의 평균·표준편차 | 슬라이싱 범위, 지금 값을 넣느냐 |
| 2 | `is_anomaly()` | z-score가 k를 넘는지 | **표준편차가 0인 구간** |
| 3 | `handle_missing()` | 값이 안 들어온 자리 | **정답이 하나가 아님** |

라이브러리를 쓰지 않고 표본표준편차(n−1)를 직접 계산합니다.

**Step 2 — 7일치 데이터에 돌려 봅니다** (CNC 6대 × 7일 × 1분 = **60,480행**)

데이터에는 이상 세 가지가 심어져 있습니다. 결과입니다.

| 심어 둔 이상 | 결과 |
|---|---|
| 진동 스파이크 | **3개 중 3개** — 잡힘 |
| 온도 드리프트 | **241개 중 5개 (2.1%)** — 노이즈 수준. 못 잡은 것과 같음 |
| 센서 결측 | **121개 중 0개** — 못 잡음 |

**Step 3 — 임계값을 흔들어 봅니다**

| 임계 | 헛알람 | 하루 평균 | 드리프트 |
|---|---|---|---|
| k = 4.0 | 40행 | **6번** | 못 잡음 |
| k = 3.0 | 566행 | **81번** | 노이즈 수준 |
| k = 2.0 | 6,374행 | **911번 (11배)** | 여전히 노이즈 수준 |

**아무리 낮춰도 드리프트는 안 잡히는데 헛알람만 11배가 됩니다.**
이동평균이 같이 올라가기 때문입니다 — z-score의 구조적 한계입니다.
설명으로 듣는 게 아니라 자기 숫자로 봅니다.

**Step 4 — AI가 짠 것과 나란히 놓기** (10분)

같은 함수를 Claude에게 짜게 하고 비교합니다. 특히 결측 처리를 봅니다.
AI는 대개 `ffill`이나 `dropna`를 쓰는데, 그러면 2시간 내내 같은 값이 되어
표준편차가 0이 되고 **값이 돌아오는 순간 없던 이상이 하나 생깁니다.**

*"AI가 내놓은 결과물을 판정할 수 있는 사람"* — 이 구간이 주는 것입니다.

**산출물**: 완성된 `detect.py` · 임계값별 측정표 · AI 구현과의 비교 기록

### 닫기 (10분)

*"규칙으로는 여기까지입니다. 그럼 누가 판단하죠?"*
답하지 않고 끝냅니다. 내일 것입니다.

# 3일차 — 움직이기

### 도입 (40분) — 어제 만든 자를 회수한다

규칙은 **미리 정한 것만** 봅니다. 그러면 AI에게 맡기면 되나 — 환각을 먼저 봅니다.
그리고 에이전트, ReAct, 오케스트레이터, MCP까지.
**오전은 「읽는 손」, 오후는 「움직이는 손」입니다.**

### §1 (55분) — 내 코드를 MCP 도구로 내놓기

어제 짠 `detect()` 는 아직 스크립트입니다. **MCP 도구로 내놓으면 AI가
"지난주 이상 점검해 줘"라는 말을 듣고 알아서 그 코드를 호출합니다.**

| 도구 | 무엇 | 핵심 |
|---|---|---|
| `detect_anomaly` | 어제 짠 `detect()` 를 에이전트가 부를 수 있게 | **내 코드를 그대로 불러 씀** |
| `query_equipment` | 센서 요약 + 정비 이력 조회 | 정비 이력의 `note` 가 진단의 실마리 |

서버 뼈대·전송·데이터 연결은 완성돼 있고 도구 본문만 채웁니다.
**여기서부터는 Claude와 같이 짭니다** — 알고리즘은 어제 직접 짰고, 지금은 연결입니다.

**Step 2 — 에이전트에게 지시 한 문장을 줍니다**

에이전트가 도구를 줄줄이 호출해 리포트를 씁니다. 그리고 **AI가 원인을 지목합니다.**

> `WO-2026-0801` — 냉각 계통 정기점검, **"부품 입고 지연으로 보류. 재개 일자 미정"**

내 알고리즘이 이상을 잡고, AI가 정비 이력에서 원인을 찾아냅니다.

**산출물**: MCP 도구 2개 · AI가 쓴 진단 리포트

### 이론 (20분) — 되돌릴 수 있는가

한 문장에 네 가지 일이 들어 있으면 어디서 틀렸는지 알 수 없습니다.
그래서 셋으로 쪼갭니다 — **감지 · 진단 · 조치.**

그리고 제어 권한이 열립니다. 어제까지 화면에 「잠김」으로 보이던 통로 네 개가
이 시점에 실제로 열립니다.

| 명령 | 되돌릴 수 있나 | 그래서 |
|---|---|---|
| `set_equipment_speed` (감속) | 되돌릴 수 있음 | **자동 실행** |
| `ack_alarm` | 되돌릴 수 있음 | 자동 실행 |
| `stop_equipment` (정지) | **못 되돌림** | **사람 승인** |
| `dispatch_robot` (로봇 파견) | **못 되돌림** | **사람 승인** |

이 선을 `hitl.py` 에서 직접 긋습니다. **모르는 명령은 안전한 쪽으로** — 물어봅니다.

### §2 (70분) — 폐루프 닫기

에이전트 세 개를 채웁니다. 오케스트레이터와 실행 루프는 완성돼 있습니다.

```
감지 → 진단 → 조치 → 승인 → 실행 → 다시 감지
```

공장에 드리프트가 주입되고, 화면에서 이 순서가 실제로 일어납니다.

| 걸음 | 실제로 일어나는 것 |
|---|---|
| 감지 | 온도 드리프트 검출 |
| 진단 | AI가 `WO-2026-0801` 을 근거로 원인 지목 |
| 조치 | **감속 실행** — 약 1,450 → 1,150 rpm (승인 없이 자동) |
| 승인 | **로봇 파견은 화면이 멈추고 묻습니다** |
| 실행 | 승인 → **AMR이 EQ-03 로 이동 시작** |
| 재인지 | 온도가 실제로 내려감 — 루프가 닫힘 |

**감속하면 온도가 내려가는 것은 우연이 아닙니다.** 시뮬레이터에서 온도가 rpm의 함수라
`temp = 24℃ + 16.7 × (rpm/1000)^1.4` 로 물리적으로 결합돼 있습니다.
이 결합이 없으면 「행동 → 다시 인지」가 닫히지 않습니다.

**마지막 장면은 슬라이드가 아니라 각자의 화면입니다.**

**산출물**: 에이전트 3개 · 폐루프 실행 기록 · 감사 로그

### 닫기 (10분)

*"다 됐습니다. 그런데 이건 전부 소프트웨어입니다."*
— 다음 세션(PLC·실물 제어)으로 넘기는 문장입니다.

## 4. 실습 환경

| 무엇 | 내용 |
|---|---|
| 가상 공장 | CNC 6대(EQ-01~06) + AMR 2대. 1인 1개, 서로 격리 |
| 센서 데이터 | 7일치 CSV 60,480행 — 이상 3종이 심어져 있음 |
| 실시간 스트림 | 1초 주기 · 가상 시계로 4시간 드리프트를 강의 시간 안에 재현 |
| 제어 API | 4종 — 3일차 오후에 개방 |
| LLM | 서버가 중계 (개인 키 불필요) |

**가상 시계에 대하여** — 라이브 시연에서 드리프트의 기울기를 키우지 않습니다.
샘플당 상승폭이 커지면 2일차의 "드리프트는 미탐된다"와 모순되기 때문입니다.
대신 1분 간격 샘플을 그대로 둔 채 더 빨리 내보냅니다.
샘플당 상승폭이 나눠 주는 CSV와 **동일하게 유지**됩니다(실측 0.008353 vs 0.008333℃).

## 5. 수료 후 얻게 될 변화

- **알고리즘을 직접 짤 수 있다** — 라이브러리 없이 이동 윈도 z-score를 구현하고,
  표본표준편차·0으로 나누기·결측 처리를 스스로 다룹니다.
- **숫자로 완료를 정의할 수 있다** — "정확도 95%"가 왜 위험한지 몸으로 압니다.
  정탐과 오탐이 맞바뀌는 지점을 직접 재 봤기 때문입니다.
- **내 코드를 AI의 도구로 내놓을 수 있다** — MCP로 함수를 노출하고,
  에이전트가 그것을 호출해 판단하게 만듭니다.
- **AI에게 무엇까지 맡길지 선을 그을 수 있다** — 되돌릴 수 있는 행동과 없는 행동을 나누고,
  승인 관문을 코드로 강제합니다.
- **AI가 내놓은 것을 판정할 수 있다** — AI 구현과 내 구현을 나란히 놓고
  "어느 쪽이 낫나, 왜"에 답할 수 있습니다.
