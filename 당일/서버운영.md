## 0. 30초 개념 — 학생은 어떻게 접속하나

유튜브를 볼 때 내 컴퓨터에 유튜브가 설치돼 있지 않듯, 학생 컴퓨터에도 **아무것도 설치하지 않습니다.**
서버 한 대가 "강의실 안의 작은 웹사이트"가 되고, 학생은 **크롬 주소창에 주소를 치기만** 합니다.

```
   서버 1대 (강사 PC 또는 클라우드)
     └ 공장 39개가 이 안에 들어 있음 (학생 1인 1개. 팀은 쓰지 않는다)
        └ 학생은 자기 주소로 접속 → 자기 공장 하나만 보임
           http://<서버주소>:8000/view?tenant=S07   ← 내번호.py 가 찍어 준다
```

데이터베이스(Supabase)는 인터넷 위에 있어서 **서버가 어디서 돌든 그대로 공유**됩니다.
그래서 로컬↔클라우드 전환에 DB 작업은 없습니다.

> ⚠️ **서버는 반드시 한 곳에서만.** 로컬과 클라우드를 동시에 켜면 두 시뮬레이터가
> 같은 DB에 이중으로 써서 공장 데이터가 꼬입니다. 전환 = "한쪽 끄고 → 다른 쪽 켜기".

## 1. 로컬로 띄우기 (기본)

```
백스테이지\시뮬레이터\시작.bat   더블클릭
```

- 서버가 뜨고 브라우저 2개가 자동으로 열립니다 (강사 콘솔 · 2D 공장 화면)
- 배속 ×60, **개인 공장 39개**가 전부 기본값으로 뜹니다 — **추가 설정 없음**
- 창에 **강사 PC의 IP**가 표시됩니다. 이게 학생이 접속할 주소입니다
- **이 창을 닫으면 서버가 꺼집니다.** 수업 내내 켜 두세요
- 강사 콘솔 토큰: `백스테이지\시뮬레이터\.env` 의 `INSTRUCTOR_TOKEN`

### 로컬이 성립하려면 — 강의장 네트워크 3조건

| 조건 | 확인 방법 | 안 되면 |
|---|---|---|
| ① 학생·강사가 **같은 와이파이** | 학생 1명에게 주소 쳐보게 함 | 강의장 전용 와이파이 안내 |
| ② 공유기 **AP 격리(기기 간 통신 차단) 꺼짐** | 학생 접속이 전원 실패하면 이것 | **강의장 관리자에게 확인 요청** → 안 되면 클라우드로 |
| ③ 강사 PC 방화벽 **8000 인바운드 허용** | 첫 실행 때 Windows 팝업에서 "허용" | 제어판 방화벽에서 수동 허용 |

②번이 가장 위험합니다 — 학교·공용 와이파이는 보안상 켜 둔 경우가 많고, 켜져 있으면
**39명 전원이 접속 불가**입니다. **D-7에 반드시 확인하세요.**

## 2. 클라우드로 띄우기 (보험 · 이미 배포돼 있음)

강의장 네트워크가 막혀도 학생이 **LTE 포함 아무 인터넷으로** 접속할 수 있습니다.
위 3조건이 전부 사라집니다.

| 항목 | 값 |
|---|---|
| 인스턴스 | `knu-factory` (GCP, 서울 asia-northeast3-a, e2-small) |
| 주소 | **http://34.64.94.16:8000** |
| 학생 화면 | `http://34.64.94.16:8000/view?tenant=S01` |
| 강사 콘솔 | `http://34.64.94.16:8000/console` |
| 비용 | 켜져 있을 때만 과금 (월 환산 2만원대, $300 크레딧 사용 중) |

### 켜기 / 끄기 — **평소에는 꺼 둡니다**

```bash
# 켜기 (약 1분 뒤 접속 가능)
gcloud compute instances start knu-factory --zone=asia-northeast3-a

# 끄기 (수업 끝나면 반드시)
gcloud compute instances stop knu-factory --zone=asia-northeast3-a

# 상태·헬스 확인
bash 백스테이지/시뮬레이터/tools/cloud_deploy.sh --status
```

VM 안의 서버는 systemd 로 등록돼 있어 **VM 이 켜지면 자동으로 뜹니다.** 따로 실행할 것 없습니다.

### 처음부터 다시 만들어야 한다면

```bash
bash 백스테이지/시뮬레이터/tools/cloud_deploy.sh          # 생성~기동 전부
bash 백스테이지/시뮬레이터/tools/cloud_deploy.sh --destroy # 특강 후 정리
```
전제: `gcloud auth login` 완료 + `gcloud config set project <프로젝트ID>`.
**특강이 끝나면 `--destroy` 를 꼭 실행하세요** — 고정 IP는 안 써도 과금됩니다.

## 3. 학생에게 번호를 나눠 주기 (매 수업일 아침)

**나눠 줄 것이 없습니다.** 학생이 `python 내번호.py` 를 돌리면 서버가 안 쓰는 번호를
하나 배정하고 2일차 설정 두 곳까지 자동으로 채웁니다.

강사가 할 일은 **서버 주소를 화면에 띄워 두는 것**뿐입니다.

```bash
cd 백스테이지/시뮬레이터
python tools/자리배정.py              # 누가 몇 번을 가져갔나
python tools/자리배정.py --풀기 S07    # 노트북을 바꿔 온 학생의 옛 번호 회수
python tools/자리배정.py --전부풀기 --예  # 다음 기수에 초기화 (--예 가 없으면 확인을 묻습니다)
```

- 학생이 자기 번호를 잊으면 `python 내번호.py` 를 다시 돌리면 그대로 나옵니다.
- 노트북을 바꿔 왔으면 `python 내번호.py S07` — 기억하는 번호로 되찾습니다.

<details><summary>예비 — 자기배정이 통째로 막혔을 때만</summary>

학생 PC 에서 파이썬이 안 돌거나 네트워크가 막혀 서버에 못 붙는 경우에만 씁니다.

```bash
python tools/키배포표.py                                # 그날 IP 자동 감지
python tools/키배포표.py --base http://34.64.94.16:8000  # 클라우드로 수업할 때
```

⚠️ 배포표에는 진짜 키가 들어 있어 **커밋되지 않습니다**(.gitignore 처리됨)
</details>

## 4. 2일차 오후 준비 (그때만)

```bash
cd 백스테이지/시뮬레이터

python tools/제어개방.py                          # 제어 개방 + 배속 ×120
python tools/제어개방.py --inject-all --stagger 2  # ★ 39명 전원에게 주입 (수업 중엔 이것)
python tools/제어개방.py --inject S07              # 한 사람만 (개별 대응)
python tools/제어개방.py --status                  # 지금 상태·경고 확인
python tools/제어개방.py --end                     # 끝나면 제어 잠금 상태로 되돌림
```

**진단 호출은 돈이 나갑니다.** 얼마나 나갔는지 이렇게 봅니다.

```bash
curl -H "X-Instructor-Token: <토큰>" http://127.0.0.1:8000/api/v1/diagnose/usage
```

번호별 호출 횟수·합계·살아 있는 키 수가 나옵니다.
한 사람이 유독 많으면 그 학생 루프가 같은 설비를 반복 진단하고 있는 것입니다
(서버가 분당 12회에서 막고 그 이유를 학생 화면에 말해 줍니다).

> ⚠️ **`--stagger 2` 를 빼지 마세요.** 39명에게 동시에 넣으면 감지도 동시에 몰려
> 진단 호출이 한꺼번에 나갑니다. 2초씩 벌리면 중앙 3.8초, 빼면 중앙 15.8초까지 늘어납니다.

> ⚠️ **클라우드로 수업한다면 매번 `--base` 를 붙이세요.**
> `python tools/제어개방.py --base http://34.64.94.16:8000`
> 안 붙이면 로컬(127.0.0.1)에 대고 실행돼서 **클라우드 쪽 제어가 안 열립니다.**
> 명령이 어느 서버를 향하는지 실행 첫 줄에 `대상 …` 으로 표시되니 확인하세요.

강사 콘솔 화면의 버튼으로도 같은 일을 할 수 있습니다.
**주입 → 감지까지 1~3분** 걸립니다. 학생 화면이 그동안 조용한 것이 정상이니,
주입한 뒤에 "지금부터 1~3분은 아무 일도 안 일어나는 게 맞습니다"라고 미리 말해 두세요.

> ### ★ 전원이 `loop.py` 를 돌린 것을 확인한 **뒤에** 주입하세요
>
> 주입은 가상 5시간짜리라 **배속 x120 에서 실제 150초면 끝납니다**(x60 은 300초).
> 끝나면 온도가 5초 만에 원래대로 돌아갑니다.
> **먼저 주입하고 학생이 나중에 돌리면 이미 끝나 있어서 영영 못 봅니다** —
> 화면에 「감지 이상 없음」만 찍히고 학생은 자기 코드 탓이라고 생각합니다.
> 늦게 온 학생 한 명은 `python tools/제어개방.py --inject S07` 로 따로 넣어 주세요.

## 5. 문제가 생기면

| 증상 | 원인 | 해결 |
|---|---|---|
| 학생 **전원**이 접속 안 됨 | AP 격리 / 방화벽 | 위 1번 3조건 확인 → 안 되면 **클라우드로 전환**(로컬 창 닫고 → VM start → 칠판에 새 주소, 학생은 `python 내번호.py --서버 http://34.64.94.16:8000`) |
| 학생 **일부**만 접속 안 됨 | 그 학생이 다른 와이파이 / 주소 오타 | 와이파이 확인 → `python 내번호.py` 가 찍어 준 주소 그대로인지 |
| 화면은 뜨는데 숫자가 안 변함 | 폴링 문제 or 서버 정지 | 서버 창 살아 있는지 → `/api/v1/health` 가 `ok` 인지 |
| "네임스페이스 없음" | 번호 오타 | 대문자 확인 (`S07` O, `s07` X) · `python 내번호.py` 재실행 |
| 서버가 죽음 | — | 로컬: 시작.bat 다시 실행 / 클라우드: `sudo systemctl restart factory` (자동 재시작되므로 대개 불필요) |
| 2일차 인데 제어가 안 됨 | 제어 개방 안 함 | `python tools/제어개방.py` 실행 |
| 감지가 안 됨 | 주입 안 함 · 대기 중 · **주입이 이미 끝남** | `--status` 로 진행 중 주입 확인 → 0건이면 다시 주입. 1~3분은 정상 대기 |

**전체가 정상인지 한 번에 확인:**
```bash
cd 백스테이지
python 리허설.py --token <강사토큰> --부하
# 클라우드 대상이면: --base-url http://34.64.94.16:8000 추가
```
이틀 수업을 사람 없이 통째로 재생해 **73항목**을 확인합니다(**약 11분**).
**D-7 에 강의장에서 1회 필수.**

이 리허설은 학생이 실행하는 것을 **학생 환경 그대로**(cp949, UTF8 강제 없음) 돌립니다.
학생 PC 에서만 나는 인코딩 결함이 여기서 걸립니다.

`--부하` 는 39명 동시 진단을 **실제 모델로** 부릅니다 — **비용이 납니다.**
빼면 나머지 71항목만 돌고 그 2항목은 「건너뜀」으로 남습니다.

시작할 때 **앞선 실행이 남긴 상태(제어 개방·배속 120·주입)를 스스로 되돌리고**
무엇을 되돌렸는지 알려 줍니다. 지난 실행 찌꺼기 때문에 실패가 나지 않습니다.

**학생에게 줄 저장소도 여기서 뽑습니다:**
```bash
cd 백스테이지
python 배포본만들기.py --검증
```
손으로 만들어 두면 이쪽 구조가 바뀌었을 때 저쪽이 안 따라옵니다. 실제로 한 번 어긋났습니다.
`--검증` 은 뽑은 배포본을 학생 조건으로 **실제로 돌려** 24항목을 확인합니다.
비밀정보가 섞였는지도 매번 훑습니다.

## 6. D-7 강의장 점검 체크리스트

- [ ] 강의장 와이파이에서 **AP 격리 꺼져 있는지** (관리자 확인) — 막히면 클라우드로 확정
- [ ] 강사 PC 방화벽 8000 인바운드 허용 · Supabase 5432 아웃바운드 열림
- [ ] 학생 단말 1대로 실제 접속 (로컬 주소 / 클라우드 주소 둘 다)
- [ ] **`리허설.py --token <토큰> --부하`** 1회 — **73항목 전부 통과·약 11분.**
      39명 동시 진단까지 포함되므로 이것 한 번이면 됩니다(그냥 `리허설.py` 를 따로 돌릴 필요 없음).
      `--부하` 는 실제 모델을 39번 부르므로 **비용이 납니다.** 39/39 성공 · 429 0건 · WO 인용 39/39
- [ ] **`배포본만들기.py --검증`** — 학생에게 줄 저장소를 뽑고 학생 조건에서 확인 (24항목)
- [ ] 39대 동시 렌더 부하 재측정 (지금 수치는 제작 PC 기준)
- [ ] 배속 ×60 으로 드리프트 끝까지 돌려보기 (62→64℃, 80℃ 미도달)
- [ ] `python tools/자리배정.py --전부풀기 --예` (**1일차 아침에만** — 2일차 아침에 하면 39명이 어제 공장을 잃습니다)

## 7. 최후의 대비 — 강의장이 우리 포트를 통째로 막았을 때

로컬도 클라우드도 안 되는 최악의 경우를 위한 경로가 **이미 준비돼 있습니다.**
학생이 우리 API 서버 대신 **Supabase 를 직접 폴링**하는 방식입니다.

```bash
cd 백스테이지/시뮬레이터
python tools/fallback/state_updater.py          # API 서버 없이 상태만 계속 써 넣는다
```

학생에게는 `web/fallback/index.html` 을 열게 합니다(파일을 그대로 줘도 됩니다).
2D 공장 화면 대신 표 형태 대시보드가 갱신됩니다.

| 되는 것 | 안 되는 것 |
|---|---|
| 1일차 §1 — 값이 바뀌는 것을 눈으로 보기 | 2일차 제어·폐루프 (제어 API 가 필요합니다) |

> **이건 1일차를 살리는 장치입니다.** 2일차까지 이 상태면 클라우드 전환이 답입니다.
> D-7 점검에서 Supabase 5432 아웃바운드가 열려 있는지 반드시 확인하세요.

## 8. 보안 메모

- `.env` 는 커밋 금지 (`.gitignore` 처리됨)
- `INSTRUCTOR_TOKEN` = 고장 주입·제어 개방·초기화 권한. **학생에게 노출 금지**
- `access_key` = 학생별 제어 키. 본인에게만
- **제작 중 쓴 DB 비밀번호·API 키·강사 토큰은 저장소 공개 전에 교체할 것**
  (Supabase 대시보드 → Settings → Database / API 에서 회전 후 `.env` 만 수정)
