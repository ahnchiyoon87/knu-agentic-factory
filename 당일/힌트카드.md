## 힌트 1 — 실습 시작 15분 뒤 전체 공개 (TODO 1 을 못 넘는 학생용)

막히는 곳은 대부분 **"지금 값을 통계에 넣느냐"** 와 **슬라이싱 범위**입니다.

- 통계는 **지금 값 바로 앞** W개로만 냅니다. 지금 값을 넣으면 튀는 값이 자기 평균을 끌어올려 자기를 숨깁니다
- `values[i - window:i]` — `i` 는 포함되지 않습니다. 파이썬 슬라이싱은 뒤끝을 뺍니다
- 앞이 모자라면(`i < window`) 판단할 수 없으므로 `None` 을 돌려줍니다
- 표본 표준편차는 `(개수 - 1)` 로 나눕니다

```python
seg = values[i - window:i]
mean = sum(seg) / len(seg)
var  = sum((x - mean) ** 2 for x in seg) / (len(seg) - 1)
```

## 힌트 2 — 실습 시작 25분 뒤 (TODO 2 · 0으로 나누기에서 멈춘 학생용)

`ZeroDivisionError` 가 나면 **표준편차가 0** 인 구간입니다. 최근 W개가 완전히 똑같았다는 뜻이고, 실제 데이터에서 생깁니다.

정답이 하나가 아닙니다. 다음 중 하나를 고르고 **왜 그런지 말할 수 있으면** 됩니다.

| 선택 | 뜻 |
|---|---|
| `False` 를 돌려준다 | 판단 불가 구간은 알람을 안 울린다 |
| 값이 평균과 다르면 `True` | 계속 같던 값이 갑자기 달라졌으니 이상이다 |
| 아주 작은 수를 더해 나눈다 | 편법. 왜 위험한지 설명할 수 있어야 함 |

z-score 자체는 한 줄입니다.

```python
z = (value - mean) / std
return abs(z) > k
```

## 힌트 3 — 실습 시작 35분 뒤 (TODO 3 · 결측에서 멈춘 학생용)

`TypeError: unsupported operand type(s)` 가 나면 **`None` 을 계산에 넣은 것**입니다.
EQ-01 에 2시간(120개) 짜리 결측이 들어 있습니다.

선택지와 **각각의 대가**입니다. 이게 Step 3 토론의 재료입니다.

| 방침 | 대가 |
|---|---|
| 그냥 둔다 (그 구간은 판정 안 함) | 결측 자체는 못 잡는다 |
| 직전 값으로 메운다 (ffill) | 2시간 내내 같은 값 → **표준편차가 0** 이 되고, 값이 돌아오는 순간 **없던 이상이 하나 생긴다** |
| 앞뒤 평균으로 보간 | 없는 값을 지어낸다. 그 구간 z-score 는 거짓말이 된다 |
| 결측 자체를 이상으로 본다 | 센서 고장을 잡는다. 다만 **뼈대상 값으로만 표현할 수 있다** — 아래 참조 |

> **네 번째를 고른 학생에게 짚어 줄 것** — `handle_missing()` 은 값만 돌려주고,
> `detect()` 는 값이 없는 자리를 무조건 「판정 안 함」으로 넘깁니다.
> 그래서 이 방침을 쓰려면 결측을 **정상에서 크게 벗어난 값으로 바꿔** z-score 가
> 스스로 튀게 만들어야 합니다. 그게 정직한 방법인지 아닌지가 Step 3 의 좋은 논점입니다.
> (학생 `detect.py` 의 `handle_missing` 주석에도 같은 설명이 있습니다)

값이 없는지 확인은 `if v is None:` 입니다. `== None` 이 아닙니다.

## 참고 — Step 3 비교 시 짚을 것

참고 구현(`1일차/실습/정답/detect_answer.py`)은 **"메우지 않고 그대로 둔다"** 를 골랐습니다. 그래서 센서 결측 121개 중 **0개**를 잡습니다.

이것이 유일한 정답이 아닙니다. **학생이 "결측 자체를 이상으로 본다"를 골라 3종을 다 잡았다면 그쪽이 더 나은 선택**입니다. 시연에서 AI 가 내놓는 구현은 대개 `ffill` 이나 `dropna` 를 쓰는데, 위 표의 두 번째 줄(없던 이상이 생김)을 짚어 주면 "AI가 내놓은 결과물을 판정할 수 있는 사람"이라는 Step 3 의 메시지로 이어집니다.
