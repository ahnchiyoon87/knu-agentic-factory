# 교육 실라버스 · 4시간 과정

# 피지컬 AI 시대의 Agentic AI 실습 ②
# 판단하고, 움직이게 한다
— 내가 짠 코드를 AI의 손에 쥐여주고, 설비를 실제로 움직인다 —

**감지 → 진단 → 조치 → 승인 → 실행 → 다시 감지. 폐루프를 직접 닫는다**

총 4시간 (240분) · 단일 세션
대상: 컴퓨터공학과 1~4학년 | 진행 방식: 전원 개인 실습 | 준비물: 개인 노트북 (전날 환경 그대로)

> **저희가 맡은 이틀 중 마지막 날입니다.** 앞 세션에서 로봇 명세를 글로 썼고, 어제 이상감지를 손으로 짰습니다.
> 오늘은 그 코드를 AI가 부르게 만들고, **화면 속 설비가 실제로 움직이는 것**까지 갑니다.

## 1. 과정 개요

어제 학생들은 규칙이 어디서 무너지는지를 자기 숫자로 봤습니다.
드리프트는 임계값을 아무리 낮춰도 안 잡혔고, 낮추면 헛알람만 11배가 됐습니다.
그리고 이런 질문을 안고 끝냈습니다 — **"규칙으로 안 되면, 누가 판단하죠?"**

오늘 답합니다. 규칙은 **미리 정한 것만** 봅니다. 정비 이력에 "냉각 점검이 부품 지연으로
보류 중"이라고 적혀 있어도 z-score는 그 문장을 읽지 않습니다. 하지만 AI는 읽습니다.

그래서 오늘은 어제 짠 `detect()` 를 **MCP 도구로 내놓습니다.** 그러면 AI가
"지난주 이상 점검해 줘"라는 한 문장을 듣고 알아서 그 함수를 호출하고,
정비 이력을 조회해 원인을 지목합니다.

거기서 한 걸음 더 갑니다. **제어 권한을 엽니다.** 어제까지 화면에 「잠김」으로만 보이던
통로 네 개가 오늘 열리고, AI가 판단해 설비를 감속시킵니다. 다만 되돌릴 수 없는 행동
— 정지와 로봇 파견 — 은 **사람이 승인해야** 실행됩니다. 그 선을 학생이 직접 코드로 긋습니다.

마지막 장면은 슬라이드가 아닙니다. 학생이 승인을 누르면 **자기 화면의 AMR이 목적지로 움직입니다.**

### 과정 콘셉트

"AI에게 무엇까지 맡길 것인가는 기술 문제가 아니라 **되돌릴 수 있는가**의 문제입니다.
그 선을 그을 줄 아는 사람이 AI를 현장에 놓을 수 있습니다."

### 이 과정만의 차별점

- **내가 짠 코드를 AI가 부릅니다** — 남의 라이브러리를 붙이는 게 아니라 어제 자기 손으로
  만든 함수가 그대로 도구가 됩니다. "내 알고리즘을 AI가 쓴다"는 경험이 오늘의 축입니다.
- **AI가 근거를 대고 원인을 지목합니다** — 추측이 아니라 정비 이력의 작업지시 번호를
  인용합니다. 실측으로 39명 전원이 같은 근거(`WO-2026-0801`)를 집어냈습니다.
- **되돌릴 수 있는 행동과 없는 행동을 나눕니다** — 감속은 자동, 정지와 로봇 파견은 사람 승인.
  이 규칙을 `hitl.py` 에 학생이 직접 씁니다. 모르는 명령은 안전한 쪽으로 — 물어봅니다.
- **진짜로 움직입니다** — 감속 명령에 온도가 실제로 내려갑니다. 시뮬레이터에서 온도가
  회전수의 함수로 결합돼 있어, 「행동 → 다시 인지」가 물리적으로 닫힙니다.

### 어제와 오늘 — AI를 쓰는 방식이 반대입니다

| | 2일차 (어제) | 3일차 (오늘) |
|---|---|---|
| 손코딩 | **25분** — 함수 3개를 직접 | **거의 없음** — 뼈대의 ★ 자리만 |
| AI 사용 | 마지막에 비교용으로만 | 처음부터 끝까지 (AI가 판단하고 움직인다) |
| 학생이 하는 일 | 알고리즘을 만든다 | **AI가 만든 것을 판정한다** |
| 배우는 것 | 규칙의 한계 | 판단의 위임과 그 경계 |

어제 AI를 막은 이유가 오늘 드러납니다. **직접 만들어 본 사람만이
AI가 내놓은 진단을 보고 "이건 맞다 / 이건 아니다"를 말할 수 있습니다.**

## 3. 모듈별 상세

## 도입 (10분) — 어제 만든 자를 회수한다

**목표**: 어제 남긴 질문에 답하고, 오늘 무엇을 하는지 그림을 갖는다.

### 다루는 내용

- 어제 학생들은 자를 하나 만들었습니다. 6만 행을 훑고 진동 스파이크는 잡았지만
  온도 드리프트와 센서 결측은 놓쳤습니다.
- **왜 놓쳤나** — 규칙은 미리 정한 것만 봅니다. "평균에서 3배 벗어나면 이상"이라고
  정해 두면 그것만 봅니다. 정비 이력에 원인이 적혀 있어도 읽지 않습니다.
- 오늘은 세 도막입니다 — **도구로 내놓고 → 판단을 맡기고 → 움직이게 한다.**

## M1 (20분) — 환각 · 에이전트 · ReAct

**목표**: AI에게 그냥 물어보면 왜 안 되는지 보고, 에이전트가 무엇으로 이루어지는지 안다.

**체험 키워드**: 환각 · 도구 · 관측 · 추론-행동 루프

### 다루는 내용

- **그냥 물어보면 이렇게 됩니다** — 데이터를 주지 않고 "EQ-03에 무슨 문제가 있나"라고
  물으면 그럴듯한 답이 나옵니다. 그런데 근거가 없습니다. 지어낸 것입니다.
- **눈을 달아 줘도 손이 없습니다** — 데이터를 읽게 해 줘도 거기서 끝입니다.
  설비를 멈추거나 로봇을 보낼 수 없습니다.
- **에이전트는 넷으로 이루어집니다** — **뇌(LLM)** 판단을 맡고, **도구** 조회하고 제어하고,
  **루프** 결과를 보고 다시 판단하고, **자율성** 다음에 무엇을 할지 자기가 정합니다.
- **챗봇도 코파일럿도 아닙니다.** 차이는 하나뿐입니다 — 다음에 무엇을 할지 누가 정하는가.
  챗봇은 안내원, 코파일럿은 보조원, 에이전트는 **야간 당직자**입니다. 물어보지 않아도 순찰을 돕니다.
- **ReAct** — Reasoning(추론)과 Acting(행동)을 번갈아 합니다. 한 번에 답을 내지 않고
  한 걸음 가고, 결과를 보고, 다음을 정합니다. 그래서 예상과 다른 것이 나와도 방향을 바꿀 수 있습니다.
  새벽 3시 EQ-03에 돌리면 **아홉 걸음**이 됩니다 — 온도 조회 → 정비 이력 조회 → 속도 조절.

## M2 (15분) — 오케스트레이터 패턴 · MCP

**목표**: 하나에게 다 시키면 왜 안 되는지 알고, 도구를 쥐여주는 표준이 무엇인지 안다.

**체험 키워드**: 역할 분해 · MCP · 도구 스키마

### 다루는 내용

- **하나에게 다 시키면 이렇게 됩니다** — 한 에이전트에게 감지·진단·조치를 다 맡기면
  어디서 틀렸는지 알 수 없습니다. 틀린 진단으로 설비를 멈춰도 원인을 못 찾습니다.
- **패턴은 다섯입니다** — 프롬프트 체이닝(쪼개서 줄줄이 잇는다) · 라우팅(성격 보고 알맞은 곳으로) ·
  병렬 처리(상관없는 일은 동시에) · **총괄과 담당**(총괄이 나누고 담당이 처리한다) ·
  검증과 되짚기(검사하는 쪽을 따로 둔다).
  오늘 손으로 짜는 것은 **총괄과 담당**입니다.
- **MCP** — AI에게 외부 프로그램을 손으로 달아 주는 표준입니다.
  함수 하나를 MCP 도구로 등록하면 AI가 그 이름과 인자를 보고 스스로 호출합니다.
- **오늘 만드는 도구는 두 개** — `detect_anomaly`(어제 짠 코드) · `query_equipment`(설비 조회).

## M3 (55분) — 내 코드를 MCP 도구로 내놓기 (실습 1)

**목표**: 어제 짠 함수를 AI가 부를 수 있는 도구로 만들고, AI가 근거를 대며 원인을 지목하게 한다.

**체험 키워드**: MCP 서버 · 도구 스키마 · 정비 이력 · 근거 있는 진단

### 다루는 내용

`mcp_server.py` 에 채울 자리가 두 곳 있습니다. 서버 뼈대·전송·데이터 연결은 완성돼 있습니다.

| 도구 | 무엇을 하나 | 핵심 |
|---|---|---|
| `detect_anomaly` | 어제 짠 `detect()` 로 7일치를 훑는다 | **내 코드를 그대로 불러 씁니다** |
| `query_equipment` | 최근 센서 요약 + **정비 이력** 조회 | 정비 이력의 `note` 가 진단의 실마리 |

- **채울 것은 도구 본문 두 자리뿐입니다.** 알고리즘은 어제 학생이 짰고,
  지금 하는 건 연결입니다. 막히면 `점검.py --힌트` → `--열기` 로 채우고 넘어갑니다.
- 도구가 돌려주는 것은 **에이전트가 읽을 수 있는 형태**여야 합니다.
  이상이 몇 건인지, 어느 시각인지, 정비 이력에 무엇이 적혀 있는지.
- 설정은 어제 `내번호.py` 가 이미 채워 뒀습니다. 손으로 옮겨 적을 것이 없습니다.

**Step 2 — 에이전트에게 지시 한 문장을 줍니다.**

에이전트가 도구를 줄줄이 호출해 리포트를 씁니다. 그리고 **AI가 원인을 지목합니다.**

> `WO-2026-0801` — 냉각 계통 정기점검, **"부품 입고 지연으로 보류. 재개 일자 미정"**

내 알고리즘이 이상을 잡고, AI가 정비 이력에서 원인을 찾아냅니다.
어제 z-score가 못 읽던 그 문장을 오늘 AI가 읽습니다.

### 실습

1. `mcp_server.py` 의 두 자리를 채운다. 막히면 `점검.py --힌트 1`.
2. `python mcp_server.py --check` — 두 도구의 응답에 `WO-2026-0801` 이 보이면 완성이다.
3. 에이전트에게 지시 한 문장을 주고, 나온 리포트를 읽는다.
4. 막히면 `점검.py` — 연결 상태부터 도구 응답 모양까지 순서대로 짚어 준다.

**산출물**: MCP 도구 2개 · **AI가 근거를 인용해 쓴 진단 리포트**

## M4 (20분) — 되돌릴 수 있는가

**목표**: 제어 권한이 열리는 것을 보고, AI에게 무엇까지 맡길지 선을 긋는 기준을 얻는다.

**체험 키워드**: 제어 API 4종 · 되돌릴 수 있는 행동 · HITL(Human-in-the-Loop)

### 다루는 내용

- **여기까지는 제안만 했습니다.** AI가 "감속하세요"라고 리포트에 썼을 뿐 아무것도 안 움직였습니다.
- **한 문장에 네 가지 일이 들어 있습니다** — "온도가 오르면 원인을 찾아 감속하고 정비를 부르라"는
  지시에는 감지·진단·조치·통보가 섞여 있습니다. 그래서 셋으로 쪼갭니다.
- **지금 제어 권한이 열립니다.** 어제까지 화면에 「잠김」으로 보이던 통로 네 개가
  이 시점에 실제로 열립니다. 강사가 그 자리에서 엽니다 — *"어제까지는 못 움직였다"* 가 사실이어야 합니다.

| 명령 | 되돌릴 수 있나 | 그래서 |
|---|---|---|
| `set_equipment_speed` (감속) | 되돌릴 수 있음 | **자동 실행** |
| `ack_alarm` (알람 확인) | 되돌릴 수 있음 | 자동 실행 |
| `stop_equipment` (정지) | **못 되돌림** — 라인이 선다 | **사람 승인** |
| `dispatch_robot` (로봇 파견) | **못 되돌림** — 로봇이 이미 움직였다 | **사람 승인** |

- **갈림선은 기술이 아니라 되돌릴 수 있는가입니다.** 이 기준은 웹앱이든 로봇이든 같습니다.
- **모르는 명령은 안전한 쪽으로** — 목록에 없는 명령이 오면 물어봅니다.
  학생이 `hitl.py` 에 이 규칙을 직접 씁니다.
- AI에게 다 맡기는 것도, 사람이 다 하는 것도 아닙니다. **고리 안에 사람이 한 자리** 있습니다.

## M5 (70분) — 폐루프 닫기 (실습 2)

**목표**: 감지부터 실행까지 스스로 도는 루프를 완성하고, 자기 화면에서 설비가 움직이는 것을 본다.

**체험 키워드**: 오케스트레이터 · 담당 셋 · 승인 관문 · 행동 → 다시 인지

### 다루는 내용

에이전트 세 개를 채웁니다. 오케스트레이터와 실행 루프는 완성돼 있습니다.

| 담당 | 하는 일 |
|---|---|
| 감지 | 최근 구간을 보고 드리프트가 있는지 판정한다 |
| 진단 | 센서와 정비 이력을 근거로 원인을 추정한다 |
| 조치 | 어떤 명령을 낼지 정하고, 승인이 필요한지 판단한다 |

**폐루프는 일곱 걸음입니다.**

```
감지 → 진단 → 조치 결정 → 승인 관문 → 실행 → 다시 감지 → (해결될 때까지)
```

강사가 전원의 공장에 드리프트를 주입합니다. **감지까지 1~3분 걸립니다.**
그동안 화면이 조용한 것이 정상이라고 미리 말해 둡니다.

그리고 학생 화면에서 이 순서가 실제로 일어납니다.

| 걸음 | 화면에서 보이는 것 |
|---|---|
| 감지 | 온도 드리프트 검출 |
| 진단 | AI가 `WO-2026-0801` 을 근거로 원인 지목 |
| 조치 | **감속 실행** — 회전수가 내려간다 (승인 없이 자동) |
| 승인 | **로봇 파견에서 화면이 멈추고 묻는다** — 되돌릴 수 없는 행동입니다 |
| 실행 | 승인 → **AMR이 EQ-03 로 이동 시작** |
| 재인지 | 온도가 실제로 내려간다 — 루프가 닫힌다 |

**감속하면 온도가 내려가는 것은 우연이 아닙니다.** 시뮬레이터에서 온도가 회전수의 함수로
결합돼 있습니다(`temp = 24℃ + 16.7 × (rpm/1000)^1.4`). 이 결합이 없으면
「행동 → 다시 인지」가 닫히지 않고, 폐루프는 말뿐인 것이 됩니다.

### 실습

1. `python loop.py --check` 로 내 공장에 붙는지 확인한다.
2. 에이전트 세 곳을 채운다. 막히면 `loop.py --열기 1` (1 감지 · 2 진단 · 3 조치).
3. `python loop.py` 를 돌린다. **전원이 돌린 것을 확인한 뒤 강사가 주입한다.**
4. 화면에서 세 가지를 본다 — 감속이 실행되는 것, 승인을 묻는 것, AMR이 움직이는 것.
5. 정해진 시각까지 못 채운 학생은 `python loop.py --열기 전부` — 막힌 자리를 채우고 바로 간다.

**산출물**: 에이전트 3개 · 폐루프 실행 기록 · **움직이는 AMR** · 감사 로그

## 닫기 (10분) — 그런데 이건 전부 소프트웨어입니다

**목표**: 오늘 한 것을 정리하고, 물리 세계로 넘긴다.

- 오늘 세 가지를 했습니다 — 내 코드를 AI의 도구로 내놨고, AI가 근거를 대며 판단했고,
  사람이 승인한 뒤 설비가 실제로 움직였습니다.
- **그런데 이건 전부 소프트웨어입니다.** 화면 속 설비가 움직인 것이지 쇳덩이가 움직인 건 아닙니다.
  실물에서는 정지 거리, 안전 펜스, E-Stop, 인증이 붙습니다.
- 다음 세션(PLC·실물 제어)으로 넘기는 문장입니다.

## 정리 (20분) — 템플릿에 두 번째로 채우기

**목표**: 어제 만든 템플릿에 오늘 것을 넣고, **링크 하나로 제출한다.**

- 오늘은 새 용어가 많이 나왔습니다 — MCP · 에이전트 · ReAct · 오케스트레이터 ·
  HITL · 폐루프. 이 중 **안 풀린 것 2~3개**를 카드로 만듭니다.
- 어제와 같은 방식입니다. 「안 보고 설명하면」부터 쓰고, 안 써지면 AI에게 물어 교정받습니다.
- 「코드로는」 칸에는 오늘 실제로 쓴 줄을 붙입니다 — 도구 등록부, 승인 관문, 폐루프 한 바퀴.
- **갤러리 뷰로 바꿔** 이틀치 카드가 제대로 보이는지 확인합니다.
- **링크를 제출합니다.** 그게 수료 조건입니다.

> 이틀치가 한 표에 쌓였습니다. 앞으로 듣는 수업도 여기에 계속 쌓으면 됩니다 —
> 1교시에 만든 그릇을 그렇게 쓰라고 만든 것입니다.

**산출물**: 개념 카드 2~3장 · **제출 링크**

## 4. 실습 환경

| 무엇 | 내용 |
|---|---|
| 가상 공장 | 어제 받은 그 공장 그대로. 번호도 설정도 유지 |
| **제어 API** | **4종. 오늘 오후에 개방** — 어제까지는 잠겨 있었습니다 |
| MCP | SDK 2.x · 로컬 stdio 전송. 막히면 설정 한 줄로 공용 서버 우회 |
| LLM | **서버가 중계합니다.** 학생 PC에 키를 두지 않습니다 |
| 승인 관문 | 학생이 `hitl.py` 에 직접 씁니다. 시뮬레이터가 강제하지 않습니다 |

**LLM 키를 나눠 주지 않는 이유** — 39명에게 키가 나가면 회수가 안 됩니다.
학생은 자기 접속 키로 강사 서버에 붙고, 서버가 대신 모델을 부릅니다.
프롬프트는 서버가 만들지 않습니다 — **학생이 고친 프롬프트가 그대로 쓰입니다.**

## 6. 수료 후 얻게 될 변화

- **내 코드를 AI의 도구로 내놓을 수 있다** — MCP로 함수를 노출하고,
  에이전트가 그것을 스스로 호출하게 만듭니다.
- **AI에게 무엇까지 맡길지 선을 그을 수 있다** — 되돌릴 수 있는 행동과 없는 행동을 나누고,
  승인 관문을 코드로 강제합니다. 이 기준은 웹앱이든 로봇이든 같습니다.
- **AI가 내놓은 판단을 검증할 수 있다** — 근거를 댔는지, 그 근거가 실제 데이터에 있는지 봅니다.
  어제 직접 짜 봤기 때문에 가능합니다.
- **폐루프가 무엇인지 안다** — 행동이 상태를 바꾸고, 바뀐 상태를 다시 인지하는 고리.
  말이 아니라 자기 화면에서 닫히는 것을 봤습니다.
- **피지컬 AI가 소프트웨어와 어디서 갈리는지 안다** — 문법은 같고, 되돌릴 수 없다는 것이 다릅니다.
