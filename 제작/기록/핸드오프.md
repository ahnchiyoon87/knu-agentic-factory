## 서버 — 클라우드 하나뿐

수업도 연습도 **http://34.64.94.16:8000** 하나로 한다. 강의장 와이파이가 기기 간 통신을
막아 학생이 강사 PC 에 붙을 수 없기 때문이다. **강사 PC 에서 서버를 띄우지 않는다.**

- 켜기 `gcloud compute instances start knu-factory --zone=asia-northeast3-a`
- 끄기 (수업 끝나면 반드시) `... instances stop ...`
- VM 안 서버는 systemd 로 자동 기동. **파이썬 venv + requirements.txt** (uv 아님)
- 도구가 향하는 주소는 `시뮬레이터/.env` 의 `BASE_URL` 한 줄로 정해진다 —
  그래서 명령마다 `--base` 를 붙일 필요가 없다. 빠뜨리면 학생 전원이 403 이던 구멍을 없앴다

## 학생 환경 — 파이썬을 설치하지 않는다

`uv` 하나만 깔면 실습 폴더에 파이썬 3.12 와 패키지를 uv 가 갖춘다.
학생이 치는 명령은 앞에 **`uv run`** 이 붙는 것뿐이다 (`uv run 내번호.py`).

- 정의는 `특강/pyproject.toml` · `.python-version` — 배포본에 같이 나간다
- **requirements.txt 는 없다.** 의존성 출처는 pyproject 하나
- **uv 는 학생 실습 폴더에서만 쓴다.** 서버는 손대지 않는다 (환경이 하나뿐이라 바꿀 이유가 없다)

# 4. 핵심 설계

## 진단 중계 — 학생 PC 에 AI 키를 두지 않는다

```
학생 PC ──(내 접속 키)──> 클라우드 서버 ──(OPENAI_API_KEY)──> OpenAI
```

키는 서버 `.env` 에만 있고, 특강이 끝나면 서버만 내리면 된다.
**프롬프트는 서버가 만들지 않는다** — 학생이 고친 프롬프트가 그대로 올라가야 실습이 성립한다.

## 39명이 몰려도 안 터지는 장치

| 겹 | 장치 |
|---|---|
| 1 | 서버→AI **동시 호출 6건 관문** (`DIAGNOSE_CONCURRENCY`) |
| 2 | 학생 1인당 **분당 12회** 제한 (연타 방지) |
| 3 | 리포트당 **AI 호출 6번 상한** (비용 폭주 방지) |
| 4 | 일시 오류 **자동 재시도** · 죽은 키 10분 격리 |
| 5 | **설비별 진단 1회 캐시** — 매 회차 다시 부르던 것이 호출 폭증의 주범이었다 |
| 6 | 주입 시차 `--inject-all --stagger 2` — 빼면 중앙 3.8초가 15.8초까지 늘어난다 |

## 필수 프롬프트 — 이 세 문장이 39/39 를 만든다

`diagnoser.py` 프롬프트에 반드시 들어간다. **가이드에 원문으로 주고 학생이 복사해 넣는다.**

```
① "이 변화는 지금 작아도 계속 오른다."
   → 없으면 "조금 올랐네요, 지켜보죠" 하고 아무 조치도 안 낸다

② "원인이 정비 보류·지연이면 감속과 함께 로봇 파견 요청까지 낼 것.
   파견은 사람이 승인하므로 요청을 망설이지 말 것."
   → 없으면 감속만 하고 끝나서 승인 화면이 안 뜬다

③ "근거(evidence)에는 작업지시 번호를 그대로 인용할 것."
   → 없으면 WO 인용이 약 95% 로 떨어진다. 39명 중 2명이 하이라이트를 놓친다
```

## 이탈 방지 4단계 — 세 랩 전부에 있다

```
점검.py            내 코드를 돌려보고 어디가 왜 틀렸는지만 짚는다 (답은 안 준다)
점검.py --힌트 1    개념
점검.py --힌트 2    의사코드
점검.py --열기 N    ★ 시간이 다 됐을 때만. 막힌 함수 하나만 완성본으로
```

3일차 오후는 `loop.py --열기 1·2·3` (파일을 안 고친다. 옵션을 빼면 내 코드로 돌아온다).
**정답본은 학생에게 같이 나간다** — `--열기` 가 그걸 읽는다. 훔쳐볼 수 있다는 대가보다
3분 막혀 이탈하는 손해가 크다는 판단이다.

# 5. 다시 밟지 말 것

| 함정 | 내용 |
|---|---|
| **cp949 인코딩** | `—` `→` 출력에서 `UnicodeEncodeError` 로 실습이 중간에 죽었다. 리허설은 UTF-8 을 주입해 돌아 안 보였다 — **학생은 그 환경변수가 없다.** 새 진입점을 만들면 인라인 UTF-8 가드를 반드시 넣을 것 |
| **검증 도구가 학생 환경을 잘못 흉내** | 리허설이 학생 코드를 자기 프로세스에서 불러 쓰는데 제작 환경에 `mcp`·`asyncpg` 가 없어 자식 프로세스가 즉사했다. 30초 타임아웃으로만 보여 학생 코드 결함으로 오인했다 |
| **VM 이 옛 상태로 남아 있음** | VM 의 `.env` 가 옛것이라 **OpenAI 키와 진단 설정이 통째로 없었다.** 그대로 수업했으면 3일차가 전부 실패했다. 코드를 push 해도 VM 은 저절로 안 바뀐다 — 수업 전날 `git pull` + 재기동 필수 |
| **접속 키가 커밋에 딸려감** | 수동 테스트로 채워진 `config.json` 이 스테이징에 들어갔다. 커밋 전 `git status` 육안 확인 |
| **문서 치환이 본문까지 번짐** | 슬라이드 문구를 일괄 치환했더니 단축키 표·본문 용어까지 바뀌었다. **장을 지정해서만** 바꿀 것 |
| **pptx 문단 갈아끼우기** | 문단을 통째로 새 런에 넣으면 첫 런의 서식(파란 번호)이 항목 전체로 번진다. **런 구조를 지켜서** 해당 런만 바꿀 것 |
| **머리말 글상자는 폭 고정** | 원래보다 길어지면 옆 글과 겹친다. 대상을 드러내려면 머리말이 아니라 **부제**에 쓸 것 |
