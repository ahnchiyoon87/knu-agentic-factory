## 2. ★ pptx 를 직접 고치지 않는다

**슬라이드는 코드로 만든다.** pptx 는 산출물이라, 손으로 고치면 다음에 뽑을 때 사라진다.

```
build_2일차.py ─┐
build_3일차.py ─┼→ HTML → (레이아웃검사) → PNG → pptx
svgs*.py       ─┤        Playwright 로 그린다
_기준판.css     ─┘
```

| 고칠 것 | 어디를 고치나 |
|---|---|
| 글자·제목·표 | `build_2일차.py` · `build_3일차.py` |
| 도해·아이콘 | `svgs.py`(2일차) · `svgs3.py`(3일차) |
| 색·글꼴·여백 | `_기준판.css` |
| 레이아웃 종류 | `deckkit.py` |

## 3. 한 장은 이렇게 생겼다

`deckkit.py` 가 레이아웃 여덟 개를 준다. 모든 장은 **제목 · 부제 · 본문 · 각주** 네 칸이다.

| 레이아웃 | 쓰는 자리 |
|---|---|
| `cover` | 표지 |
| `sect` | 구간 표지 · 실습 시작 (오른쪽에 이름/시간/할 일) |
| `pic` | 왼쪽 그림 + 오른쪽 문단 — 제일 많이 쓴다 |
| `rail` | 번호 붙은 항목 3~4개 (아이콘 + 굵은 줄 + 회색 부연) |
| `cmp` | 좌우 비교 두 칸 |
| `tbl` | 표 (`키폭=` 으로 첫 열 폭을 줄 수 있다) |
| `words` | 낱말 카드 여러 개 |
| `graph` | 그래프 한 장 |

```python
S.append(D.pic("제목 — 지금 하는 일",
               "부제 — 왜 하는지 한 줄",
               V.그림이름,
               ["본문 문단 1", "본문 문단 2"],
               '각주 — 이 장에서 남길 한 줄'))
```

## 4. 문체 — 이것 때문에 여러 번 다시 썼다

### 지우는 것

- **대구로 맞춘 세 줄** — 같은 길이·같은 어미로 떨어지면 광고 문구가 된다
- **앞 장을 참조하는 말** — 「앞에서 ~했으면 이제」 금지. 그 장 일은 그 장 안에서 끝낸다
- **아직 안 배운 용어** — 뒤에서 만들 것을 앞 장에서 아는 척하지 않는다
- **결과 화면 장의 본문 글** — 「이렇게 됩니다」류는 그림과 각주만
- **훈계** — 「10분을 넘기지 마세요」「부끄러운 일이 아닙니다」

### 바꾸는 것

| 자리 | 규칙 |
|---|---|
| 제목 | 기능 이름이 아니라 **지금 하는 일**. 한 장에 두 가지를 넣지 않는다 |
| 부제 | **왜 하는지** 한 줄. 조작(누른다·친다)은 절대 넣지 않는다 |
| 본문 | 잘게 쪼개지 말고 덩어리로 붙인 뒤 마지막에 결론 |
| 어미 | 「~입니다」로만 떨어지면 기계 같다. 반문·단정을 섞는다 |
| 관점 | 무슨 일이 일어나는지가 아니라 **학생이 얻는 것**으로 |

### ★ 실제로 틀렸던 다섯 — 쓰고 나서 이 표로 자기검열한다

| 함정 | 나쁨 | 좋음 |
|---|---|---|
| 괄호에 부연 눌러 넣기 | (재는 자리가 겉면이 아니라 베어링 안쪽이라 숫자가 이만큼 높습니다) | 온도는 겉면이 아니라 **베어링 안쪽**에서 잽니다. 그래서 숫자가 이렇게 높습니다. |
| 반대로 읽히는 문장 | 한 기계에게 정상인 온도가 **다른 기계에게는 이상**일 수 있습니다 | **「정상」의 기준이 기계마다 다릅니다.** |
| 부정형으로 꼬기 | 정답이 하나가 아닙니다 | **정답이 두 개입니다. 둘 중 하나를 고르세요** |
| 번역투 | **손은 온도로 연습했지만** 채점은 진동에도 태웁니다 | 감시자를 **온도와 진동, 두 데이터에** 돌립니다 |
| 예고편투(AI스러움) | 「이상을 잡는 자를 만든다 / 새벽 3시의 사건 · …」 | 강사가 강의실에서 읽어 자연스러운 말로 |

**자기검열 세 물음** — ①괄호를 열었는가(대개 두 문장으로 나눠야 할 것) ②반대로 읽힐 수 있는가
③읽는 사람에게 지시하고 있는가(지시 대신 이유를).

## 5. 그림과 글이 같은 말을 해야 한다

**자동 검사는 넘침·잘림만 본다. 뜻은 눈으로만 잡힌다.** 실제로 검사를 통과한 채 나온 결함들이다.

| 실제 사례 | 무엇이 문제였나 |
|---|---|
| 3일차 26장 | **다음 장 그림을 미리 써서** 반전이 유출됐다 |
| 2일차 39장 | 화면 **8개**를 그려 놓고 라벨은 「**39개** 화면」 |
| 2일차 19장 | 「부숴도 된다」(안전)에 **저울** — 저울은 오탐·미탐 맞바꿈 전용 |
| 3일차 2장 | 어제 회고 그림이 **옛 판**(「채울 곳 셋」) — 2일차 최종은 「함수 셋 · 빈칸 다섯」 |
| 3일차 30장 | 화살촉이 「감지」 **글자를 뚫었다** |

**지킬 것** — 라벨 숫자 = 그림 개수 · 아이콘 뜻 = 제목 · 다음 장 답 스포일러 금지 ·
다음 날 회고 그림 = 전날 최종판.

## 6. 절대 바꾸면 안 되는 수치 (전부 실측이다)

| 값 | 뜻 |
|---|---|
| **56 ~ 74℃** | 정상 온도는 기계마다 다르다 (회전수의 함수 · **베어링 안쪽** 기준) |
| **80℃** | 알람 임계. 2일차에 **한 번도 안 넘는다** — 그게 11장의 반전이다 |
| **4시간에 2℃** | 드리프트 크기. 「하루 12℃ 상당」 같은 환산은 **금지** |
| **567 · 81 · 97** | 6대·7일 헛울림 567행 = **하루 81번**. **97은 한 대(EQ-03)의 7일치** |
| **60,480행** | 7일치 데이터 (6대 × 7일 × 1분 간격 × 2지표) |
| **45 · 49장** | 장수. 넣거나 빼면 **`강의/<일차>/진행.md` 의 장 번호를 같이 고친다** |

**추측 수치 금지.** 모르면 재 보거나 뺀다 — 근거 없이 쓴 값으로 실제 두 번 틀렸다.

## 7. 고쳤으면 여기까지 돌린다

```bash
cd 제작/덱빌드
uv run build_2일차.py          # 또는 build_3일차.py
uv run 레이아웃검사.py           # 걸리면 문구·좌표를 고친다. 검사를 끄지 않는다
uv run render.py 2일차덱        # PNG 로 그린다
```

**★ 그다음 `제작/산출물/슬라이드/<일차>/*.png` 를 눈으로 본다.**
바꾼 장과 그 앞뒤 장은 반드시. 5절의 결함들은 전부 이 단계에서만 나왔다.

```bash
cd ../빌드도구
uv run 편집pptx.py 2일차        # pptx (PowerPoint 를 먼저 닫는다)
uv run --with playwright 드라이브폴더만들기.py   # 학생에게 줄 zip 까지
```
