## 2. 접속 정보 설정

```bash
cp .env.example .env
```

`.env` 를 열어 채운다. **코드에는 URL·키를 넣지 않는다. 전부 여기서만 읽는다.**

| 키 | 어디서 | 비고 |
|---|---|---|
| `SUPABASE_DB_URL` | Project Settings > Database > Connection string > **Session pooler** | 아래 형식 주의 |
| `SUPABASE_URL` | Project Settings > API > Project URL | 학생 직접 폴링·폴백용 |
| `SUPABASE_PUBLISHABLE_KEY` | Project Settings > API > publishable(anon) | 서버는 안 쓴다 |
| `INSTRUCTOR_TOKEN` | 직접 생성 | `python -c "import secrets;print(secrets.token_urlsafe(24))"` |

### 접속 문자열 형식

```
postgresql://postgres.<프로젝트ref>:<DB비밀번호>@aws-1-ap-northeast-2.pooler.supabase.com:5432/postgres
```

- **세션 풀러(5432)** 를 쓴다. 서버가 커넥션을 계속 들고 있고 `COPY` 로 배치 적재하기 때문이다.
- 호스트 접두사가 프로젝트마다 `aws-0` 또는 `aws-1` 로 다르다. **대시보드가 알려주는 값을 그대로 쓴다.**
  틀리면 `tenant/user postgres.<ref> not found` 가 뜬다.
- `db.<ref>.supabase.co` 직결은 IPv6 전용이라 대개 실패한다. 쓰지 말 것.

### 접속 확인

```bash
python -c "import asyncio,asyncpg,sys;sys.path.insert(0,'.');from server.app.config import get_settings;\
asyncio.run(asyncpg.connect(get_settings().database_url,statement_cache_size=0))" && echo 접속OK
```

## 4. 기동

```bash
python -m server.run
```

```
러너 기동 — 테넌트 39개, 배속 x1, 실제 tick 1.00s, flush 2.0s
Uvicorn running on http://0.0.0.0:8000
```

| 주소 | 용도 | 누가 |
|---|---|---|
| `http://<호스트>:8000/view` | 2D 공장 뷰 | 강사 시연 · 학생 |
| `http://<호스트>:8000/view?tenant=S07` | 특정 학생 공장 바로 열기 | 학생 개인 링크 |
| `http://<호스트>:8000/console` | 강사 콘솔 (토큰 필요) | 강사만 |
| `http://<호스트>:8000/docs` | API 문서 (OpenAPI) | 학생 |
| `http://<호스트>:8000/fallback` | 폴백 대시보드 | 비상시 |

### 절대 하지 말 것 — 워커 늘리기

시뮬레이션 상태가 **프로세스 메모리**에 있다.
`--workers 2` 이상으로 띄우면 학생마다 다른 공장을 보게 된다.
`server/run.py` 가 `workers=1` 로 고정해 뒀으니 그대로 쓴다.

### 강의장에서 학생이 붙게 하려면

`.env` 의 `HOST=0.0.0.0` 을 유지하고 강사 PC 의 사설 IP 를 안내한다.

```bash
# Windows
ipconfig | findstr IPv4
# 방화벽 인바운드 허용 (관리자 PowerShell, 1회)
New-NetFirewallRule -DisplayName "K-정밀 시뮬레이터" -Direction Inbound -LocalPort 8000 -Protocol TCP -Action Allow
```

학생에게는 `http://192.168.x.x:8000` 형태로 안내한다.

### 6-1. 가상 시계 — 배속 (라이브 시연의 핵심)

**드리프트를 강의 시간 안에 보여줄 때 기울기를 키우지 않는다.** 시계를 가속한다.

기울기를 키우면 두 가지가 동시에 깨진다.

- 1일차 논지 — *"한 시간에 0.5도는 눈으로 구분되지 않는다"*. 3분에 3도면 학생 눈에 그냥 보인다
- 1일차 학습 — *"드리프트는 이동평균이 적응해 미탐된다"*. 샘플당 상승폭이 커지면 z-score 가
  쉽게 잡아 2일차 시연이 1일차 과 모순된다

배속은 **1분 간격 가상 샘플을 그대로 둔 채 그 샘플을 더 빨리 내보낼 뿐**이다.
샘플당 상승폭이 W5 레거시 CSV 와 정확히 같으므로(0.00833℃/샘플) 이상감지 알고리즘
검증 결과가 그대로 유효하다.

| 배속 | 실제 tick | 공장 4시간 | 샘플당 상승폭 | 39개 적재 |
|---|---|---|---|---|
| ×1 | 1.00초 (1초치) | 4시간 | — | 312행/초 |
| **×60 (권장)** | **1.00초 (1분치)** | **4분** | 0.00833℃ | 312행/초 |
| ×80 | 0.75초 (1분치) | 3분 | 0.00833℃ | 416행/초 |
| ×120 | 0.50초 (1분치) | 2분 | 0.00833℃ | 624행/초 |

**×60 을 기본으로 쓴다.** 실제 tick 이 정확히 1초라 교안의 「1초 주기 변동」이 그대로
유지되고 적재량도 ×1 과 같다. ×120 은 적재량이 2배가 되므로 학생 모드(8개)에서만 쓴다.

**AMR 주행만은 배속과 무관하게 항상 실시간이다.** 가상 시간으로 움직이면 ×60 에서
공장을 가로지르는 데 0.2초가 걸려 눈에 안 보인다. 2일차 클라이맥스가
「화면에서 AMR 이 실제로 움직인다」이므로 이 하나는 예외로 뒀다.

#### 2일차 라이브 시연 순서 (교안 12~14장)

1. 콘솔에서 **×60** 을 누른다 — 2D 뷰 상단에 「공장 시각 · 배속 ×60」이 뜬다
2. 「온도 드리프트 — 새벽 3시 EQ-03」 프리셋을 EQ-03 에 주입
3. 화면의 공장 시각이 흐르는 것을 보여주며 **"실제로는 네 시간에 걸친 일입니다"**
4. 4분 뒤 62 → 64℃. **고정 임계값 80℃ 는 끝까지 넘지 않는다** — 여기가 1일차 서사의 회수 지점
5. 감지 에이전트가 포착하면 **×1 로 되돌린다**
6. 감속·로봇 파견을 실시간으로 시연 — AMR 이동이 그대로 보인다

> 2D 뷰 상단 시계 바는 배속이 1보다 크면 색이 바뀐다. 학생이 "지금은 가속 중"임을
> 화면으로 확인할 수 있어야 강사의 설명이 성립한다.

### 6-2. 이상 주입 3종 (교안 3절)

프리셋 버튼 한 번이면 된다. 대상은 개별 네임스페이스 또는 `*`(전체 일괄).
**파라미터는 서사·W5 기준값 하나뿐이다.** 라이브 시연은 파라미터가 아니라 배속으로 만든다.

| 프리셋 | 쓰는 자리 |
|---|---|
| **온도 드리프트 — 새벽 3시 EQ-03** (0.5℃/h · 4시간 · 62→64℃) | 2일차 라이브 시연 (배속 ×60~×80) · W5 정합성 확인 |
| 진동 스파이크 — 시연용 (알람 발생) | 화면에서 확실히 보임. **`ack_alarm` 시연은 이쪽** |
| 진동 스파이크 — 미세 (z-score 로만 탐지) | 1일차 1일차 이상감지 |
| 센서 결측 — 2시간 (W5 와 동일 길이) | 1일차 결측 처리 (배속 ×60 이면 실제 2분) |
| 센서 결측 — 짧게 (2분) | ×1 에서 화면 표시만 빠르게 확인 |

주입은 **끝나면 서서히 회복**한다(온도 0.2℃/분). 순간 복귀는 화면에서 오작동처럼 보이기 때문이다.
즉시 멈추려면 「진행 중인 주입」에서 중단하거나 「전체 주입 중단」을 누른다.

주입 파라미터의 시간 단위는 전부 **공장 시각(가상)** 이다. `duration_seconds: 7200` 은
가상 2시간이고, ×60 이면 실제 2분에 끝난다. 「지연 N초 뒤 시작」만 실제 초로 받아 환산한다.

> 알람 시연에 **드리프트를 쓰지 않는다.** 드리프트가 80℃ 를 넘게 하려면 기울기를 키워야
> 하는데 그러면 1일차·1일차 이 깨진다. 알람이 필요하면 진동 스파이크나 센서 결측을 쓴다.

### 그밖에

- **네임스페이스 초기화** — 이력·알람·명령·주입을 지우고 공장을 정상 상태로 되돌린다
- **보존정책 즉시 실행** — 오래된 이력 삭제
- **DB 사용량** — 무료 티어 500MB 감시

## 7. 보존정책 — 반드시 확인할 것

실측 기준(39 네임스페이스 · 1초 주기):

| 항목 | 실측값 |
|---|---|
| 적재 속도 | 초당 312행 (설비 234 + 로봇 78) |
| `sensor_readings` 행 크기 | 약 158 B (인덱스 포함) |
| `robot_readings` 행 크기 | 약 161 B (인덱스 포함) |
| **시간당 증가량** | **약 180 MB** |

무료 티어 DB 한도가 500MB 이므로 **`RETENTION_HOURS=1` 이 기본값**이다.
Pro(8GB)로 전환하면 2~4 로 올려도 된다.

- 러너가 `RETENTION_SWEEP_SECONDS`(기본 180초)마다 `prune_readings()` 를 호출한다
- `DELETE` 라 디스크가 즉시 OS 로 반환되지는 않지만 autovacuum 이 공간을 재사용하므로
  정상 상태에서 보존 창 크기 근처를 유지한다
- **배속을 올려도 적재 속도는 ×60 까지 그대로다**(실제 tick 1초 유지). ×120 에서만 2배가 된다
- 하루 4시간 수업이라 1시간 보존으로 충분하다. 학생의 장기 이력은
  **학생 자신의 Supabase 프로젝트**(1일차 에서 생성)에 쌓이고, 1일차 의 과거 7일치는
  W5 레거시 CSV 로 들어간다

## 9. 폴백 경로 (교안 3절 명시)

시뮬레이터가 미완이거나 강의장에서 우리 API 서버 포트가 막혔을 때.
**2D 뷰와 API 서버 없이 Supabase 만으로 성립한다.**

```bash
python tools/fallback/state_updater.py
# 부분만 돌리려면
python tools/fallback/state_updater.py --tenants S01,S02 --tick 2
```

학생은 `web/fallback/index.html` 을 브라우저로 열고
Supabase URL 과 publishable 키를 넣으면 표가 갱신된다.
파일을 직접 열어도(`file://`) 동작하므로 우리 서버가 아예 없어도 된다.

읽는 대상: `tenant_public`, `equipment_latest`, `robot_latest`, `alarm`.
이 키로는 읽기만 된다(004_grants.sql).

> 손실되는 것 — 2일차 클라이맥스인 AMR 이동 시연의 임팩트. 교안도 이 점을 명시했다.

| `tenant/user postgres.<ref> not found` | 풀러 호스트 접두사(`aws-0`/`aws-1`) 불일치 | 대시보드 값 그대로 복사 |
| `getaddrinfo failed` (db.\<ref\>.supabase.co) | 직결은 IPv6 전용 | 세션 풀러 주소로 교체 |
| 기동 시 "시뮬레이션 대상 테넌트가 없습니다" | 시드 미적용 | `python tools/migrate.py up` |
| 학생 대시보드에 CORS 오류 | — | 서버가 `*` 허용 중. 주소·포트 오타 확인 |
| 제어 API 가 403 | 정상. 2일차 전 잠김 | 콘솔에서 개방 |
| 제어 API 가 401 | `X-Access-Key` 없음/불일치 | 콘솔 표에서 해당 키 확인 |
| 값이 계속 `null` | 센서 결측 주입 중 | 콘솔 「진행 중인 주입」에서 중단 |
| 없는 알람이 계속 떠 있음 | (해결됨) 재기동 시 자동 정리 | 재기동 로그의 "알람 N건 정리" 확인 |
| 공장 시각이 실제 시각보다 한참 앞섬 | 정상. 배속 가동 중이거나 가동했던 흔적 | 재기동하면 실제 시각으로 되돌아온다 |
| 배속을 올렸는데 AMR 이 그대로 | 정상. AMR 주행은 항상 실시간이다 | 6-1 참조 |
| 재기동 후 주입이 사라짐 | 의도된 동작 | 공장이 정상 상태로 초기화되므로 다시 주입한다 |
| 이력 조회(`readings`)가 예상보다 많이 나옴 | `minutes` 는 실제 적재 시각 기준 | ×60 이면 N분이 가상 N시간분이다 |
| DB 사용량이 계속 증가 | 보존 주기가 김 | `RETENTION_HOURS` 낮추고 콘솔에서 즉시 실행 |
| 무료 프로젝트가 멈춰 있음 | 1주 미사용 자동 일시정지 | 대시보드에서 재개. **리허설과 본강의 사이 간격 주의** |

## 13. 클라우드 VM 배포 (GCP) — 강의장 네트워크 보험

> ✅ **2026-08-07 실제 배포·검증 완료.** 아래는 실제로 돌려 본 절차다.
> 현재 인스턴스: `knu-factory` (asia-northeast3-a, e2-small) · 고정 IP **34.64.94.16**
> 학생 화면 `http://34.64.94.16:8000/view?tenant=S01` · 강사 콘솔 `http://34.64.94.16:8000/console`
> **평소에는 정지해 둔다**(과금 절약): `gcloud compute instances stop knu-factory --zone=asia-northeast3-a`
>
> **한 번에 하기** — `bash tools/cloud_deploy.sh` (아래 13-1~13-4 를 자동으로 수행,
> 재실행 안전). `--status` 상태 확인 · `--destroy` 특강 후 정리.

**언제 쓰나** — 강의장 와이파이의 AP 격리(기기 간 통신 차단)가 안 꺼지거나, 학생 단말에서
강사 PC 접근이 막힐 때. 클라우드에 올리면 학생은 **아무 인터넷(LTE 포함)으로** 접속하므로
강의장 네트워크 조건 3개가 전부 사라진다.

> **GKE(쿠버네티스)가 아니라 Compute Engine VM 1대로 간다.**
> 이 서버는 프로세스 하나라 k8s 이점이 없고, GKE는 클러스터 관리비(월 ~$73)와
> Docker 빌드 단계만 늘어난다. e2-small VM은 월 $15~20 — $300 크레딧의 5% 수준.

### 13-1. VM 만들기 (GCP 콘솔 또는 gcloud, 1회)

```bash
# 서울 리전. Supabase(ap-northeast-2)와 가까워 지연 최소
gcloud compute instances create knu-factory \
  --zone=asia-northeast3-a --machine-type=e2-small \
  --image-family=ubuntu-2404-lts-amd64 --image-project=ubuntu-os-cloud

# 8000 포트 개방 (학생 접속용)
gcloud compute firewall-rules create allow-factory-8000 \
  --allow=tcp:8000 --direction=INGRESS

# 고정 IP (재부팅해도 주소 유지 → 쪽지 미리 인쇄 가능)
gcloud compute addresses create knu-factory-ip --region=asia-northeast3
```
콘솔에서 만들 때의 선택지: 리전 `asia-northeast3(서울)` · 머신 `e2-small` · 부팅 디스크 Ubuntu 24.04 LTS · 방화벽에서 8000 허용.

### 13-2. 서버 올리기 (VM 안에서, 1회)

```bash
sudo apt update && sudo apt install -y python3.12 python3.12-venv git
git clone https://github.com/ahnchiyoon87/knu-agentic-factory.git
cd knu-agentic-factory/산출물/공통/시뮬레이터
python3.12 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
# .env 는 로컬 것을 복사해 만든다 (SUPABASE_DB_URL, INSTRUCTOR_TOKEN 등 — §2 와 동일)
nano .env
```

### 13-3. 상시 기동 등록 (끊겨도 자동 재시작)

```bash
sudo tee /etc/systemd/system/factory.service > /dev/null <<'UNIT'
[Unit]
Description=K-Precision Factory Simulator
After=network-online.target

[Service]
WorkingDirectory=/home/%i/knu-agentic-factory/산출물/공통/시뮬레이터
ExecStart=/home/%i/knu-agentic-factory/산출물/공통/시뮬레이터/.venv/bin/python -m uvicorn server.app.main:app --host 0.0.0.0 --port 8000 --workers 1
Restart=always
Environment=PYTHONUTF8=1

[Install]
WantedBy=multi-user.target
UNIT
sudo systemctl enable --now factory
curl http://127.0.0.1:8000/api/v1/health   # ok 나오면 성공
```
(`%i` 자리는 실제 사용자명으로 바꾼다. 경로에 한글이 있으므로 셸에서 탭 자동완성으로 확인할 것.)

### 13-4. 학생 주소 전환 — 이것뿐이다

코드는 한 줄도 안 바뀐다. **주소만 바뀐다.**

```bash
# 강사 PC에서 — 쪽지를 클라우드 주소로 다시 뽑는다
python tools/키배포표.py --base http://<VM고정IP>:8000
```
강사 콘솔도 브라우저로 `http://<VM고정IP>:8000/console` 접속(토큰 동일).

### 13-5. 전환 판단 절차 (당일)

> ⚠️ **서버는 반드시 한 곳에서만 돌린다.** DB(Supabase)가 공유라서, 로컬과 클라우드
> 서버를 동시에 켜면 두 시뮬레이터가 같은 공장 데이터에 이중으로 쓰기 시작해 값이 꼬인다.
> 전환 = "한쪽 끄고 → 다른 쪽 켜기". 평소 VM 은 `sudo systemctl stop factory` 로 재워 둔다.

1. 기본은 로컬(시작.bat). 셋업 랩에서 학생 2~3명이 접속 확인 → 되면 그대로 진행
2. 안 되면(AP 격리 등): **로컬 서버 창을 닫고** → VM 에서 `sudo systemctl start factory`
   → **키배포표를 클라우드 주소로 재인쇄** → 배부
3. 강의장 인터넷 자체가 죽으면: 로컬도 클라우드도 불가(DB 가 클라우드) — 핫스팟 전환이 최후 수단

### 13-6. 겪은 함정 (실배포 기록)

| 증상 | 원인 | 해결 |
|---|---|---|
| `pscp: unable to open .../산출물/...: no such file` | Windows 의 pscp 는 **경로에 한글이 있으면 못 연다** | 양쪽 다 ASCII 경로로 보내고(`/home/<user>/env_upload`) 원격에서 `mv` — 스크립트에 반영됨 |
| `Compute Engine API has not been used` | 새 프로젝트는 API 가 꺼져 있음 | `gcloud services enable compute.googleapis.com` (스크립트 0단계) |
| systemd 가 root 로 실행 | `User=` 누락 시 홈 경로·venv 를 못 찾음 | 유닛에 `User=<계정>` 명시 — 스크립트에 반영됨 |
| 청구서에 모르는 VM 요금 | **다른 프로젝트**의 잔여 인스턴스 | `gcloud compute instances list --project=<각 프로젝트>` 로 전수 확인 후 정지/삭제 |
