# Day 1 프롬프트 시드 — 초안 v1

Day 1 Step 1(작은 성공, 40분)에서 학생이 **AI에게 맨 처음 붙여넣는 지시문**입니다.
기술 사양은 실측 검증된 값이고, **떠먹이는 수위는 강의자료 담당이 조절**하시면 됩니다.

- 학생이 바꾸는 곳은 **두 군데뿐**: `<서버주소>` 와 `S07`(자기 번호). 쪽지에 둘 다 있습니다.
- 아래 A안이 기본이고, 시간·수준에 따라 B/C안으로 갈아 끼웁니다.

---

## A안 (권장) — 목표는 주되, 만드는 방법은 AI에게

```
너는 웹 프론트엔드 개발자야. 아래 조건으로 "실시간 공장 관제 대시보드"를 만들어 줘.

[데이터 출처]
- 주소: http://<서버주소>/api/v1/S07/state
- 이 주소를 GET 으로 부르면 내 공장의 현재 상태가 JSON 으로 온다.
- 응답 안에 equipment(가공기계 6대)와 robots(운반로봇 2대) 배열이 있다.
  · equipment 각 항목: equipment_id, temperature(℃), vibration, rpm, run_state
  · robots 각 항목: robot_id, pos_x, pos_y, battery, status
- 실제 응답을 먼저 한 번 불러서 구조를 확인한 뒤 화면을 만들어 줘.

[요구사항]
1. 기계 6대를 카드 형태로 보여준다 — 기계 이름, 온도, 진동, 회전수, 가동 상태.
2. 로봇 2대의 위치와 배터리를 보여준다.
3. 화면은 2초마다 자동으로 갱신된다. (중요: 2초보다 짧게 하지 말 것.
   여러 명이 같은 서버를 쓰기 때문에 서버가 버티지 못한다.)
4. 마지막 갱신 시각을 화면 어딘가에 표시한다.
5. 데이터를 못 받아왔을 때는 화면이 깨지지 말고 "연결 대기 중"이라고만 표시한다.

[결과물]
- HTML 파일 하나로 만들어 줘. 브라우저에서 바로 열 수 있어야 한다.
- 외부 라이브러리 없이 순수 HTML/CSS/JavaScript 로.
- 파일 이름은 dashboard.html, 지금 열려 있는 저장소 폴더 안에 저장해 줘.

만들고 나서, 브라우저에서 어떻게 열어 보는지 한 줄로 알려 줘.
```

## B안 (덜 떠먹이기) — 빠른 학생·도전용

A안에서 **[요구사항] 3~5번을 지웁니다.** 폴링 주기 규칙만 남기고 나머지는 학생이
스스로 요구하게 두는 버전입니다. 진행이 빠른 조에 이 버전을 주면 난이도를 맞출 수 있습니다.

## C안 (더 떠먹이기) — 막힌 학생 구제용

A안 뒤에 아래 문단을 덧붙입니다.

```
[막힐 때 대비]
- 데이터가 안 보이면, 먼저 fetch 결과를 console.log 로 찍어서 구조를 확인해 줘.
- 브라우저 보안(CORS) 문제가 나면 그 에러 메시지를 나에게 그대로 보여줘.
- 완성 전에 절대 가짜 샘플 데이터로 채우지 마. 반드시 위 주소에서 받아온 값만 써.
```

## 이어지는 자유 변형 (Step 1 후반, 학생이 직접 씀)

시드로 성공한 뒤 "한 가지를 마음대로 바꾸는" 단계의 예시 문구입니다. 그대로 주지 말고
**칠판에 예시로만** 띄우는 걸 권합니다 — 창의성 투표 대상이기 때문입니다.

- "온도가 70도를 넘는 기계는 카드를 빨간색으로 강조해 줘"
- "전체를 어두운 테마로 바꿔 줘"
- "기계 카드를 클릭하면 그 기계만 크게 보이게 해 줘"
- "가동 중인 기계 수를 맨 위에 큰 숫자로 표시해 줘"

## 사양 근거 (실측)

| 항목 | 값 | 확인 |
|---|---|---|
| `/state` 응답 | equipment 6 · robots 2 · alarms 배열 | 실측 확인 |
| equipment 필드 | equipment_id·temperature·vibration·rpm·run_state | 실측 확인 |
| robots 필드 | robot_id·pos_x·pos_y·battery·status·eta_seconds | 실측 확인 |
| 폴링 주기 | **2초 이상** (교안 강사 노트: 폴링 주기를 가이드에 고정) | 규정 |
| 온도 기준값 | 기계마다 다름 (56℃대~74℃대 정상) | 실측 확인 — 자유 변형 예시의 임계값을 70도로 잡은 이유 |

## 확정 필요 (강의자료 담당)

- 떠먹이기 수위: A/B/C 중 기본안
- `<서버주소>` 표기 방식 — 쪽지에 이미 전체 주소가 있으므로 "쪽지의 주소" 라고만 써도 됨
- 자유 변형 예시를 배포물로 줄지, 구두로만 할지
