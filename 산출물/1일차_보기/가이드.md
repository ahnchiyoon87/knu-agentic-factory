### 1-4. 파이썬 브릿지 — C를 아는 사람의 1페이지 (5분)

오늘 AI가 만들어 줄 코드는 파이썬입니다. 여러분은 C를 배웠으니, 아래 대응표 한 장이면
읽을 수 있습니다. **외울 필요 없습니다** — 오늘 코드는 AI가 쓰고, 여러분은 읽고 판단만 합니다.

| C에서 | 파이썬에서 | 한 줄 감상 |
|---|---|---|
| `#include <stdio.h>` | `import requests` | 도구 가져오기. 따옴표·세미콜론 없음 |
| `printf("%d", x);` | `print(x)` | 형식 지정자 없이 그냥 출력 |
| `int x = 5;` | `x = 5` | 타입 선언 없음. 변수는 그냥 씀 |
| `for (i=0; i<6; i++)` | `for m in machines:` | 인덱스 대신 "목록에서 하나씩 꺼내며" |
| `struct` + 포인터 | `dict` (딕셔너리) | `m["temperature"]` 처럼 이름으로 접근. 포인터 없음 — 전부 참조 |
| 함수 `int f(int a){...}` | `def f(a): ...` | 중괄호 대신 **들여쓰기**가 블록 |
| 컴파일 → 실행 | 그냥 `python 파일명.py` | 컴파일 단계 없음 |

메시지는 하나입니다: **여러분은 이미 더 어려운 걸 배웠습니다.** 포인터를 이해한 사람에게
파이썬은 내리막입니다.

# §2. Lab 1-1 — 바이브코딩으로 관제 대시보드 만들기 (110분)

### 왜 하는가 (교안 원문)

> 피지컬 AI의 첫 단계는 물리 세계를 '보는' 것이다. AI에게 말로 시키는 개발이 어디까지
> 되는지, 어디서부터 안 되는지도 함께 확인한다 — **안 되는 지점이 내일 배울 내용이다.**

**바이브코딩**이란: 코드를 직접 치는 대신, AI에게 자연어로 "이런 걸 만들어 줘"라고 말해서
프로그램을 만들어 내는 방식입니다. 오늘 여러분은 키보드로 코드를 안 칩니다 —
**요구를 말하고, 결과를 보고, 다시 말합니다.**

### 2-0. 재료 소개 — 공장 데이터는 어디서 오나 (5분, 읽기만)

여러분의 공장은 **API**로 데이터를 내어줍니다. API란 프로그램이 다른 프로그램에게
데이터를 요청하는 창구입니다 — 주소를 부르면 최신 데이터가 문자(JSON)로 돌아옵니다.

AI가 대시보드를 만들 때 쓸 창구들입니다 (전부 `공장 서버 주소/api/v1/` 뒤에 붙습니다):

| 창구 | 무엇이 오나 | 오늘 용도 |
|---|---|---|
| `/{내번호}/state` | **공장 전체 스냅샷 한 방** — 기계 6대 + 로봇 2대 + 알람까지 | ★ 오늘의 주력. 이것만 불러도 대시보드가 됨 |
| `/{내번호}/equipment` | CNC 6대 현재 상태만 | 부분 갱신용 |
| `/{내번호}/robots` | AMR 2대 위치·상태만 | 로봇 경로 표시(카드 3)용 |
| `/{내번호}/alarms` | 알람 목록 | 알람 표시(카드 1)용 |
| `/{내번호}/readings` | 센서 **이력** (지나간 기록) | 이력 그래프(카드 2)용 |

기계 한 대의 데이터에는 이런 값들이 들어 있습니다:
`equipment_id`(EQ-01~06) · `temperature`(온도 ℃) · `vibration`(진동) · `rpm`(회전수) · `run_state`(가동 상태)

> ⚠️ **딱 하나의 규칙 — 폴링은 2초에 1번까지.**
> 폴링이란 프로그램이 "지금은? 지금은?" 하고 주기적으로 데이터를 다시 요청하는 것입니다.
> 39명이 같은 서버를 쓰므로, **2초(2000ms)보다 잦게 요청하도록 만들지 마세요.**
> AI에게 시킬 때도 이 숫자를 꼭 말해주세요. 아래 시작 프롬프트에 이미 들어 있습니다.

| 아무 데이터도 안 나옴 | AI에게 쪽지의 서버 주소와 내 번호를 다시 알려주며 "이 주소로 고쳐 줘" |
| AI가 가짜 데이터를 넣음 | "가짜 데이터 말고 아까 준 실제 API 주소에서 받아 와" 라고 명시 |
| 에러 화면 | 에러 문구를 **그대로 복사해서 AI에게 붙여넣기** — "이 에러 고쳐 줘" 가 오늘의 만능 열쇠 |

**④ 성공했으면 — 내 마음대로 한 가지 바꾼다 (남는 시간 전부).**
자유입니다. 예를 들면: "온도가 65℃ 넘는 기계는 빨간색으로" · "다크 모드로" ·
"기계를 클릭하면 상세 정보가 뜨게". **바꾼 것이 랩업 투표 대상입니다.**

### 2-2. Step 2 — 일부러 겪는 불편 (40분)

이제 강사가 **요구사항 카드 5장**을 순서대로 하나씩 나눠줍니다. 실제 발주처가 요구를
추가하는 상황의 재현입니다. 한 장 받을 때마다 AI에게 시켜서 대시보드에 추가하세요.

| 순서 | 카드 | 요구 내용 |
|---|---|---|
| 1 | 온도 임계 알람 | 온도가 기준을 넘으면 화면에 경고 표시 |
| 2 | 설비별 이력 그래프 | 기계를 고르면 지나간 온도 추이 그래프 (`/readings` 창구 사용) |
| 3 | AMR 경로 표시 | 로봇 2대가 어디서 어디로 가는지 표시 |
| 4 | 알람 담당자 배정 | 알람마다 담당자를 지정·표시 |
| 5 | 야간모드/권한 분리 | 야간 화면 + 보는 사람에 따라 다른 화면 |

> **미리 말해두는 것:** 3~4장째쯤에서, **앞에서 잘 되던 기능이 깨지는 일**이 거의 모두에게
> 일어납니다. 그건 여러분이 못해서가 아니라 **오늘 수업이 노리고 설계한 경험**입니다.
> 깨지면 당황하지 말고 딱 한 가지만 하세요 — **몇 장째 카드에서, 뭐가 깨졌는지 메모.**
> 그 메모가 내일 수업의 출발점입니다.

깨진 걸 고치려고 남은 시간을 다 써도 됩니다. 못 고쳐도 전혀 문제없습니다 —
**"왜 고칠수록 더 깨지지?"라는 의문을 갖는 것**까지가 오늘의 과제입니다.

### 2-3. Step 3 — 내일 볼 것 미리 보기 (20분, 관람)

강사가 여러분과 **똑같은 요구사항 5개**를, 이번엔 **스펙 문서를 기반으로 한 번에** 지시하는
걸 시연합니다. 이 경우엔 안 무너집니다.

**관람 포인트 두 가지만 챙기세요:**
1. 강사의 지시문과 내 프롬프트는 뭐가 달랐나
2. 같은 AI인데 왜 결과가 다른가

강사가 "차이가 뭘까요?"라고 물을 겁니다. **답은 오늘 안 나옵니다** — 내일 4시간이 그 답입니다.

### 2-4. Step 4 — 자산으로 남기기 (10분)

오늘 만든 것과 오늘 쓴 프롬프트를 저장소에 저장합니다. **커밋**이란 지금 상태를 저장소에
도장 찍어 보관하는 것입니다.

1. Claude 채팅 기록에서 오늘 쓴 주요 프롬프트를 복사해 `prompts_day1.md` 파일로 저장
   (VS Code에서 새 파일 → 붙여넣기 → 저장소 폴더 안에 저장).
2. 터미널에 순서대로:

```
git add .
git commit -m "Day1: 관제 대시보드"
git push
```

3. **성공 판정** — 브라우저로 GitHub의 내 저장소 페이지를 열었을 때 방금 파일들이 보이면 성공.

**안 되면:** `git push` 에서 인증 창이 뜨면 GitHub 로그인. 그 외 에러는 문구 복사 → AI에게 "이 git 에러 해결해 줘".

# §3. 랩업 (20분)

- 지원자 2~3명이 자기 대시보드를 화면에 공유합니다 — Step 1-④에서 "내 마음대로 바꾼 것" 중심으로.
- **누가 제일 창의적으로 바꿨는지 그 자리에서 투표**합니다.
- 오늘 가져가는 것 세 줄:
  1. AI에게 말로 시켜서, 실제로 돌아가는 공장의 관제 화면을 만들었다
  2. 요구가 쌓이면 말로만 시키는 개발은 **무너진다** — 몇 장째에서 무너졌는지 내 메모에 있다
  3. 스펙 문서가 있으면 안 무너지더라 — **왜인지는 내일**

> 내일 예고: "오늘 공장을 봤습니다. 내일은 공장을 **'설계'** 합니다."
